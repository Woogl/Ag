# 시나리오 테스트

AI가 동작 테스트를 공유 에디터의 PIE 대신 테스트 창(별도 게임 프로세스)에서 하는 도구입니다. 왜 이렇게 하는지는 [개발 도구와 검증](<../../Docs/Program/개발 도구와 검증.md>)의 '동작 테스트 실행'을 따릅니다. 테스트할 일을 시나리오 파일에 적어 실행하면, 화면 오른쪽에 창이 떠서 단계마다 무엇을 확인하는지 보여 주고, 끝나면 판정을 출력하고 창을 닫습니다.

## 준비

- 프로젝트가 빌드되어 있어야 합니다. 창은 에디터와 같은 실행 파일로 뜨고, 디스크에 저장된 에셋과 `DesignData` JSON을 읽습니다. 에디터에서 저장하지 않은 수정은 보이지 않습니다.
- 라이브 코딩으로 고친 코드는 창에 들어가지 않습니다. 라이브 코딩은 고친 코드를 켜져 있는 에디터에만 넣기 때문입니다. 코드를 고쳤으면 Build.bat으로 빌드한 뒤 실행합니다.
- 에디터는 켜 두어도 되고 꺼도 됩니다.
- 창은 보스 스테이지를 소리 없이 엽니다. 타이틀 화면, 메뉴 조작, 소리는 이 도구로 확인하지 못합니다.

## 쓰는 법

실행 전 물음과 끝난 뒤 정리는 [AI 워크플로우](<../../Docs/AI 워크플로우.md>)의 '테스트 작업'을 따릅니다.

1. 시나리오 파일을 씁니다. 형식은 아래 '시나리오'를 따릅니다. 시나리오는 테스트마다 쓰는 임시 파일이라 저장소에 올리지 않습니다.
2. 실행합니다. 맵을 열고 준비하는 데 20초쯤 걸립니다.
   ```
   python -I Scripts/ScenarioTest/run.py <시나리오.py>
   ```
   - 테스트 한 번에 1분 안팎이 걸립니다. AI의 명령 실행 도구는 제한 시간을 넉넉히(5분) 잡습니다.
   - 빌드 도구(UnrealBuildTool)가 돌고 있으면 끝날 때까지 기다렸다가 창을 띄웁니다.
   - 판정을 띄운 채 10초 뒤에 창을 닫습니다. `--hold <초>`로 바꿉니다. run.py가 도중에 끊겨도 창은 함께 닫힙니다.
   - `--keep`을 붙이면 창을 닫지 않습니다. 떠 있는 창은 프로젝트 DLL을 잡고 있어 Build.bat이 실패하므로, 다 보면 닫습니다.
   - 종료 코드는 통과 0, 테스트 실패 1, 실행 실패 2입니다. 테스트 실패는 실행·판정을 마쳤지만 통과 조건을 충족하지 못한 경우이고, 실행 실패는 준비·단계·판정 중 오류 등으로 검증을 완료하지 못한 경우입니다.
   - 끝에 창 로그의 게임 오류(`LogAg: Error`)를 함께 출력합니다. 데이터 파일을 읽지 못한 경우처럼 오류가 있으면 판정을 믿지 않고 원인부터 봅니다.
3. 여러 테스트를 동시에 실행해도 됩니다. 창 자리는 화면 오른쪽 2×2의 4개이고, 비어 있는 자리를 차례로 씁니다.

## 시나리오

```python
TITLE = "기본 공격 콤보 (보스 AI 정지)"   # 창 제목과 화면 첫 줄
AI_ON = False                        # True면 준비가 끝난 뒤 보스 AI를 다시 켭니다.

def _start(c):
    c.face_boss(150)
    c.boss_hp0 = c.attr("b", "HP")

STEPS = [                            # (시작 후 초, 화면에 띄울 항목, 할 일)
    (1.5, "보스 앞 1.5m에 서서 보스를 봄", _start),
    (2.5, "기본 공격 키 연타 (4초)", lambda c: c.mash("Input.Attack")),
    (6.5, "연타 멈춤", lambda c: c.mash()),
    (8.5, "판정", None),             # 마지막 단계가 지나면 evaluate를 부릅니다.
]

def evaluate(c):                     # (전체 통과 여부, 판정 항목 목록)
    chain = [m for m in c.seq("p", 2.5, 8.5) if m.startswith("AM_Player_BasicAttack:")]
    dmg = c.boss_hp0 - c.attr("b", "HP")
    items = [(len(chain) >= 5, "1~5타가 이어짐 (%d타)" % len(chain)),
             (dmg > 0, "보스가 대미지를 받음 (%.0f)" % dmg)]
    return all(ok for ok, _ in items), items
```

- 창 화면에는 제목 아래에 준비와 `STEPS`의 항목이 한 줄씩 모두 뜹니다. 진행 중인 항목은 노란색 `[진행]`, 끝난 항목은 `[완료]`, 남은 항목은 회색 `[대기]`입니다. 끝나면 그 아래에 판정과 판정 항목이 한 줄씩 붙습니다.
- 판정 항목은 `(통과 여부, 글자)`로 주면 항목마다 `[통과]`·`[실패]`가 붙고, 글자만 주면 전체 판정의 색을 따릅니다.
- 창이 800×450이라 한 줄은 40자 안쪽으로 씁니다.
- 시간은 준비가 끝난 순간부터 셉니다. 준비는 보스 AI를 멈추고, 보스와 플레이어의 몽타주가 끝나고 프레임이 안정되기를 기다립니다.
- 단계 함수와 `evaluate`는 아래 도우미 `c`를 받습니다. `"p"`는 플레이어, `"b"`는 보스입니다.

| 도우미 | 하는 일 |
| - | - |
| `press(tag)`, `mash(tag)`, `hold(tag)` | 행동 키를 한 번 누름, 매 프레임 누름(연타), 누르고 있음. 태그는 `Input.Attack`처럼 씁니다. 인자 없이 부르면 멈춥니다. |
| `move(x, y)` | 이동 입력(x 오른쪽, y 앞). 회피 방향은 회피 키보다 한 프레임 이상 먼저 넣습니다. |
| `face_boss(cm)` | 플레이어를 보스에서 그 거리에 두고 플레이어와 카메라가 보스를 보게 합니다. |
| `attr(who, name)`, `set_attr(who, name, value)` | 어트리뷰트(`HP`, `MP`, `UP`, `PP` 등)를 읽고 씁니다. 이 창의 메모리만 바꿉니다. 값만 바꾸고 변경 이벤트는 일으키지 않아서, HP를 0으로 해도 사망하지 않고 HUD도 바뀌지 않습니다. |
| `console(command)` | 콘솔 명령을 실행합니다. 사망은 [테스트용 콘솔 명령](<../../Docs/Program/개발 도구와 검증.md>)(`AgKillBoss`, `AgKillPlayer`)으로 일으킵니다. |
| `has(who, tag)` | 게임플레이 태그가 붙어 있는지 |
| `montage(who)`, `seq(who, 시작, 끝)` | 지금 몽타주, 그 구간에 재생된 몽타주 순서. 기본 섹션(`Default`)이 아닌 섹션은 `AM_Player_BasicAttack:Attack3`처럼 섹션을 붙입니다. |
| `pos()`, `forward()` | 플레이어 위치와 앞 방향 |
| `banner(text, key)` | 화면에 글자 한 줄을 더합니다. 같은 `key`로 다시 부르면 그 줄이 바뀝니다. |
| `rows`, `notes` | 프레임마다 기록한 값(몽타주와 섹션, HP·SP·MP·UP, 보스 HP·PP, 가드·사망), 결과에 남길 메모 |

- 더 필요한 것은 단계 함수에서 `unreal` 모듈로 직접 합니다. 액터 속성을 쓸 때는 `set_editor_property(이름, 값, unreal.PropertyAccessChangeNotifyMode.NEVER)`로 씁니다. 알림과 함께 쓰면 엔진이 컴포넌트를 다시 등록하면서 캐릭터의 어빌리티가 모두 사라집니다.
- 개발용 입력 속성 같은 에디터 전용 속성은 C++ 이름(`DevMashInput`)으로 씁니다.

## 참고

- 결과는 `Saved/ScenarioTest/slot<자리>_<시각>.json`(판정, 몽타주 순서, 프레임별 기록), 창의 로그는 `Saved/ScenarioTest/slot<자리>.log`에 남습니다.
- 창은 Windows 관리 기능(WMI)으로 띄웁니다. 그래야 사용자가 쓰고 있는 창의 포커스를 가져가지 않습니다.
- 창은 사람의 입력(마우스, 키보드, 패드)을 받지 않습니다. 시나리오가 시작되면 창을 Windows에서 비활성으로 만들고 게임의 플레이어 입력도 끕니다. 그래서 창을 눌러도 반응하지 않고, 창의 닫기 단추도 듣지 않습니다. `--keep`으로 남긴 창은 실행할 때 출력한 PID로 작업 관리자나 `taskkill /PID <PID> /F`로 닫습니다.
