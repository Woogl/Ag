# 기획서 모션 그림

기획서의 모션 그림(`Docs/Design/Attachments`의 `플레이어 모션 *.gif`, `보스 모션 *.gif`)을 만드는 도구입니다. 그림마다 `sheets/<그림 이름>.json`에 어느 모션 구간을 이어 재생하고 어느 순간에 무엇을 표시할지 적어 두면, 스크립트가 에디터에서 캡처해 움직이는 그림(GIF)으로 합성합니다. 모션의 주요 프레임을 늘어놓은 칸 그림(jpg)도 만들 수 있습니다.

## 준비

- 에디터에서 프로젝트를 열어 둡니다. 스크립트는 에디터의 unreal-mcp 서버로 캡처하고, 무기 위치는 에디터의 파이썬 원격 실행으로 잽니다(둘 다 프로젝트 설정에서 켜져 있습니다).
- 캡처하는 동안 레벨 멀리에 임시 마네킹을 놓았다가 끝나면 지웁니다. `LV_BossStage`처럼 액터를 파일로 따로 저장하는 레벨에서는 레벨이 수정되지 않습니다.
- Python 3와 Pillow(`pip install pillow`)가 필요합니다. 글꼴은 맑은 고딕을 씁니다.

## 쓰는 법

1. `sheets/`에서 그림 파일을 고치거나 새로 만듭니다. 형식은 아래 '그림 파일'을 따릅니다.
2. 처음 쓰거나 새 모션을 넣었으면 모션 데이터를 뽑습니다. 1분 정도 걸리고, 에디터를 켠 채로 해도 됩니다.
   ```
   python Scripts/MotionImages/motion_images.py probe
   ```
3. 그림을 만듭니다. 결과는 `Docs/Design/Attachments`에 움직이는 그림(`animation`)이 있으면 `<그림 이름>.gif`로, 칸 그림(`rows`)이 있으면 `<그림 이름>.jpg`로 저장됩니다. 저장 전에 확인하려면 `--out <폴더>`를 붙입니다.
   ```
   python Scripts/MotionImages/motion_images.py make "플레이어 모션 평타"
   ```
   - 이름을 빼면 모든 그림을 만듭니다.
   - 그림마다 캡처가 끝나는 대로 합성하므로, 여러 그림을 만들 때 앞 그림부터 결과가 나옵니다. 합성은 다음 그림을 캡처하는 동안 함께 진행합니다. 자세와 카메라가 같은 프레임(처음·끝 멈춤, 자세 유지)은 한 번만 찍어 복사합니다. 한 장 찍는 데 0.35초쯤 걸립니다.
   - 캡처하는 동안 에디터를 캡처 모드로 둡니다. 창이 뒤에 있어도 느려지지 않게 'Use Less CPU when in Background'를 끄고, 시간에 따라 움직이는 구름(`VolumetricCloud`)을 숨겨 찍을 때마다 하늘과 빛이 같게 합니다. 둘 다 메모리에서만 바꾸고(구름은 아웃라이너의 눈 아이콘과 같은 임시 숨김) 끝나면 원래대로 되돌립니다. 그동안 에디터가 CPU를 더 씁니다.
   - 캡처는 에디터 하나가 한 장씩 차례로 처리하므로, 요청을 동시에 보내도 빨라지지 않습니다.
   - 라벨이나 판정 문구만 바꿨으면 아래 순서로 실행해 기존 캡처를 다시 합성합니다. 모션 구간이나 재생 속도를 바꿨으면 `make`로 다시 캡처합니다.
     ```
     python Scripts/MotionImages/motion_images.py plan
     python Scripts/MotionImages/motion_images.py compose
     ```

## 그림 파일

```json
{
  "image": "플레이어 모션 스킬",
  "character": "player",
  "animation": {
    "segments": [{"clip": "Samurai/Attack_Sprint", "from": 0.0, "to": 0.9833}],
    "marks": [{"clip": "Samurai/Attack_Sprint", "t": 0.3667, "label": "내려베기"}],
    "spans": [{"from": {"clip": "Samurai/Attack_Sprint", "t": 0.38}, "to": {"clip": "Samurai/Attack_Sprint", "t": 0.9833}, "label": "후딜", "color": "cyan"}]
  }
}
```

| 항목 | 뜻 |
| - | - |
| `image` | 그림 파일 이름(확장자 제외) |
| `character` | `player`(Quinn과 카타나) 또는 `boss`(Manny와 할버드) |
| `animation` | 움직이는 그림. 없으면 gif를 만들지 않습니다. 아래 '움직이는 그림'을 따릅니다. |
| `rows` | 칸 그림의 줄. 없으면 jpg를 만들지 않습니다. 아래 '칸 그림'을 따릅니다. |

- 그림에는 조정할 수 있는 수치를 쓰지 않습니다. 움직이는 그림은 왼쪽 아래에 지금 재생 중인 모션의 에셋 이름을 표시합니다. 칸 그림에는 애니메이션 에셋 이름을 쓰지 않고 기획서 본문의 '모션:' 줄에 적습니다.

### 움직이는 그림

몽타주처럼 모션 구간을 이어 `play_rate` 속도로 재생한 GIF입니다. 초당 20프레임으로 캡처하고, 카메라는 캐릭터를 따라갑니다. 골반을 가운데 두고 모든 그림을 같은 틀로 잘라, 캐릭터가 같은 크기로 보입니다. 크게 휘두를 때는 무기 끝이 잠깐 잘릴 수 있습니다. 파일을 줄이려고 하늘색에 가까운 픽셀을 한 색으로 칠하며, 하늘을 비추는 칼날처럼 하늘색과 눈에 띄게 다른 픽셀은 그대로 둡니다.

```json
"animation": {
  "play_rate": 0.8,
  "segments": [
    {"clip": "Halberd/Attack_Combo1", "from": 0.0, "to": 0.136, "rate": 0.3523},
    {"clip": "Halberd/Attack_Combo1", "from": 0.136, "to": 0.27},
    {"clip": "Halberd/Attack_Combo2", "from": 0.0, "hold": 0.35}
  ],
  "marks": [
    {"clip": "Halberd/Attack_Combo1", "t": 0.2333, "label": "1타 찌르기", "lead": 0.37, "lead_label": "패리 예고"}
  ],
  "spans": [
    {"from": {"clip": "Halberd/Attack_Combo1", "t": 0.0}, "to": {"clip": "Halberd/Attack_Combo1", "t": 0.136}, "label": "무적", "color": "cyan"}
  ]
}
```

| 항목 | 뜻 |
| - | - |
| `play_rate` | 몽타주 전체의 재생 속도(기본 1). 보스 공격 패턴은 보스 사양 '모션 재생 속도', 처형은 플레이어 사양 '처형'을 따릅니다. |
| `segments` | 차례로 이어 재생할 구간. 모션 `clip`의 `from`초부터 `to`초까지이고, 몽타주에서 느리게 재생하는 구간은 `rate`를 적습니다(기본 1). `to` 대신 `hold`를 적으면 `from`의 자세로 그 시간(초)만큼 멈춥니다(돌진 중 자세 유지처럼 코드가 멈춰 두는 구간). |
| `marks` | 타격 순간. 앞뒤 0.075초 동안 `label`과 테두리를 표시하고, 그 전 `lead`초 동안은 `lead_label`(예고 이름)을 표시합니다. 예고를 몽타주의 예고 노티파이에 맞추려면 `lead`를 '타격 순간 − 예고 시작'(실제 시간)으로 적습니다. 가드 불가면 `"red": true`이고, 색만 바꾸려면 `color`입니다. 같은 모션이 두 번 나오면 구간 순서대로 찾습니다. |
| `spans` | 정해진 구간 동안 `label`을 표시합니다(가드 불가 예고 구간, 무적, 후딜). 구간은 모션 위치 `from`부터 `to`까지이고, `color`는 `yellow`·`red`·`cyan`, 테두리를 두르려면 `"border": true`입니다. 구간이 겹치면 뒤에 적은 구간을 표시합니다. |

### 칸 그림

모션의 주요 순간을 칸으로 늘어놓은 jpg입니다.

```json
"rows": [
  {
    "title": "평타 1 ~ 5타",
    "note": "",
    "frames": [
      {"clip": "Samurai/Attack_Combo_B1", "t": 0.2833, "time": "0.28초", "label": "1타 내려베기", "hit": true, "banner": [["움찔", "yellow"]]}
    ]
  }
]
```

| 항목 | 뜻 |
| - | - |
| `title`, `note` | 줄 제목과, 제목 옆의 회색 설명 |
| `clip` | 모션. `팩/이름` 형식입니다(`Samurai/Attack_Combo_B1`, `Halberd/Attack_Combo1`). 움직이는 그림의 `clip`도 같습니다. |
| `t` | 모션 안의 시간(초). 가장 가까운 프레임을 씁니다. |
| `time` | 칸에 적는 시간. 여러 모션을 잇거나 재생 속도를 바꾼 그림은 그에 맞춰 계산한 값을 적습니다. |
| `label` | 시간 옆 설명 |
| `hit` | 타격 칸입니다. 테두리를 두르고, 직전 10프레임의 칼끝 궤적을 그립니다. |
| `trail` | 타격 칸에서 궤적을 뺄 때 `false` |
| `red` | 가드 불가 타격 칸입니다. 테두리와 글자를 빨간색으로 그립니다. |
| `banner` | 칸 아래의 판정 문구. `[문구, 색]` 목록이고, 색은 `yellow`(판정), `cyan`(무적·패리 구간 같은 구간), `red`(가드 불가, 가드 불가 예고)입니다. |

## 참고

- 중간 결과는 git에 올리지 않는 `Saved/Tools/MotionImages`에 저장됩니다. `probe.json`은 모션 데이터, `jobs.json`은 프레임(칸)별 자세와 카메라·라벨, `weapons.json`은 마지막으로 잰 무기 위치, `frames/`는 캡처한 프레임입니다. 모션 에셋을 바꾸면 `probe` → `make` 순서로 갱신합니다.
- 카메라는 캐릭터의 오른쪽 앞 위에서 루트를 내려다보고, 그림은 골반을 중심으로 자릅니다.
- 무기는 게임과 같은 자리에 그립니다. 그림을 만들 때마다 열린 에디터에서 `BP_AgPlayer`·`BP_AgBoss`를 잠깐 스폰해, 게임이 무기로 쓰는 컴포넌트(태그 `Weapon`)가 `hand_r`에 대해 어디에 붙는지 재고 바로 지웁니다. 캡처할 마네킹에는 같은 무기를 `hand_r`에 같은 위치로 붙여 자세를 따라가게 합니다. 소켓, 무기 컴포넌트 오프셋, 무기 메시를 바꿨으면 그림을 다시 만들기만 하면 됩니다. 에디터에 닿지 못하면(예: `plan`만 실행) 마지막으로 잰 값을 씁니다. 새 무기 메시를 쓰면 `common.py`의 `WEAPON_TIPS`에 날 끝 위치를 더합니다(칼끝 궤적용).
- 루트 모션을 켠 모션은 에디터 미리보기에서 루트가 제자리에 고정되어 그려집니다. 그래서 캡처할 때 임시 마네킹을 그 순간의 루트 위치로 옮깁니다.
