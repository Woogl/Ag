# 나이아가라

- 경량(Stateless) 시스템은 엔진 템플릿(`/Niagara/DefaultAssets/Templates/Systems/MinimalLightweight`)을 `duplicate_asset`으로 복제해 만든다. 이미터(`UNiagaraStatelessEmitter`)는 파이썬 타입이 없어 `ObjectIterator(unreal.Object)`에서 outer와 클래스 이름으로 찾고, 모듈(`Modules`)·렌더러·`EmitterState`·`FixedBounds`는 `set_editor_property`로 고친다.
- 사용자 파라미터, 일반(경량이 아닌) 이미터의 모듈과 그 입력, 이미터 이름은 엔진 실험 플러그인 NiagaraToolsets의 MCP 도구(`NiagaraToolsets.NiagaraToolset_System`)로 읽고 고친다. 파이썬에서는 부를 수 없다. 이미터·모듈·입력은 참조(`StackItemReference`)로 가리키며, 모듈은 스택에 보이는 이름이 아니라 `GetEmitterTopology`가 돌려주는 스크립트 이름과 모듈 이름(예: `ParticleSpawnScript`의 `InitializeParticle`)으로 찾는다. 사용자 파라미터 이름에는 `User.`가 붙는다.
- 나이아가라 메시 렌더러의 재질에는 사용 표시(`used_with_niagara_mesh_particles`)가 필요하다. 없으면 로그에 `missing usage flag NiagaraMeshParticles`를 남기고 기본 재질로 그린다. 엔진 재질(`BasicShapeMaterial`)에는 없으니 프로젝트 머티리얼을 만든다.
- 뼈에 붙이는 큐의 로컬 공간 이미터는 그 뼈의 축을 쓴다. 위로 움직여야 하면 `root`에 붙이고 이미터의 위치 오프셋으로 높이를 정한다.
- 사용자 파라미터는 `GetUserVariables`로 읽고 `AddUserVariables`로 더하거나 기본값을 바꾼다. 같은 이름이면 덮어쓴다. `RemoveUserVariables`는 저장소에서만 빼고 렌더러·모듈의 바인딩은 그대로 두므로, 그 파라미터에 연결한 입력과 바인딩을 먼저 끊는다.
- 모듈 입력은 `GetEmitterInputValues`로 읽고 `SetStackInputData`로 값을 넣거나 파라미터에 연결한다. 숨은 입력(Initialize Particle의 `Ribbon Facing Vector`는 `Ribbon Facing Mode`가 Direct Set일 때만 보임)은 엔진이 거부하므로 모드를 먼저 바꾼 뒤 따로 부른다. 모듈 삭제는 `RemoveModule`, 이미터 이름 변경은 `SetEmitterData`에 `{"Name": "새 이름"}`을 넣는다. 이 도구들은 컴파일하지 않으며, 저장할 때 엔진이 컴파일한다.
- 렌더러 속성(리본의 `facingMode` 등)은 파이썬 타입이 없어 `get_editor_property`로 `material` 말고는 읽지 못한다. MCP `ObjectTools.list_properties`·`get_properties`·`set_properties`(값은 JSON 문자열 `values`)로 고친다. 렌더러 경로는 `ObjectIterator(unreal.NiagaraRendererProperties)`에서 outer로 찾는다.
- 분포를 사용자 파라미터에 바인딩할 때는 분포 구조체에 `import_text('(Mode=Binding,ParameterBinding=(Name="User.X",TypeDefHandle=(RegisteredTypeIndex=N)))')`를 쓴다. N은 에디터 세션의 타입 번호라, 같은 타입의 렌더러 바인딩(`ColorBinding`은 색, `SpriteRotationBinding`은 실수)을 `export_text()`해 읽는다.
- 구조체 안의 분포(Dynamic Material Parameters의 `Parameter0` 등)는 고쳐도 엔진이 표(`Values`)를 다시 만들지 않는다. 곡선이면 `ChannelCurves`와 같은 값의 `Values`를 함께 넣는다.
- 이미터를 고친 뒤에는 시스템의 실행 데이터가 다시 만들어지지 않아 고치기 전 모양으로 재생된다. 저장하고 `EditorLoadingAndSavingUtils.reload_packages`로 다시 읽는다.
- 경량 이미터는 `seek_to_desired_age`·`set_desired_age`로 나이를 옮겨도 그 시점 모양이 나오지 않는다. 시간대별 모양은 실제 시간으로 재생하며 찍는다.
- NiagaraToolsets 도구의 답(토폴로지 등)은 수십 KB라, 여러 번 고칠 때는 `.mcp.json`의 주소로 MCP 요청(`call_tool`에 `toolset_name`·`tool_name`·`arguments`)을 보내는 스크립트로 부르고 결과를 줄여 본다.
- 모듈 입력은 `NiagaraExt_StackInputData_HlslExpression`으로 식을 넣을 수 있고, 식에서 `User.X`·`Particles.NormalizedAge`를 쓴다. 벡터 VM에는 `smoothstep`이 없어 컴파일이 실패한다(`saturate`·`pow`는 됨).
- 열거형 입력 값은 `enumName`에 `NewEnumeratorN`, `displayName`에 보이는 이름을 넣는다. 번호와 이름의 짝은 엔진 `Plugins/FX/Niagara/Content/Enums`의 열거형 에셋 `DisplayNameMap`을 uasset 분석기로 읽는다. 모드 입력을 바꿔야 그 모드의 입력(`Ring Radius` 등)이 보인다.
- 템플릿 이미터의 `ScaleSpriteSize`와 `/Niagara/Modules/Update/Size/ScaleSpriteSize`는 버전이 달라 입력이 다르다. 크기를 식으로 정할 때는 파티클 업데이트의 SetParameters로 `Particles.SpriteSize`를 직접 쓴다. 바닥에 눕힐 스프라이트는 SetParameters로 `Particles.SpriteFacing`을 (0,0,1)로 두고 렌더러 `FacingMode`를 `CustomFacingVector`로 둔다.
- 뒤에 있는 에디터에서도 모양을 시간대별로 보려면, 임시 스폰한 `NiagaraActor`의 컴포넌트를 `reset_system`·`activate` 뒤 `advance_simulation(틱 수, 틱 시간)`으로 나이를 옮기고, 임시 `SceneCapture2D`의 `capture_scene`과 `RenderingLibrary.export_render_target`으로 찍는다.
- 미리 보기는 임시 액터로 띄우고 지운다([에셋 편집](<에셋 편집.md>) '블루프린트'의 임시 스폰). 뒤에 있는 에디터의 뷰포트는 다시 그려지지 않아 `AutomationLibrary.take_high_res_screenshot`이 찍히지 않으므로, PIE 항목의 `bThrottleCPUWhenNotForeground`를 잠시 끈다.
