# 에셋 편집

## 에디터 없이 읽기

- `.uasset`의 이름 표를 읽는다. 속성 이름은 값이 기본값과 다를 때만 남으므로, 없으면 기본값이다. `/Game/...` 경로는 그 에셋이 참조하는 에셋이다.
- 레벨 액터는 액터마다 파일이 따로 있다(`Content/__ExternalActors__/Maps/<맵>/`).
- 스켈레탈 메시 컴포넌트의 메시는 `SkinnedAsset`으로 저장된다.

## T3D로 읽기

- 파이썬으로 읽을 수 없는 속성은 객체를 T3D로 내보내 읽는다. `unreal.AssetExportTask`의 `object`에 객체를, `filename`에 출력 경로를, `exporter`에 `unreal.ObjectExporterT3D()`를 주고 `unreal.Exporter.run_asset_export_task`를 부른다. 실수 값은 소수 6자리로 나온다.

## 삭제와 이름 변경

- 지우기 전에 `get_referencers`로 참조를 확인한다. 리비전 컨트롤이 꺼진 에디터에서 MCP `AssetTools.delete`와 파이썬 `EditorAssetLibrary.delete_asset`은 메모리의 패키지만 지우고 `.uasset`은 남긴다. 파일은 `git rm`으로 지운다.
- 참조를 다른 에셋으로 바꾼 직후 지우려면 먼저 `unreal.SystemLibrary.collect_garbage()`를 부른다. 아니면 강제 삭제가 ensure에 걸린다.
- `AssetTools.rename_assets`는 옛 경로에 리다이렉터를 남기고, 파이썬에는 리다이렉터를 정리하는 함수가 없다. 리다이렉터를 `save_packages`로 저장해 dirty를 없앤 뒤 `git rm -f`로 지운다.
  - 지우기 전에 참조하는 에셋이 새 경로로 저장됐는지 `grep -a`로 확인한다. 불러오지 않은 맵·외부 액터와, 같은 작업에서 먼저 이름을 바꾼 에셋(뒤에 바꾼 에셋을 참조)은 옛 경로로 남는다. 에셋은 불러와 `save_asset(경로, only_if_is_dirty=False)`, 열린 레벨은 월드 세팅·액터에 `modify()` 뒤 `save_dirty_packages`로 다시 저장한다.
  - 불러온 패키지가 참조하는 리다이렉터 파일은 지워지지 않는다('Device or resource busy'). 그 패키지와 리다이렉터를 `unload_packages`로 내린 뒤 지운다.
  - 리다이렉터 파일을 지운 뒤 그 대상 에셋까지 에디터에서 지우면, 옛 경로 패키지가 dirty로 남고 저장·언로드·삭제가 모두 실패한다. 에디터를 닫을 때 '콘텐츠 저장' 창에서 '저장 안 함'으로 버린다.
- `DesignData` JSON의 에셋 경로는 에디터의 참조(`get_referencers`, 리다이렉터 정리)에 잡히지 않는다. 에셋 이름을 바꾸면 JSON 경로도 함께 고치고, 용어를 일괄 치환하다 JSON의 에셋 경로가 바뀌었으면 에셋 이름도 바꾼다. 고친 뒤 에디터 시작 로그에 `LogAg` 오류가 없는지 본다.
- INI의 소프트 경로가 가리키는 에셋은 이름 변경이 취소된다(확인 창이 무인 실행에서 자동으로 취소된다). 그 설정 객체의 값을 메모리에서 먼저 새 경로로 바꾸면 이름 변경이 된다(예: `unreal.GameMapsSettings.get_default_object()`의 `global_default_game_mode`). INI 파일은 따로 고친다.

## 블루프린트

- 블루프린트 기본값은 CDO(`Default__BP_X_C`, C++ 컴포넌트는 `/Game/.../BP_X.Default__BP_X_C:<컴포넌트>`)를 MCP `set_properties`나 파이썬으로 고친 뒤 `unreal.BlueprintEditorLibrary.compile_blueprint(bp)` → 저장한다. 컴파일하지 않으면 스폰된 인스턴스가 네이티브 기본값을 받는다. 고친 기본값은 스폰되는 액터에만 가고 레벨에 배치된 인스턴스에는 가지 않으니, 인스턴스도 고치거나 레벨이 dirty가 아닐 때 레벨을 다시 연다.
- PIE는 에디터 월드를 복제할 때 construction을 다시 실행하지 않는다. 에셋을 저장한 뒤에도 배치된 액터가 옛 데이터를 보이면 레벨을 다시 연다.
- 블루프린트 컴포넌트의 Parent Socket은 `AgAssetToolset.SetComponentParentSocket`으로 바꾼다. 무기(`Weapon`, 자식 `WeaponCollision`)를 블루프린트 컴포넌트로 둔 것은 C++에서 만든 컴포넌트는 블루프린트에서 Parent Socket을 바꿀 수 없기 때문이다. 코드는 컴포넌트 태그로 찾는다.
  - 블루프린트 컴포넌트는 `SubobjectDataSubsystem.add_new_subobject`로 더하고, 이름은 `rename_subobject_member_variable`로 바꾼다(`rename_subobject`는 조용히 실패한다).
  - 부모 C++ 클래스의 UPROPERTY와 같은 이름의 블루프린트 변수는 컴파일이 실패한다.
- 컴파일 뒤 `bp.get_editor_property("status")`를 확인하고, 오류 상태로 저장하지 않는다.
- 그래프 읽기: MCP `BlueprintTools.read_graph_dsl`은 빈 문자열을 돌려줄 때가 있다. `list_graphs` → `find_nodes`(`title` 빈 문자열이면 모든 노드) → `get_node_infos`로 노드와 핀 연결을 읽는다.
- 노드 종류 이름은 `BlueprintTools.find_node_types(graph, type_id_filter, context_pins=[])`로 찾는다. 이 도구는 읽기만 해도 그 블루프린트를 dirty로 만들므로, 고칠 블루프린트에만 고치기 직전에 쓴다. 파이썬 `EditorLoadingAndSavingUtils.reload_packages`는 원격 실행(unattended)에서 '리로드할까요?' 창에 '아니요'로 답해 되돌리지 못한다. 그때는 저장하고 에디터를 닫은 뒤 그 `.uasset`을 `git restore`한다.
- 부모 클래스는 `unreal.BlueprintEditorLibrary.reparent_blueprint(bp, cls)` 뒤 컴파일해 바꾼다. 옛 부모에만 있던 속성은 사라지니 먼저 읽어 둔다.
- C++ 속성을 Transient로 바꿔도, 블루프린트에 전에 저장된 그 속성의 값은 블루프린트 CDO에 다시 읽혀 저장할 때 참조(import)로 남는다. 그 참조 에셋을 지울 때는 에디터를 닫고 에셋 파일을 지운 뒤, 에디터를 다시 켜 블루프린트를 다시 저장하고 `.uasset`에 옛 경로가 없는지 `grep -a`로 확인한다. 컴파일하면 레벨에 배치된 인스턴스가 다시 만들어져 레벨이 dirty가 되므로 저장만 한다.
- 테스트용 액터를 에디터 월드에 스폰하면 레벨이 dirty가 된다. 잴 것이 있으면 임시 스폰(`EditorActorSubsystem.spawn_actor_from_class(cls, loc, rot, True)`)으로 띄우고 지운다. 임시 액터는 `EditorActorSubsystem.get_all_level_actors`에 나오지 않으니 `GameplayStatics.get_all_actors_of_class`로 찾는다.

## 메시 소켓

- 정적 메시 소켓은 파이썬으로 `unreal.new_object(unreal.StaticMeshSocket, mesh)`에 `socket_name`·`relative_location`을 넣고 `mesh.add_socket`으로 더한다. 스켈레탈 메시 소켓은 파이썬에서 이름이 읽기 전용이라 MCP `SkeletalMeshTools.add_socket`·`set_socket_transform`을 쓴다.
- 스켈레탈 메시 소켓의 위치는 붙인 본의 공간이라 본의 배율을 받는다(`Halberd_weapon`의 루트 본 `Halberd`는 배율이 10이라 메시 좌표의 1/10로 넣는다). 본의 기준 자세는 `AnimPoseExtensions.get_reference_pose(skeleton)`로 읽는다.

## 구조체와 배열

- MCP `set_properties`는 배열 크기와 요소를 한 번에 바꾸지 못한다. 먼저 남길 요소를 `get_properties`가 돌려준 그대로(객체 참조는 `{"refPath": ...}`) 넘겨 줄이고, 같은 크기에서 새 값을 넣는다.
- 인스턴스 하위 객체 배열에 요소를 더할 때는 남길 요소를 그대로 두고 새 자리에 클래스 경로(`{"refPath": "/Script/Ag.<클래스>"}`)를 넣는다. 그 클래스의 새 하위 객체가 생긴다.
- 구조체 안의 EditDefaultsOnly 필드는 `set_editor_property`로 쓸 수 없다. `struct.import_text('(...)')`로 채운 뒤 구조체 전체를 CDO에 쓴다.
- `get_editor_property`가 돌려준 배열의 요소를 고칠 때는 요소를 변수로 받아 고친 뒤 배열에 다시 넣는다(`info = arr[0]`, 고치기, `arr[0] = info`). `arr[0].import_text(...)`는 복사본만 바꾼다.
- 머티리얼 Custom 노드의 입력은 `set_properties` 한 번에 하나씩, 요소를 통째로(`inputName`과 `input`) 넣어 늘린다.

## GAS와 StateTree

- GameplayCue를 복제하면 태그를 바꿀 때까지 "Multiple gameplay cues ... Skipping" 경고가 나고 원본만 재생된다. 복제본의 CDO에 `set_editor_property('gameplay_cue_tag', tag)`로 태그를 주면 바로 다시 등록된다. 엔진 `GameplayCueToolset.AddCueTag`는 태그 ini에 쓰므로 쓰지 않는다(AGENTS.md 코딩 규칙 3).
- 에디터를 켤 때 부모 클래스를 찾지 못한 GameplayCue 블루프린트는 경고 없이 Cue 목록에서 빠진다. 켜 둔 에디터에서 부모를 바꿔 저장해도 목록은 다시 만들어지지 않아, 그 세션의 PIE에서는 그 Cue가 나오지 않는다. 부모를 바꿨으면 에디터를 다시 켠 뒤 확인한다. 등록 여부는 `GameplayCueManager_0`의 `GlobalGameplayCueSet`에서 `GameplayCueData`의 태그로 본다(파이썬에 `GameplayCueSet` 타입이 없어 `ObjectIterator(unreal.Object)`에서 클래스 이름으로 찾는다). `GameplayCueData`는 파이썬으로 읽을 수 없으니 그 객체를 T3D로 내보내 읽는다('T3D로 읽기'). 엔진 `GameplayCueToolset.GetCueInfo`·`FindCueTagsWithoutNotifies`는 등록된 큐도 노티파이가 없다고 답하므로 쓰지 않는다.
- 큐 블루프린트의 `DefaultPlacementInfo`에서 붙이는 효과의 `AttachmentRule`은 `KeepWorld`로 둔다. 엔진은 월드 위치를 넘기는데 `SnapToTarget`은 그 값을 상대 위치로 써 효과가 붙일 대상에서 멀리 생긴다.
- StateTree는 `AgAssetToolset`의 StateTree 함수로 고치고, `CompileStateTree`(빈 문자열이면 오류 없음)로 컴파일한 뒤 저장한다. 읽을 때는 엔진의 StateTree 조회 도구를 쓰고, 스키마의 속성은 엔진의 `set_properties`로 스키마 객체에 쓴다.
- 파이썬으로 상태 이름을 바꾸려면 `unreal.ObjectIterator(unreal.StateTreeState)`를 `get_outermost().get_name() == '/Game/AI/ST_Enemy'`로 걸러 `set_editor_property('name', ...)`로 바꾸고, 컴파일하고 저장한다. 전환은 ID로 이어져 있어 그대로 남는다.
- `ST_Enemy`의 머무는 상태(사망)는 엔진 Delay 태스크를 계속 실행으로 둔다. 태스크가 없는 상태는 바로 끝나고, 전환 없이 끝나면 루트로 돌아간다. 사망 전환은 루트가 아니라 전투, 비전투, 플레이어 사망 대기 상태에 둔다. 루트의 틱 전환은 이미 그 상태여도 매 틱 다시 전환한다. 적 시스템 기획서 '전투 시작과 상태 전환'의 전환은 상위 상태에 우선순위가 높은 전환으로 두어, 같은 프레임에 행동이 끝나도 먼저 적용되게 한다.
