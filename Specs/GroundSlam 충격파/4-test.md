# GroundSlam 충격파 검증 결과

## 1. 테스트 시나리오

- `python -I Scripts/ScenarioTest/run.py Saved/ScenarioTest/Scenarios/boss_groundslam_shockwave.py` (보스 스테이지, 적 AI 정지, `AgPattern GroundSlam` 4회)
  1. 6m에서 가드 키를 누른 채
  2. 6m에서 착지 직전(패턴 1.15초 전후) 점프
  3. 6m에서 착지 직전 회피
  4. 15m에서 착지 0.03초 뒤 `AgGroggy` (아레나 안에서 보스와의 사이가 트인 방향을 찾아 섬)
- `python -I Scripts/ScenarioTest/run.py Saved/ScenarioTest/Scenarios/boss_swordwave_hit_reflect.py` (회귀: 8m에서 검기 3발 맞기, 첫 발 패리)
- `python -I Scripts/ScenarioTest/run.py Saved/ScenarioTest/Scenarios/gunner_pistol.py --map "/Game/Maps/LV_SimulationRoom?Enemies=Gunner"` (회귀: 탄환을 총구 소켓에서 조준 발사)

통과 기준은 실행 전에 Spec 2.2 값으로 정했습니다. 착지 후 피격 시각은 보스가 플레이어 1.5m 앞에 착지하므로 (1.5 − 캡슐 반지름 0.34) ÷ 15 = 0.077초, 15m 자리는 착지 지점에서 4m라 0.24초입니다(프레임 오차 포함 판정).

## 2. 결과

- 빌드: `AgEditor Win64 Development` 성공. 에디터 재시작 뒤 `SpawnActors.json` 로드 오류 없음 (BP를 만들기 전 로드의 `GroundSlamShockwave` 클래스 없음 오류뿐).
- 판정: 세 시나리오 모두 통과.

| 완료 조건 | 결과 |
| - | - |
| 착지하는 순간 충격파가 생기고 초당 15m로 퍼져 반경 15m에서 사라짐 | 착지 프레임에 생성, 0.96 ~ 0.98초 유지, 마지막 프레임 반경 14.8 ~ 14.9m |

| 점프로 떠 있으면 맞지 않음 / 지나간 뒤 안쪽으로 들어오면 맞지 않음 | 지날 때 공중, 착지 지점 안쪽에 내려와도 피격 없음 |

| 회귀: 탄환 | 조준 → 발사 → 재장전, 창 로그 게임 오류 없음 |

### 확인하지 않은 완료 조건

- 15m보다 먼 플레이어가 맞지 않음: 아레나(약 33m)에 27m 넘게 떨어진 자리를 만들 수 없어, 충격파가 반경 15m에서 사라지는 것으로 대신 확인했습니다.
- 벽 너머의 대상이 맞음: 판정 코드가 벽을 질의하지 않습니다. 플레이로 확인하지 않았습니다.
- 회피 무적(극한 회피 구간이 지난 뒤)으로 피함: 무적은 다른 공격과 같은 대미지 실행 계산이 처리합니다. 따로 확인하지 않았습니다.
- 궁극기 시간 정지 동안 멈춤: 시간 정지는 게임 전체 시간 배율이라 투사체와 같이 멈춥니다. 따로 확인하지 않았습니다.
- 외형: 테스트 창 캡처(착지 0.1초 뒤, 0.6초 뒤)로 지면의 밝은 띠와 낮은 벽이 보이고 안쪽은 옅은 것까지 확인했습니다. 움직일 때의 느낌은 사람이 보고 판단합니다.

### 에디터 PIE에서 충격파가 보이지 않던 문제

- 원인: 에디터가 시작할 때 JSON으로 만든 템플릿이, 그 뒤 BP를 다시 컴파일하자 옛 클래스(`REINST_BP_GroundSlamShockwave_C_1`)로 남았습니다. PIE에서 그 클래스로 생성되어 컴포넌트가 등록되지 않았습니다(에디터 로그 `Owner belongs to a DEADCLASS`). 테스트 창은 새로 켜며 읽어 보였습니다.
- 수정 확인: 에디터를 다시 켠 뒤 BP를 컴파일하자 에셋 매니저의 템플릿이 현재 클래스로 다시 만들어졌습니다(`BP_GroundSlamShockwave_C_0` → `_C_1`).

## 3. 회귀 확인

- 검기(`AAgProjectile`): 적중·관통·패리 반사 정상. 벽 소멸·사거리 소멸은 코드를 바꾸지 않은 부분이라 따로 돌리지 않았습니다.
- 탄환: 총구 소켓 발사와 조준 흐름 정상(플레이어 무적 시나리오라 적중은 확인하지 않음).
- 실행 중 다른 작업이 고친 `AgPlayerCharacter.cpp`, `AgGameplayTags.*`는 이 빌드 뒤의 변경이라 창에 들어가지 않았습니다.
