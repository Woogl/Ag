# 에셋 로딩 범위 검증 결과

## 1. 테스트 시나리오

- 공유 에디터가 켜져 있어 프로젝트 폴더는 빌드하지 않고, 작업 트리를 스크래치 폴더 두 곳에 복사해(`Content`·`DerivedDataCache`는 접합점) 따로 빌드했습니다. 하나는 구현 전(하드 참조로 켤 때 모두 읽음), 하나는 구현 후입니다. 다른 작업의 미커밋 변경은 둘 다 포함합니다.
- 메모리: 테스트 창(쿡하지 않은 에셋, `-game`)을 장면마다 새로 띄우고, 원격 실행이 응답한 뒤 30초 기다려 가비지 컬렉션을 돌린 다음 엔진 파이썬의 `ObjectIterator`로 메모리에 있는 에셋을 셌습니다. 장면마다 1회입니다.
- 회귀: `python -I Scripts/ScenarioTest/run.py <시나리오.py>`를 한 창씩 차례로 실행했습니다.
- 다시 읽기: 구현 후 사본에만 다시 읽기를 부르는 콘솔 명령을 넣고(저장소에는 없음), 테스트 창에서 살아 있는 플레이어의 회복병 몽타주를 JSON에서 바꿔 다시 읽었습니다. 파일 감시가 다시 읽기를 부르는 부분(`UAgDataReloadSubsystem`)은 바뀌지 않았습니다.
- 묶음을 읽는 시간: 구현 후 사본에만 `LoadData`에 시간 로그를 넣어 쟀습니다(저장소에는 없음).

## 2. 결과

- 빌드: 두 사본 모두 `Build.bat AgEditor Win64 Development -NoHotReloadFromIDE` 성공.
- 포맷: 바꾼 C++ 파일 `Scripts/FormatCpp.ps1` 통과.

### 메모리에 있는 에셋 (구현 전 → 후)

| 항목 | 타이틀 | 시뮬레이션 룸(샌드백만) | 요새 스테이지 |
| - | - | - | - |
| 몽타주 `AM_*` | 38 → 0 | 38 → 24 | 38 → 37 |
| 애니메이션 시퀀스(`/Game`) | 111 → 0 | 137 → 118 | 137 → 137 |
| 생성 액터 BP 클래스(`/Game/Projectiles`) | 14 → 0 | 14 → 6 | 14 → 14 |
| 카메라 셰이크 BP 클래스(`/Game/Camera`) | 6 → 0 | 6 → 6 | 6 → 6 |
| 레벨 시퀀스(궁극기 컷신) | 1 → 0 | 1 → 1 | 1 → 1 |
| 나이아가라 시스템(`/Game`) | 6 → 0 | 18 → 16 | 18 → 18 |
| 블루프린트 클래스(`/Game`) | 76 → 46 | 178 → 170 | 166 → 166 |
| 프로세스 private MB | 4615 → 3710 | 5681 → 5657 | 5695 → 5649 |

- 블루프린트 클래스 수는 에디터 실행 파일이 블루프린트마다 클래스를 둘씩 올려, 생성 액터 7종이 14, 셰이크 3종이 6으로 셉니다.
- 타이틀에는 몽타주, 생성 액터, 카메라 셰이크, 컷신이 하나도 없습니다.
- 샌드백만 둔 시뮬레이션 룸에는 플레이어와 샌드백이 쓰는 것만 남습니다. 보스·절단자·경비 사수만 쓰는 몽타주 14개와 생성 액터 4종이 빠졌습니다.
- 요새에서 빠진 몽타주 하나는 이 스테이지에 없는 공격 샌드백의 것입니다.
- 프로세스 메모리는 에디터 실행 파일과 에디터 전용 데이터를 포함한 값이고 1회 측정입니다. 스테이지의 차이(−24, −46 MB)는 이전 측정에서 본 실행 사이 흔들림(13~32 MB) 수준입니다. 타이틀의 차이에는 궁극기 컷신의 에디터 전용 미리 보기 바인딩이 붙잡던 플레이어 블루프린트와 메시가 들어 있어, 패키지 게임에서는 이보다 작습니다. 패키지 게임에서는 재지 않았습니다.

### 캐릭터가 묶음을 처음 읽는 시간

| 묶음 | 시간 |
| - | - |
| 플레이어(어빌리티 27개) | 697 ~ 1073 ms |
| 경비 사수(9개) | 439 ms |
| 보스(17개) | 206 ms |
| 절단자(11개) | 47 ms |
| 샌드백(7개) | 46 ms |
| 카메라 설정 | 1 ~ 2 ms |

- JSON 항목을 리플렉션으로 읽는 시간과 에셋의 동기 로딩을 합친 값이고, 쿡하지 않은 에셋을 에디터 실행 파일로 읽은 값입니다. 다른 측정 창이 함께 떠 있던 실행이 섞여 있습니다. 레벨을 여는 동안 듭니다.
- 절단자와 샌드백이 짧은 것은 몽타주 대부분을 먼저 읽힌 캐릭터와 함께 쓰기 때문입니다.

### 다시 읽기

테스트 창에서 회복병을 한 번 쓴 뒤(`AM_Player_Potion`), `Abilities.json`의 회복병 몽타주를 `AM_Player_Parry`로 바꿔 다시 읽었습니다. 다음 발동은 `AM_Player_Parry`를 재생했고, JSON을 되돌려 다시 읽자 다음 발동은 `AM_Player_Potion`을 재생했습니다. 캐릭터가 붙잡고 있는 묶음 객체가 그대로 새 값을 받는 것을 확인한 것입니다. 생성 액터 정의는 같은 묶음 안에 들어 있어 따로 확인하지 않았습니다.

### 오류 검사

`Abilities.json`의 회복병 몽타주를 없는 경로로 바꾸고 타이틀 맵으로 켜자, 캐릭터가 없는데도 켤 때 `LogAg: Error: DesignData/Abilities.json: Potion.Montage.Asset: /Game/Animations/AM_Missing.AM_Missing is not an asset or class of AnimMontage`가 나왔습니다.

## 3. 회귀 확인

- 위 회귀 시나리오 12개.
- 확인하지 않은 것: 패키지 게임 실행과 그 메모리, 프로젝트 폴더 빌드, 사용자 에디터의 PIE에서 JSON을 저장해 다시 읽기(파일 감시 경로는 바뀌지 않았고, 다시 읽기 자체는 위 테스트 창에서 확인), 플레이 중 처음 등장하는 종류의 캐릭터를 소환할 때 멈춤의 체감.
