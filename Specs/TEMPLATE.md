# Spec-Driven Development 템플릿 가이드

`Specs/<작업명>/`에 두는 작업 문서의 형식입니다. 진행 순서는 [AI 워크플로우](<../Docs/AI 워크플로우.md>)의 'SDD 진행 순서'를 따릅니다.

---

## 1. `1-spec.md` (기획 요구사항)
> **목적**: 이번 작업에서 무엇을 왜 만드는지, 구체적인 플레이 규칙과 수치를 정의합니다.

```markdown
# [기능명] 작업 명세 (Spec)

## 1. 개요 및 목적
- 변경/추가하려는 의도와 목표

## 2. 플레이 규칙 및 수치
- 조작, 판정, 수치(대미지, 자원, 시간), 예외 처리
- 기존 Docs 기획서와의 관계 (신규 추가 또는 덮어쓰기)

## 3. 완료 조건 (Acceptance Criteria)
- [ ] 시나리오 1: ...
- [ ] 시나리오 2: ...
```

---

## 2. `2-plan.md` (기술 설계)
> **목적**: C++ 클래스 구조, GAS 어빌리티/태스크, JSON 스키마 변경 사항을 구체적으로 설계하여 구현 전 프로그래머의 승인을 받습니다.

```markdown
# [기능명] 기술 설계 (Plan)

## 1. 영향 범위 및 아키텍처
- 수정/추가할 C++ 클래스, 컴포넌트, 인터페이스
- `Docs/Architecture/` 공통 규칙 준수 여부

## 2. GAS 및 데이터 설계
- GameplayAbility, GameplayEffect, GameplayTag 네이티브 선언
- `DesignData/` JSON 스키마 변경점

## 3. 인터페이스 & 함수 시그니처
- 추가/변경할 함수 선언
```

---

## 3. `3-tasks.md` (작업 체크리스트)
> **목적**: AI와 개발자가 진행 상황을 실시간으로 추적하고 놓치는 부분이 없도록 독립적인 실행 단위로 나눕니다.

```markdown
# [기능명] 작업 태스크

- [ ] 1. ...
- [ ] 2. ...
```

---
