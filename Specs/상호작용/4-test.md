# 상호작용 검증 결과

## 1. 테스트 시나리오

- 실행 명령: `python -I Scripts/ScenarioTest/run.py <시나리오.py>`
- 성문은 레벨에 배치하지 않았습니다(요새 돌파의 배치는 기획자가 합니다). 성문 시나리오는 보스 스테이지의 테스트 창 안에서 `BP_Gate`를 만들어 플레이어 시작 자리 3m 앞 바닥에 놓고 확인합니다.
- 회귀 시나리오로 남긴 것: `Saved/ScenarioTest/Scenarios/interaction_gate.py`, `interaction_priority.py`
- 한 번만 쓴 시나리오(임시 폴더, 남기지 않음): 처형 안내, 안내 숨김, 화면 캡처

| 시나리오 | 확인한 것 |
| - | - |
| `interaction_gate.py` | 닫힌 성문, 안내의 범위와 위치, 열림, 한 번만 |
| `interaction_priority.py` | 처형이 성문보다 우선, 처형 뒤 성문 |
| 처형 안내 (임시) | 처형 안내의 범위, 후딜 전 입력, 공중 대상에서 안내가 늦는 정도 |
| 안내 숨김 (임시) | 궁극기 컷신과 스테이지 결과 중 숨김 |
| `player_execution.py`, `groggy.py` | 처형·그로기 회귀 |
| `player_combo.py`, `stage_boss_clear.py`, `player_dodge.py` | 입력·적 캐릭터 변경의 회귀 |

## 2. 결과

- 빌드: 실제 트리 Build.bat 성공(성문 수정 포함).
- 판정: 상호작용 시나리오 4개 통과. `interaction_gate.py`, `interaction_priority.py`, `player_execution.py`는 실제 트리의 마지막 빌드로 실행했습니다. 처형 안내, 안내 숨김, `player_combo.py`, `stage_boss_clear.py`, `player_dodge.py`는 같은 소스의 임시 사본 빌드로, `groggy.py`는 성문 수정 전의 실제 트리 빌드로 실행했습니다.
- 요새 돌파의 문틀 사이에 성문을 임시로 놓고 돌린 실행에서도 성문·우선순위 항목이 모두 통과했습니다(문틀 폭 5m × 높이 5m에 `BP_Gate` 기본 크기가 맞음). 그 배치는 되돌렸습니다.

| 완료 조건 | 결과 | 근거 |
| - | - | - |
| 상호작용 대상이 없으면 F가 아무 일도 하지 않음 | 통과 | 열린 성문 뒤에서 F: 변화 없음 |

| 궁극기 컷신·스테이지 결과 중 안내 없음 | 통과 | 컷신 2.55 ~ 4.45초 동안 없음, 컷신 뒤 복귀, 보스 사망 뒤 없음 |

| 길게·여러 번 눌러도 한 번만 열림 | 통과 | 여는 중 1초 연타: 문 높이가 줄지 않고 +500cm에서 끝남 |

| 레벨을 시작하면 성문이 닫혀 있고 커스터가 보이지 않음, 사수의 탄환이 성문에 막힘, Restart 뒤 닫힌 상태 | 실행하지 않음 | 성문이 레벨에 배치된 뒤 확인. 지금은 탄환과 시야가 쓰는 선 검사가 막히는 것만 확인 |

- 안내가 대상보다 늦는 정도(틱 그룹을 엔진 기본값으로 둔 결과): 서 있는 그로기 대상은 최대 2.6cm, 넉업으로 뜬 대상은 72프레임 평균 4.7cm, 최대 20.1cm(뜨는 첫 프레임, 그 프레임에 락온 지점이 30.3cm 움직임). 한 프레임 늦게 따라가는 값입니다. 눈에 거슬리는지는 플레이로 판단이 필요합니다.

### 고친 문제

- 성문이 다 열리는 순간 게임이 멈췄습니다(스택 오버플로). 이동이 끝났다는 알림 안에서 이동 컴포넌트를 껐는데(`Deactivate`), 엔진은 끌 때 같은 알림을 다시 보내 서로를 끝없이 불렀습니다. 끄는 호출을 지웠습니다. 문이 멈춘 뒤 이동 컴포넌트는 엔진 기본 동작대로 켜진 채 아무 일도 하지 않습니다.
