# 움찔 부위별 반응 검증 결과

## 1. 테스트 시나리오

- 시나리오 실행 명령: `python -I Scripts/ScenarioTest/run.py <시나리오.py>` (시나리오는 임시 파일, 보스 AI 정지)
- A. 섹션 선택: 커스터와 린에게 `Event.Hit.Stagger.Back`·`Head`·`ArmRight`·`ArmLeft`·`Body`를 2초 간격으로 보냄. 기준: 각 이벤트 1초 안에 `AM_Flinch:<부위>` 재생, `State.HitReaction.Flinch` 유지 0.77 ~ 0.90초(모션 0.817초, 프레임 측정 오차 포함).
- B. 실제 타격: 린의 스킬(넉업)을 커스터 정면 2m, 등 뒤 2m에서 맞히고, 커스터 PP 1에서 정면으로 맞힘. 기준: 정면은 `Back`이 아닌 움찔 섹션이고 넉업 없음, 등 뒤는 `Back`, 그로기 타격은 그로기 태그와 넉업 태그가 0.05초 안에 함께 붙고 움찔 없음.
- C. 공중·넉다운: 앞으로 이동하며 점프한 린에게 공중에서 `Event.Hit.Stagger.Head`를 보내고, 이어 두 캐릭터에 `Event.Hit.KnockDown`을 보냄. 기준: `AM_FlinchAir` 재생, 공중에 있는 동안 수평 속도가 맞을 때의 50% 이상, 행동 불가 0.35 ~ 0.45초, 넉다운은 `AM_KnockDown`으로 1.6초 동안 3.5 ~ 4.5m 밀림.

## 2. 결과

- 빌드: `AgEditor Win64 Development` 성공.
- 판정:

| 시나리오 | 판정 | 내용 |
| - | - | - |
| A | 테스트 실패 (판정 기준 문제) | 10개 모두 해당 섹션 재생. 행동 불가 측정값 0.77 ~ 0.80초 중 `Head` 두 건이 하한 0.77초를 약 0.002초 밑돎. 45fps에서 첫 프레임과 마지막 프레임 사이를 재는 방식이라 실제 길이보다 최대 2프레임(약 0.045초) 짧게 나옵니다. 하한을 0.817 − 2프레임으로 잡지 않은 판정 코드의 오차이며, 기준을 바꿔 다시 돌리지는 않았습니다. |
| B | 통과 | 정면 `AM_Flinch:Body`, 넉업 없음. 등 뒤 `AM_Flinch:Back`. 그로기 타격은 그로기와 넉업이 같은 프레임(10.453초)에 시작. |
| C | 통과 (세 번째 실행) | `AM_FlinchAir` 재생, 공중 수평 속도 350 유지, 행동 불가 0.37초. 넉다운 이동: 커스터 4.23m, 린 3.52m. |

- C의 첫 두 실행은 판정 코드 문제로 실패했습니다. 수평 속도 구간에 착지 뒤 지상 프레임이 섞였고(공중에서는 350 유지), 린 넉다운 거리의 기준 위치를 순간이동 직전에 잡았습니다. 기준값은 두고 구간과 기준 위치만 고쳐 다시 돌렸습니다.
- 시나리오 코드의 함수 이름 오류(`AbilitySystemLibrary`)로 A·C 첫 실행이 실행 실패했습니다.
- 로그: `Saved/ScenarioTest/slot1_20261029-220826.json`(A), `slot2_20261029-220705.json`(B), `slot1_20261029-221202.json`(C). 게임 오류(`LogAg: Error`) 없음.

## 3. 회귀 확인

- 넉업·그로기 넉업(`AM_KnockUp` Rise → Fall → Land → GetUp)과 공중 움찔 중 착지가 기존과 같이 동작.
- 관찰: 린의 넉다운 이동(3.52m)이 커스터(4.23m)보다 짧습니다. 같은 몽타주라 캐릭터 무브먼트 설정이나 주변 충돌의 차이로 보이며, 기준 범위 안이라 따로 조사하지 않았습니다.
- 확인하지 않은 것: 투사체·범위 공격의 움찔(부위 없음 → `Body`), 넉업으로 떠 있는 커스터의 저글, 사람이 직접 보는 모션 품질.
