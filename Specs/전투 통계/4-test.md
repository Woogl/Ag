# 전투 통계 검증 결과

## 1. 테스트 시나리오

모두 테스트 창(별도 게임 프로세스)에서 실행했습니다.

| 시나리오 | 맵 | 확인한 것 |
| - | - | - |
| `Saved/ScenarioTest/Scenarios/combat_stats.py` (회귀) | `LV_SimulationRoom?Enemies=,,AttackSandbag` | 공격 샌드백의 실제 공격 5번에 피격, 가드, 패리, 극한 회피, 피격 순으로 대응한 뒤 `AgKillPlayer`. 기록의 결과·상대한 적·횟수와 Game Over 결과창의 통계 표 |
| 낙하·쓰러뜨린 공격 (임시) | `LV_SimulationRoom?Enemies=,,AttackSandbag` | 전투 중 15m 낙하(낙하 대미지)와 HP 1%에서 샌드백 공격에 사망 |
| 보스 처치 (임시) | `LV_BossStage` | 보스 처치 순간의 처치 기록, 보스 스테이지 결과창에 표 없음, 버튼 위치 |
| 도전 횟수 드라이버 (임시) | `LV_SimulationRoom?Enemies=Cutter` | 결과창 Restart, 타이틀을 거친 재진입, 플레이어를 시야 밖(공중)으로 옮긴 이탈, 배치 좌표 |
| 일시정지 드라이버 (임시) | `LV_SimulationRoom?Enemies=Cutter` | 전투 중 일시정지 메뉴 Restart(저장 안 됨, 도전 +1), 일시정지 메뉴 8초 열어 둠 |

- 실행: `python -I Scripts/ScenarioTest/run.py <시나리오> --map "<맵>"`. 드라이버는 실행기의 창 띄우기를 빌려 레벨을 여러 번 여는 임시 스크립트입니다(실행기는 레벨을 다시 열면 기록이 끊김).
- 일시정지 메뉴는 CommonUI 입력 동작으로 열려 키 주입이 닿지 않아, UI 레이아웃의 `MenuStack`에 `WBP_PauseMenu`를 올려 열었습니다.

## 2. 결과

- 빌드: `AgEditor Win64 Development` 성공. 빌드 뒤 `AgBattleResultScreen.cpp`는 포맷(람다 줄바꿈)만 바뀌었습니다.
- `WBP_BattleResult`: 컴파일 성공, 저장.
- 판정: 모두 통과.

| 완료 조건 | 결과 |
| - | - |
| 시뮬레이션 룸 처치 기록, 상대한 적 ID·배치 좌표, Stage Clear 결과창 표 | 통과. 절단자 `Location` (2064, 1048, 288) = 배치 자리 1 (2063.6, 1048.2, 200.25) + 캡슐 반높이 88. 결과창 도전 1, 0:07, 절단자 |
| 사망 기록, 쓰러뜨린 공격 포함, Game Over 결과창 표 | 통과. 낙하 시나리오: 낙하 대미지 502, 피격 2 = 움찔 1 + 쓰러뜨린 공격 1 (낙하 미포함), 기록 8초가 낙하 전부터 |
| 도전 횟수: 결과창 Restart +1, 일시정지 메뉴 Restart +1, 타이틀 뒤 1 | 통과. 1 → 2 (결과창 Restart), 일시정지 메뉴 Restart 뒤 2, 타이틀을 거쳐 다시 열면 1 |
| 보스 처치 순간 처치 기록, 다른 스테이지 결과창에 표 없음 | 통과. `LV_BossStage` Victory, 3초, 상대한 적 Boss. 표 `Collapsed` |
| 적이 놓쳐 비전투로 돌아가면 이탈 | 통과. 플레이어를 40m 위로 띄운 뒤 9초에 Disengage |
| 패리·극한 회피·피격 횟수, 가드·낙하 제외 | 통과. 회귀: 피격 2 (움찔 2), 가드 움찔 1은 미포함, 패리 1, 극한 회피 1. 결과창 값 2/1/1 |
| 일시정지 메뉴 시간 제외 | 통과. 메뉴 8초를 열어 둔 전투가 4초 (빼면 4.1~5.6초, 넣으면 12.1~13.6초 예상) |
| 전투 중 레벨을 떠난 전투는 저장 안 됨 | 통과. 일시정지 메뉴 Restart로 떠난 도전 1의 전투는 파일에 없음 |
| 실행마다 새 파일 | 통과. 테스트 창마다 `Saved/CombatStats/<실행 시각>.json`이 하나씩 생기고 그 실행의 기록이 쌓임 |

- 결과창 배치: 표가 접힌 보스 스테이지에서 Restart 버튼 위 테두리가 800×450 화면의 y 234px(기준 해상도 561.6px, 1픽셀 = 2.4px)로, 이전 고정 위치 560px과 같습니다.
- 회귀 시나리오의 패리 입력은 슬램이 몽타주 시작 약 1.2초(실제 시간) 뒤에 닿는 것에 맞춰 1.05초에 누릅니다. 0.85초에 눌렀을 때는 패리 구간(0.3초)이 끝난 뒤 맞아 가드가 되었고, 그때도 기록은 실제와 같이 패리 0이었습니다.
- 테스트 창의 준비 단계(`AgStopAI`)가 적의 StateTree를 멈추면 전투 중인 적 목록이 비어 이탈 기록이 하나 생깁니다. 치트가 만든 기록입니다.

- 전투 시간 밀리초 기록(검증 뒤 요청으로 변경): 다시 빌드한 뒤 회귀 시나리오 통과. 파일 `"Duration": 19.011`, 결과창 `0:19.011`. 위 표의 정수 초 값은 변경 전 실행의 기록입니다.

## 3. 회귀 확인

- 이번 변경은 결과 처리·적 AI·플레이어 입력 코드를 고치지 않았고(구독만 추가), 위 시나리오에서 샌드백 공격, 가드 움찔, 패리, 극한 회피, 보스 처치 슬로우모션 뒤 결과창이 그대로 동작했습니다.
- 확인하지 않은 것: 던전에서 보스가 죽을 때 다른 일반 적이 전투 중인 경우(같은 Stage Clear 경로를 보스 스테이지에서 확인), 패키지 빌드의 저장 경로.
