# 카메라 대상 비추기 검증 결과

## 1. 테스트 시나리오

- 페이즈 전환은 `AgTargetHP 40` 뒤 보스 AI를 켜서 일으켰습니다. 테스트 창은 `Scripts/ScenarioTest/run.py`로 띄웠고, 시나리오는 임시 폴더에 두었습니다(저장소에 두지 않음).
- 화면은 카메라 매니저의 최종 시점(모디파이어 적용 뒤)과 보스의 락온 지점(`spine_05`) 사이의 거리와, 시점의 정면과 락온 지점 방향 사이의 각도로 쟀습니다. 게임 카메라의 방향은 컨트롤 회전으로 쟀습니다.
- 공유 에디터를 다른 작업이 쓰는 동안에는 임시 사본에서 빌드하고 테스트 창을 띄웠고, 마지막에 작업 트리를 빌드해 다시 확인했습니다.

## 2. 결과 (작업 트리 빌드)

- 빌드: `AgEditor Win64 Development` 성공, `UnrealEditor-Ag.dll`에 `AgLookAtCameraModifier` 포함 확인
- 몽타주 `AM_Boss_PhaseTransition`: `Camera` 트랙 0.0001 ~ 2.0초에 `AgAnimNotifyState_CameraLookAt`(구조체 기본값 400cm / 0.5초 / 0.6초, `Radius` 4000), `CameraShake` 트랙 0.0001초에 줌인 `AgAnimNotify_PlayCameraEffect`(시야각 -12 / 0.5 / 0.08 / 0.6, 반경 1500 / 4000). 스테이징되지 않음.
- 판정: 아래 시나리오 모두 통과

| 시나리오 | 판정 | 확인한 값 |
| - | - | - |
| 보스 쪽 당기기: 등진 채 전환 (8m) | 통과 | 포효 전 보스가 화면 가운데에서 141°. 0.42초 438cm·1.2°, 0.7~1.95초 400cm·최대 0.30°. 게임 카메라 방향은 1.0~1.6초 보스와 최대 0.49°(마우스 입력 중), 포효 끝 0.19°. 포효 끝 0.65초 뒤 1194cm로 돌아옴, 그 뒤 마우스로 20.1° 돎 |
| 보스 쪽 당기기: 락온 중 전환 | 통과 | 포효 전 락온 구도에서 가운데에서 10.0°. 0.6~1.95초 400cm·최대 0.61°. 포효 끝 0.65초 뒤 1194cm로 돌아옴. 3초 동안 락온 유지 |
| 비추는 도중 락온 (포효 0.8초) | 통과 | 락온 키 전에는 락온 아님, 4초까지 락온 유지, 포효 중 게임 카메라 방향과 보스 최대 0.36°, 락온 키 앞뒤 프레임 사이 최대 회전 0.55° |
| 포효 시작 줌인: 락온 중 전환 | 통과 | 시야각 90.0° → 0.52초 78.0° → 1.25~1.76초 100.0° → 2.51초 90.0° |

- 느린 화면 캡처(슬로모션 0.1): 포효 전에는 반대쪽을 보다가, 0.6초에 보스 쪽으로 당겨져 보스가 화면 가운데를 크게 채우고, 2.3초부터 돌아와 2.7초에는 보스를 본 게임 카메라가 됩니다.

## 4. 판정 수정 기록

실패한 실행은 모두 기록을 본 뒤 판정을 고쳐 다시 실행했습니다.

- 등진 채 당기기: '포효 전 카메라와 보스 900cm 넘음'을 보다가 457cm로 실패. 등지면 게임 카메라가 플레이어보다 보스 쪽에 있으므로, 포효 전에는 보스가 화면 가운데에서 벗어난 각도를 보도록 고침.
- 락온 중 당기기: '보스가 가운데에서 1° 이하'를 보다가 1.04°로 실패. 기합(0.58초) 직후 0.2초 동안 가슴 뼈가 빠르게 움직여 카메라가 한 프레임 늦게 따라간 차(0.81 → 1.04 → 0.48 → 0.0°)이므로 1.5°로 고침.
- 락온 시나리오들: 포효가 끝난 뒤 보스가 다음 패턴으로 움직여 락온 스무딩으로 3° 안팎 늦는 구간까지 보다가 실패. 포효 동안만 보도록 고침.
- 비추는 도중 락온: 처음 도는 동안 긴 프레임(0.03초)에 10.6°씩 도는 락온 최대 회전 속도(초당 360°)를 튐으로 판정해 실패. 락온 키 앞뒤만 보도록 고침.
