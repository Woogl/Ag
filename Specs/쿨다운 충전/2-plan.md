# 쿨다운 충전 기술 설계 (Plan)

## 1. 영향 범위 및 아키텍처

[캐릭터 기반 구조와 GAS](<../../Docs/Architecture/캐릭터 기반 구조와 GAS.md>) '쿨다운'의 규약(쿨다운 효과 하나, 출처로 어빌리티 구분)을 그대로 씁니다. 새 클래스, 태그, 효과, Task는 없습니다.

| 대상 | 변경 |
| - | - |
| `FAgAbilityData` | `int32 MaxCharges = 1`을 `Cooldown` 다음에 더합니다. JSON에는 1이 아닐 때만 적습니다. |
| `UAgGameplayAbility::CheckCooldown` | 이 어빌리티를 출처로 걸린 쿨다운 효과의 수가 `MaxCharges`보다 적으면 통과합니다. 지금은 0개일 때만 통과합니다. |
| `UAgGameplayAbility::ApplyCooldown` | 새 쿨다운 효과의 지속 시간을 (걸린 쿨다운 효과 중 가장 긴 남은 시간) + `Cooldown`으로 겁니다. 걸린 효과가 없으면 지금처럼 `Cooldown`입니다. |
| `UAgGameplayAbility::GetCooldownTimeRemainingAndDuration` | 걸린 효과 수가 `MaxCharges`보다 적으면(충전이 남음) 0을 돌려줍니다. 아니면 가장 먼저 끝나는 효과의 남은 시간과 `Cooldown`을 돌려줍니다. |

- HUD·적 AI·입력 계층·치트는 고치지 않습니다. 모두 `CanActivateAbility`(→ `CheckCooldown`)와 `GetCooldownTimeRemainingAndDuration`으로 쿨다운을 보고, `AgPattern`의 쿨다운 지우기는 `Effect.Cooldown` 효과를 모두 지워 충전이 최대가 됩니다.

## 2. 충전을 세는 방법

- 남은 충전 = `MaxCharges` − 이 어빌리티를 출처로 걸린 쿨다운 효과 수.
- 새 효과는 마지막 효과가 끝나는 때로부터 `Cooldown` 뒤에 끝나므로, 효과들이 `Cooldown` 간격으로 줄지어 하나씩 끝납니다. 그래서 한 번에 하나씩 충전되고, 쓰는 순간 흐르던 쿨다운이 다시 시작하지 않습니다(Spec 2의 예와 같음).
- 가장 먼저 끝나는 효과의 남은 시간은 늘 `Cooldown` 이하이고, 이것이 다음 충전까지의 시간입니다.
- `MaxCharges` 1이면 걸린 효과가 없을 때만 발동하고 효과 지속 시간이 `Cooldown`이므로 지금 동작과 같습니다.
- 모든 쿨다운 효과는 같은 ASC의 게임 시간 타이머로 흘러, 일시정지·슬로우모션·궁극기 시간 정지에서 줄의 간격이 어긋나지 않습니다.

### 쓰지 않은 방법

- 엔진 GE 스택(스택 상한 = 충전, 만료 때 한 스택씩 빼고 시간 갱신): 상한이 GE 정의의 값이라 어빌리티마다 쿨다운 GE를 따로 만들어야 하고, 실행 중에 만든 GE의 스택 방식을 정하는 함수는 에디터 전용입니다.
- 어빌리티 인스턴스에 충전 수와 타이머를 두기: 쿨다운이 효과와 별도 상태 두 곳으로 나뉘어 치트의 쿨다운 지우기, 남은 시간 조회를 따로 맞춰야 합니다.

## 3. 데이터

| - | - |
| `MaxCharges` | 최대 충전 횟수(기본 1). `Cooldown`이 0이면 쓰지 않습니다. |

## 5. 검증

- 시나리오 창으로 확인합니다. 창은 디스크의 JSON을 읽으므로, 실행 동안만 `Abilities.json`의 `Skill`에 `"MaxCharges": 3`과 `"Cooldown": 5`를 적고 끝나면 되돌립니다(테스트용 데이터 수정이라 사람의 확인을 받습니다).
- MP는 `AgFillMPUP`으로 사용 전마다 채웁니다. 판정은 기록 행의 스킬 몽타주 시작 시각과 HUD 스킬 슬롯 쿨다운 위젯의 표시 여부로 합니다.
- 회귀: 값을 되돌린 뒤 스킬 3초 쿨다운과 보스 패턴 하나의 쿨다운을 확인합니다.
