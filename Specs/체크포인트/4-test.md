# 체크포인트 검증 결과

## 1. 테스트 시나리오

- 시나리오 실행 명령: `python -I Scripts/ScenarioTest/run.py <시나리오.py> --map "/Game/Maps/LV_FortressBreach"`
- 새 시나리오(`Saved/ScenarioTest/Scenarios`)
  - `checkpoint_rest.py`: 체크포인트를 소환해 안내, 닿기만 한 경우, 휴식, 두 번째 휴식을 확인합니다.
  - `checkpoint_rest_combat.py`: 경비 사수의 탄환이 날아오고 락온한 채로, 그리고 보스가 패턴을 쓰는 중에 휴식합니다.
- 체크포인트는 레벨에 놓지 않았고(자리는 레벨 기획서에서 정함), 테스트 창에서 `BP_Checkpoint`를 소환했습니다.

- 판정: 두 시나리오 모두 통과.

**미리 읽기**

- 패키지 빌드 로그에서 레벨을 연 프레임 뒤부터 적이 모두 생성될 때까지 `FlushAsyncLoading` 줄이 없습니다(첫 진입과 Restart 각 5회). 엔진은 게임 스레드가 패키지를 그 자리에서 읽으면 프레임마다 첫 번째를 이 줄로 남기므로, 적을 생성하는 동안 그 자리에서 읽은 패키지가 없습니다.
- 이미 메모리에 있는 에셋을 요청해도 엔진은 완료 콜백을 다음 프레임에 부릅니다(`s.StreamableDelegateDelayFrames` 기본 1). 그래서 처음 생성은 항상 두 프레임 이상 걸리고, Restart에서도 로딩 화면이 뜹니다. 휴식할 때는 스포너가 에셋을 붙잡고 있어 요청하지 않고 같은 프레임에 생성합니다.

**에디터**

- `LV_FortressBreach`의 적 14명(보스 포함)을 같은 자리·방향·그룹의 스포너로 바꿨습니다. 정찰 경로를 가진 적은 없었습니다.
- 변환 뒤 맵 검사: 오류 0, 경고 0. 스포너마다 미리 보기 메시 컴포넌트에 적의 메시가 들어 있습니다.

**로딩 시간 Before/After** (2-plan 6장의 조건, 5회, 최소 / 중앙 / 최대, 초)

| 경우 | 값 | Before | After |
| - | - | - | - |
| 첫 진입 | 멈춘 시간 (`LoadMap`) | 0.083 / 0.089 / 0.450 | 0.062 / 0.073 / 0.078 |
| 첫 진입 | 조작할 수 있을 때까지 | 0.083 / 0.089 / 0.450 | 0.199 / 0.248 / 0.367 |
| 첫 진입 | 가장 긴 프레임 | 0.115 / 0.117 / 0.607 | 0.073 / 0.098 / 0.149 |
| Restart | 멈춘 시간 (`LoadMap`) | 0.138 / 0.149 / 0.229 | 0.077 / 0.086 / 0.103 |
| Restart | 조작할 수 있을 때까지 | 0.138 / 0.149 / 0.229 | 0.122 / 0.163 / 0.176 |
| Restart | 가장 긴 프레임 | 0.168 / 0.189 / 0.267 | 0.098 / 0.107 / 0.132 |

- 로딩 화면은 첫 진입에서 4~5프레임, Restart에서 2프레임 떠 있었습니다.
- 멈춘 시간과 가장 긴 프레임은 줄었고, 첫 진입에서 조작할 수 있을 때까지는 0.16초 늘었습니다. 모두 0.2초 안쪽의 차이라 지금 콘텐츠에서 체감되는 개선은 아닙니다.
- Before의 에셋 읽기가 0.03초쯤이라 비동기로 옮길 몫이 작았습니다. 남은 비용은 적 14명을 한 프레임에 생성하고 초기화하는 0.05~0.07초로, 게임 스레드의 일이라 로딩 화면 뒤의 프레임으로 자리만 옮겨졌습니다.
- 휴식 프레임: 테스트 창(에디터 빌드)에서 적 14명을 지우고 생성한 프레임이 0.044초와 0.050초였습니다. 패키지 빌드에서는 재지 않았습니다.
- After는 로딩 화면 이름을 바꾸기 전의 패키지로 쟀습니다. 이름만 바뀌었습니다.

**확인하지 못한 것**

- 로딩 화면이 떠 있는 동안의 조작과 Esc: 코드(메뉴 입력 모드, HUD의 뒤로 액션은 게임 입력 모드에서만 받음)로만 확인했습니다.
- 에디터 뷰포트에서 스포너의 적 외형, 시야, 정찰 경로 미리 보기가 그려지는 모습: 컴포넌트와 값만 확인했고 화면은 보지 못했습니다.
- 정찰 경로가 있는 스포너: 레벨에 정찰 경로가 없어 실행해 보지 못했습니다.
- 스포너의 소프트 참조만으로 적 블루프린트가 쿡되는지: 패키지에서 적 14명이 생성됐지만, 시뮬레이션 룸 게임 모드가 같은 블루프린트를 하드 참조하고 있어 따로 떼어 확인하지 못했습니다.
- PIE에서는 실행하지 않았습니다.
