# 몽타주 Notify 전환 작업 목록

상태: 설계안 작성 완료, 구현 미착수. 체크되지 않은 항목은 수행하지 않았습니다.

## 1. 설계 검토

- [x] 현재 타임라인·Task·데이터 로딩과 UE 5.8 Notify 소스 확인.
- [x] 작업 명세와 기술 설계 작성.
- [ ] 프로그래머가 타이밍 정본 예외, 데이터 형식, 실행 연결부와 이관 순서 승인.

## 2. 최소 연결부와 대표 동작

- [ ] 구현 시점의 작업 트리·에셋·JSON을 다시 확인하고 기존 변경과 이관 범위 구분.
- [ ] `UAgMontageTaskData`, 항목 ID 맵, AssetManager 읽기·재로딩과 시간 필드 분리 준비.
- [ ] C++ 단발 Notify와 NotifyState 추가. 미리 보기 억제, TaskId, 인스턴스 컨텍스트, State 병합 방지 설정.
- [ ] ASC 재생 라우팅과 PlayMontage의 실행 사본·활성 Task 수명 연결.
- [ ] 기존 MakeTask 경로 재사용. RootMotion에 에셋 구간 전달.
- [ ] 대표 몽타주에서 이전 타임라인과 새 Notify 경로를 배타적으로 실행하도록 준비.
- [ ] C++ 빌드 및 에셋 로드 확인. 에디터 조작 전에 프로젝트 에디터 작업 스킬 확인.

## 3. 전체 이관 전 필수 검증

실행 전에 사용자에게 무엇을, 창 몇 개로, 얼마나 확인할지 확인받습니다. 테스트용 데이터 변경이 필요하면 별도로 확인받습니다. 검증 기록은 실행 단계에서 `4-test.md`에 작성합니다. 임시 시나리오·확인 코드는 저장소에 추가하지 않습니다.

| 시나리오 | 통과 조건 |
| - | - |
| 기본 공격 1타, 짧은 판정 구간 | 의도한 타격·보상, 구간 밖 피해와 중복 없음 |
| 회피 시작 프레임·무적 종료 | 최초 판정 전 무적 적용, 종료 후 무적 잔류 없음 |
| 동시 시작·끝 | 필수 Task 누락 없음, 트랙 순서 변경에 따른 결과 변화 없음 |
| 저 FPS·프레임 지연 | 짧은 구간의 Begin/End·스윕 수명 확인, 누락·범위 확대를 기록 없이 허용하지 않음 |
| 보스 돌진 Hold 반복 | Dash·판정·통과 효과 유지, 한 타의 적중 기록 유지, Recover 진입 시 정리 |
| 점프 공격 착지 전환 | Start/Fall/Land 간 구간 유지·종료, 착지 이벤트 누락 없음 |
| 구간 안팎 점프 | 도착점 상태 일치, 건너뛴 단발 실행 없음, 대기 Queued 통지의 잘못된 실행 없음 |
| 궁극기·컷신·시간 정지 | Sequencer 재생과 혼동 없음, 시간 정지 해제와 마무리·슬로우모션 정상 |
| 피격·사망·강제 취소·같은 몽타주 재시작 | 구 재생 콜백이 신 재생을 건드리지 않음, 효과·판정·소스·구독 정리 |
| 동일 에셋의 동시 재생 | 캐릭터별·재생별 Task와 적중 기록 분리 |
| 정상 블렌드 아웃·히트스톱·배율 변경 | 활성 구간의 의도한 수명과 시간 기준 유지 |

- [ ] 위 시나리오를 30/60/120 FPS와 지연 조건에서 필요한 조합으로 확인.
- [ ] 실패한 경계 사례가 있으면 `2-plan.md`의 실행 방식과 보완 연결부를 수정하고 재검토. 전체 이관 보류.
- [ ] 대표 검증 통과 결과 기록. 기존 판정기를 제거할 수 있는지 확인.

- [ ] 전체 빌드·쿡·패키지 로딩 확인, 주요 행동 회귀 기록.
- [ ] 실행 창 종료, 임시 변환·확인 파일 정리, 임시 설정 복원.
