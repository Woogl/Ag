# 몽타주 Notify 전환 작업 명세

상태: 설계 검토안. 구현과 에셋 이관 전입니다.

## 1. 목적과 범위

몽타주의 게임플레이 실행 시점과 구간을 엔진 AnimNotify·AnimNotifyState로 관리합니다. 모션을 보며 타이밍을 편집하고, 프로젝트의 매 프레임 타임라인 판정기를 제거하는 것이 목적입니다.

기획 값은 JSON, 실행 로직은 C++, 모션에 붙는 시각과 구간은 몽타주 에셋을 정본으로 삼는 정책 변경을 제안합니다. 타이밍을 JSON과 에셋 양쪽에서 편집하거나 상시 동기화하지 않습니다.

현재 작업 트리 기준으로 `MontageTimelines.json`에는 21개 몽타주의 118개 항목이 있습니다. 구현을 시작할 때 다시 집계하고, 그 시점의 데이터와 에셋을 이관 기준으로 삼습니다.

## 2. 플레이 규칙과 수치

이번 작업은 전투 규칙과 밸런스를 바꾸지 않습니다. 피해·적중 보상·가드 가능 여부·무적·Busy·이동·추적·입력 전환·시간 연출·카메라 셰이크의 값과 의도를 유지합니다. 이관을 위해 모션 길이, 섹션 연결, 기존 연출을 임의로 변경하지 않습니다.

적용 기준은 다음 정본의 관련 절입니다.

- [전투 시스템](<../../Docs/Design/System/전투 시스템.md>): 공격 판정 세부 규칙, 공격 중 위치·회전 보정, 사망 처리.
- [플레이어 시스템](<../../Docs/Design/System/플레이어 시스템.md>): 선입력과 모션 캔슬.
- [시간 규칙](<../../Docs/Design/System/시간 규칙.md>): 모션 진행을 따르는 구간, 히트스톱과 궁극기 시간 정지.
- [현재 타임라인 규약](<../../Docs/Architecture/몽타주 타임라인과 구간 판정.md>): 재생 시작, 섹션 이동, 반복, 재생 교체, 종료 시 처리.

전환 후에도 다음 동작을 충족해야 합니다.

1. 한 공격 구간은 대상마다 한 번만 적중하고, 섹션 안의 반복이나 구간 안으로의 이동으로 적중 기록을 초기화하지 않습니다.
2. 섹션 이동으로 건너뛴 공격·투사체·효과는 실행하지 않습니다. 도착 위치에 이미 걸쳐 있는 구간은 활성화합니다.
3. 재생 시작 위치의 무적·Busy·시간 정지 등은 최초 판정에 필요한 시점부터 적용되어야 합니다. 첫 Notify 지연으로 취약한 틈을 만들지 않습니다.
4. 같은 재생의 섹션 이동은 필요한 구간을 유지하고, 새 재생은 이전 구간을 종료합니다.
5. 피격·사망·다른 몽타주·어빌리티 취소 시 판정, 효과, 루트 모션 소스, 워핑 목표, 이벤트 구독을 정리합니다. 이미 생성되어 독립적으로 움직이는 투사체는 기존 규칙을 따릅니다.
6. 히트스톱·배율·반복 중 모션 구간은 모션 진행을 따릅니다. 쿨다운·효과 지속 시간 등의 시간 기준은 기존 규칙을 따릅니다.
7. 동일 몽타주를 쓰는 어빌리티는 같은 몽타주 Task 값을 사용합니다.
8. JSON 재로딩은 다음 몽타주 재생부터 Task 값에 반영합니다. 같은 재생의 섹션 이동은 기존 사본을 사용합니다.

엔진 Notify의 프레임 내 전달 순서가 기존 판정기와 같다고 가정하지 않습니다. 순서 차이로 위 플레이 규칙이 깨지면 이관 완료로 인정하지 않으며, 기술 설계를 수정합니다. 이번 명세로 새로운 판정 오차나 한 프레임의 무적 누락을 허용하지 않습니다.

## 3. 완료 조건

- [ ] 모든 기존 항목의 타이밍은 몽타주에, Task 값은 새 JSON에 한 번씩만 존재합니다.
- [ ] C++ Notify로 기존 Task를 실행하며 BP 이벤트 그래프·Construction Script를 추가하지 않습니다.
- [ ] `PlayMontage`의 매 프레임 위치 비교, 구간 경계 수집·정렬, 타임라인 평가 코드를 제거합니다.
- [ ] 일반 공격, 회피, 보스 돌진, 점프 공격, 궁극기에서 위 플레이 규칙을 충족합니다.
- [ ] 0초·짧은 구간·동시 항목·반복·구간 안팎 섹션 이동·재생 교체를 검증합니다.
- [ ] 30/60/120 FPS 및 인위적 프레임 지연에서 피해·보상 중복, 효과 잔류, 이동 잔류가 없습니다.
- [ ] 두 캐릭터가 같은 몽타주를 동시에 재생해도 실행 상태가 섞이지 않습니다.
- [ ] JSON 재로딩, 에셋 ID 참조 검사, 쿡 및 패키지 로딩을 확인합니다.
- [ ] 승인된 최종 구조를 정본 문서와 규칙에 반영한 뒤 작업 폴더를 정리합니다.

## 4. 이번 범위에서 유지하는 것

단일 `UAgGameplayAbility`, 범용 AbilityTask 구성, GAS 효과, 무기 판정 방식, 네이티브 태그 정책을 유지합니다. Motion Warping의 동적 Modifier 등록도 유지합니다. 네트워크 대응, 새로운 전투 기능, 범용 타임라인 편집기나 JSON↔에셋 동기화 도구는 만들지 않습니다.
