# 어빌리티 데이터 구조 작업 명세 (Spec)

## 1. 개요 및 목적

- AI가 어빌리티 하나를 `Abilities.json`의 항목 하나만 읽고 파악하게 합니다. 지금은 어빌리티 정의, 캐릭터의 몽타주 ID별 에셋(`Characters.json`의 `Montages`), 몽타주 타임라인(`MontageTimelines.json`)을 차례로 건너야 어빌리티 하나가 다 보입니다.
- 있는 Task·이벤트·키를 조합한 어빌리티는 C++를 고치지 않고 데이터만으로 더하게 합니다. 지금은 키로 발동하는 플레이어 행동마다 입력 계층과 HUD 코드를 고쳐야 합니다.

## 2. 플레이 규칙 및 수치

플레이 규칙과 수치는 바꾸지 않습니다. 모든 행동·피격 반응·패턴은 지금과 같은 조건으로 발동하고, 같은 모션·판정·수치로 동작합니다. 바뀌는 것은 기획 데이터의 형식과 구현 문서이며, 기획서는 아래 하나만 바로잡습니다.

- 극한 회피 구간은 무적 구간처럼 모션 시간을 따릅니다. [시간 규칙](<../../Docs/Design/System/시간 규칙.md>) '시간 연출의 영향' 표에서 극한 회피 구간을 '모션을 따르는' 줄로 옮깁니다. 지금 게임에서 달라지는 장면은 없습니다. 회피 몽타주의 재생 배율은 1이고, 회피 첫 0.2초는 무적이라 히트스톱이 생기지 않습니다.

작업 뒤 데이터만으로 더할 수 있는 것과 C++가 필요한 것은 다음과 같습니다.

| 구분 | 범위 |
| - | - |
| 데이터만으로 더함 | 적 패턴, 이미 있는 이벤트로 발동하는 반응·패시브, 이미 있는 키에 묶이는 플레이어 행동(발동 조건으로 구분), 캐릭터마다 다른 모션(어빌리티를 복제). 새 모션이면 몽타주 에셋은 만듭니다. |
| C++가 필요함 | 새 키, 새 이벤트(예: 적중했을 때 공격자에게 가는 이벤트), 새 Task 기능, 새 카메라 상황, 충전식 쿨다운, 새 취소·차단 관계에 쓰는 태그 |

## 3. 완료 조건 (Acceptance Criteria)

- [x] 어빌리티 항목 하나에 태그, 입력, 발동 조건, 비용, 쿨다운, 대상, Task, 몽타주, 타임라인이 모두 있습니다. `MontageTimelines.json`과 캐릭터의 `Montages`는 없습니다.
- [x] 키로 발동하는 플레이어 행동은 어빌리티의 입력 태그로 연결되고, HUD의 스킬·궁극기 칸도 입력 태그로 어빌리티를 찾습니다.
- [x] 기본 공격의 5타 콤보와 5타 뒤 1타, 가드 반격 뒤 2타부터 시작하는 콤보가 지금과 같습니다.
- [x] 점프, 점프 공격, 착지가 지금과 같습니다.
- [x] 회피(이동 입력이 있을 때와 없을 때), 후딜 중 다시 회피, 회피 후딜에서 이어지는 달리기가 지금과 같습니다.
- [x] 극한 회피의 네 방향과 입력 없음, 그 보상·회피 반격 기회·슬로우모션, 회피 반격이 지금과 같습니다.
- [x] 가드 유지와 해제, 다른 행동이 끝날 때 누르고 있던 가드, 패리와 가드 자세 복귀, 가드 밀림, 가드 브레이크, 가드 반격이 지금과 같습니다.
- [x] 스킬·궁극기의 비용·쿨다운과 HUD 표시, 처형과 처형 카메라, 락온이 지금과 같습니다.
- [x] 움찔(부위 다섯, 공중), 넉업(지상·공중), 저글, 넉다운이 지금과 같습니다.
- [x] 그로기(움찔 중·넉다운 중에 시작하는 경우, 비전투 중에 PP가 0이 되는 경우 포함), 처형 피격과 사망 모션, 페이즈 전환이 지금과 같습니다.
- [x] 보스·절단자·경비 사수·공격 샌드백의 패턴이 지금과 같습니다.
- [x] 에디터에서 JSON을 고치면 다음 발동부터 새 값을 씁니다.
- [x] 있는 Task로 만든 새 어빌리티 하나를 JSON만 고쳐 더하고 발동되는 것을 확인합니다. 확인용 데이터는 확인 뒤 되돌립니다.
