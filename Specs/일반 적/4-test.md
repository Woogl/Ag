# 일반 적 검증 결과

## 1. 테스트 시나리오

- 시나리오 실행 명령: `python -I Scripts/ScenarioTest/run.py <시나리오.py>` (시나리오는 임시 파일이라 저장소에 두지 않습니다)
- 범위: 보스(커스터)로 확인할 수 있는 완료 조건과 회귀. 보스에 해당하지 않는 완료 조건은 아래 '일반 적 작업에서 확인할 항목'에 둡니다.
- 위치 기준: 보스의 처음 자리 (2590, 1800), 처음 방향 -X(아레나 중심 쪽). 플레이어는 처음 자리에서 그 거리·각도에 두고 보스를 바라보게 합니다.
- 비전투 시작: 준비가 보스 AI를 멈춘 뒤 플레이어를 보스 뒤로 옮기고, 놓친 지 5초가 지난 뒤 AI를 다시 켭니다. 트리가 비전투에서 시작하므로 보스가 아직 전투에 들어가지 않은 상태가 됩니다.

| 시나리오 | 통과 조건 |
| - | - |
| T1 보스전 시작 (AI 켬, 플레이어 시작 지점) | 1.5초에 보스가 전투 중(`State.NonCombat` 없음)이고 HUD의 보스 상태(`BossStatusPanel`)가 보임. 0 ~ 5초에 보스 공격 패턴 몽타주가 하나 이상 재생됨 |
| T2 커스터 시야 | 보스를 처음 자리·방향에 두고 시작. 뒤쪽 7m, 정면 21m, 15m·70°에서는 각각 2초 뒤에도 비전투이고 시야 감각에 플레이어가 없음. 19m·50°에 두면 1초 안에 전투에 들어가고, 그 뒤 4.4초 안에 공격 패턴 몽타주가 재생됨 |
| T2b 벽에 가린 플레이어 (AI 끔, 시야 감각만) | 보스를 서쪽 벽 앞(600, 900)에 두고 입구 통로(-600, 1750)의 플레이어를 바라보게 하면(14.7m, 정면) 2.7초 뒤에도 시야 감각에 플레이어가 없음. 플레이어를 경기장 안(300, 1750, 9m, 약 35°)으로 옮기면 1.4초 안에 보임 |
| T3 시야 밖 피격 | 비전투 보스의 뒤 1.5m에서 기본 공격을 하면 1.5초 안에 전투에 들어가고 보스 HP가 줄어듦 |
| T4 보스는 놓쳐도 계속 전투 (AI 켬) | 창 메모리에서 보스 걷기 속도를 0, 시야 거리를 50cm로 줄이고 플레이어를 12m에 둠. 3초에 시야 감각에 플레이어가 없고, 11초(놓친 지 5초 이상)에도 보스가 전투 중이고 HUD 보스 상태가 보임 |
| T5 다가가기·페이즈 전환·패턴 (AI 켬) | 플레이어를 정면 15m에 두면 4초 안에 보스와의 거리가 3m 이상 줄어듦(길찾기로 다가감). 5초에 보스 HP를 40%로 하면 12초까지 `AM_Boss_PhaseTransition`이 재생되고, 16초까지 그 뒤에 공격 패턴 몽타주가 재생됨 |
| T5b 길찾기로 걸어서 다가감 (AI 켬) | 플레이어를 15m에 두어 0 ~ 5초에 DashThrust를 쓰게 한 뒤, 5초에 다시 15m에 두면(DashThrust 쿨다운 10초, 다른 패턴은 사거리 밖) 5 ~ 9초에 공격 패턴 없이 거리가 3m 이상 줄어듦 |
| T6 플레이어 사망 (AI 켬) | 3초에 플레이어를 죽이면 4초부터 8초까지 보스가 비전투이고, 방향이 1° 넘게 바뀌지 않고, 위치가 20cm 넘게 움직이지 않으며, 8초에 몽타주가 없음 |
| T7 그로기·처형 (AI 끔) | 보스 PP를 1로 두고 기본 공격으로 그로기를 만든 뒤(공격 모션이 끝난 4초에) 처형하면 `AM_Boss_Executed`가 재생되고, 끝난 뒤 보스 PP가 최대 |

## 2. 결과

- 빌드: `AgEditor Win64 Development` 성공. 에디터 시작 로그에 `LogAg` 오류 없음(데이터 읽기 성공).
- 판정: T1, T2, T2b, T3, T4, T5, T5b, T6, T7 모두 통과.

| 시나리오 | 결과 |
| - | - |
| T1 | 1.5초에 전투 중, 보스 상태 `SelfHitTestInvisible`(보임), JumpCleave·DashThrust 재생 |
| T2 | 뒤쪽 7m·정면 21m·15m 70°에서 비전투이고 안 보임, 19m 50°에서 전투 진입, 그 뒤 DashThrust 재생 |
| T2b | 입구 통로(벽 뒤 14.7m 정면)에서 안 보임, 경기장 안으로 옮기자 보임 |
| T3 | 뒤 1.5m 기본 공격으로 전투 진입, 보스 HP 3000 → 2900 |
| T4 | 시야에서 놓친 뒤 11초까지 계속 전투, 보스 상태 보임 |
| T5 | 15m → 2.1m로 다가감(DashThrust), HP 40%에서 PhaseTransition 뒤 QuintupleStrike(2페이즈 패턴) |
| T5b | DashThrust 쿨다운 중 패턴 없이 길찾기로 15m → 9.8m 걸어서 다가감 |
| T6 | 플레이어 사망 뒤 4 ~ 8초 비전투, 방향 변화 0.0°, 이동 0cm, 몽타주 없음 |
| T7 | 그로기 → 처형 피격 재생 → PP 1500/1500 |

- 로그: 테스트 창 로그의 `LogAg: Error` 0건. T7에서 AI를 끈 동안 기본 공격 이벤트를 받은 `SendStateTreeEvent ... not started yet` 경고는 테스트 조건(StateTree 정지) 때문입니다.
- 처음 시도에서 실패한 것은 모두 판정 코드 문제였습니다(테스트 창의 위젯 트리 이름, 파이썬에서 못 읽는 속성, 준비 중 움직인 보스를 기준으로 한 위치, 공격 모션 중에 누른 처형 키). 기록을 보고 시나리오를 고쳤고 통과 조건은 바꾸지 않았습니다.
- 첫 전투의 쿨다운: 시작할 때 쿨다운 효과가 없고 패턴을 시작할 때만 걸린다는 것을 코드로 확인했습니다(1절 '지금 코드에서 확인한 것', 2-plan). 테스트 준비 중에 보스가 이미 패턴을 써서 창에서는 따로 보지 않았습니다.

## 3. 회귀 확인

- 확인한 기존 기능과 결과: 보스 패턴 선택과 후딜레이(T1·T2·T5), 페이즈 전환과 2페이즈 패턴(T5), 그로기·처형 피격과 PP 회복(T7), 플레이어 사망 뒤 보스 대기(T6), 플레이어의 기본 공격 적중(T3), 보스 공격의 플레이어 적중(넉업·넉다운, 모든 시나리오) 모두 정상입니다.
- 실행하지 않은 것: 보스 사망과 스테이지 결과(사망 처리와 게임 모드 코드는 바꾸지 않았고, 사망한 캐릭터를 지우는 코드가 없음을 코드로 확인), 시작 화면에서 들어가는 흐름(테스트 창은 보스 스테이지를 바로 엶).

## 일반 적 작업에서 확인할 항목

보스는 비전투로 돌아가지 않고 보스 전장에는 정찰 지점이 없어, 아래 완료 조건은 일반 적 캐릭터를 만드는 작업에서 확인합니다.

- 시야에서 놓친 지 5초가 지나면 가장 가까운 정찰 지점으로 걸어가 정찰을 이어 감, 정찰 지점이 없으면 처음 자리로 돌아가 처음 방향으로 돌아서 대기
- 놓친 지 5초가 지나기 전에 다시 보이면 전투를 이어 감
- 정찰 지점을 순서대로 돌고 마지막에서 첫 지점으로, 걷는 속도로
- 비전투로 돌아갔다가 다시 전투에 들어오면 HP·PP가 그대로이고 쿨다운이 이어서 흐름
- 샌드백 관련 동작은 샌드백 작업에서 확인합니다.
