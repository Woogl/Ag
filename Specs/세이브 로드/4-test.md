# 세이브&로드 검증 결과

## 1. 테스트 시나리오

검증은 저장소를 건드리지 않는 임시 사본(소스·설정·데이터 복사, 고칠 콘텐츠 폴더만 복사하고 나머지는 연결)에서 했습니다. 사본에서 빌드하고, 사본의 에디터로 위젯 블루프린트를 만들고, 사본의 테스트 창(`-game`)을 타이틀 화면(`/Game/Maps/LV_FrontEnd`)에서 띄워 단계마다 원격 실행으로 조작하고 읽었습니다. 저장 파일은 사본의 `Saved/SaveGames`에만 생겼습니다.

- 메뉴 버튼은 CommonUI 버튼의 클릭 알림으로, 방향키·Enter·Esc는 창에 보낸 키 메시지로, 게임 입력과 전제 상태(사망, 보스 처치, 아이템 수, AI 정지)는 확인용 입력과 테스트용 콘솔 명령으로 넣었습니다.
- 체크포인트가 놓인 레벨이 없어, 사본의 `LV_FortressBreach` 시작 지점 4m 앞에 `BP_Checkpoint`를 놓아 확인했습니다. 저장소의 레벨은 고치지 않았습니다.
- 회귀 시나리오 실행 명령: `python -I Scripts/ScenarioTest/run.py <시나리오.py>` (사본의 실행기, 시나리오는 `Saved/ScenarioTest/Scenarios`)

구현하면서 고친 것:

- 삭제 확인 창에서 방향키를 누르면 선택이 뒤의 Load Game 화면 Back 버튼으로 넘어가고 Enter가 그 버튼을 실행했습니다. 확인 창이 네 방향의 엔진 내비게이션 규칙을 Stop으로 두게 고쳤습니다.
- 슬롯을 다 지우고 타이틀로 돌아오면 접힌 Load Game 버튼에 포커스 복원이 걸려 아무 버튼도 선택되지 않았습니다. 엔진 설정 `CommonUI.FallbackToDesiredOnAutoRestoreFailure`를 켜, 복원에 실패하면 화면의 첫 포커스 대상으로 넘어가게 했습니다.
- 빈 슬롯 줄의 외곽선이 흐려지지 않았습니다(슬레이트가 둥근 박스의 외곽선 색에 렌더 불투명도를 곱하지 않음). 외곽선 색을 직접 흐리게 했습니다.

## 3. 회귀 확인

사본 빌드에서 기존 시나리오 11개를 돌려 모두 통과했습니다. 스테이지를 바로 여는 시나리오는 슬롯 없는 진행으로 돕니다.

- `item_potion`, `checkpoint_rest`, `checkpoint_rest_combat`, `interaction_gate`, `stage_boss_clear`, `player_combo`, `player_execution`, `player_skill`, `groggy`, `boss_patterns`, `combat_stats`
- `checkpoint_rest`와 `interaction_gate`는 처음에 실패했습니다. 두 시나리오가 시작 지점 근처에 체크포인트와 성문을 소환하는데, 검증용으로 사본에 놓은 체크포인트가 그 자리와 겹쳤기 때문입니다. 그 체크포인트를 사본에서 뺀 뒤 둘 다 통과했고, 변경 전 빌드에서도 통과합니다.

## 4. 작업 트리에서의 확인

사본에서 만든 위젯 블루프린트 7개를 작업 트리의 `Content/UI`로 복사하고, 공유 에디터를 닫은 뒤 작업 트리를 빌드해 다시 켰습니다.

- 빌드: 작업 트리에서 `AgEditor Win64 Development` 통과. 다시 켠 에디터에서 위젯 블루프린트 7개가 모두 컴파일되고 저장 안 된 에셋 없음.
- 작업 트리 빌드의 테스트 창(타이틀에서 시작): 저장이 없을 때 New Game·Settings·Quit와 New Game 선택 → New Game → 요새 돌파 시작 지점 (200, 570), 회복병 3 → 사망 → GAME OVER 문구에 버튼 숨김 → 시작 지점에서 다시 시작 → Return to Title → Continue 선택, Load Game 화면에 Slot 1 'Fortress Breach'. `LogAg: Error` 0건.
- 이 확인으로 생긴 `Saved/SaveGames/Slot1.sav`는 지웠습니다.
