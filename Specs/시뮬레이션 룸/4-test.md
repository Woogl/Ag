# 시뮬레이션 룸 검증 결과

## 1. 테스트 시나리오

- 테스트 창 5회: `python -I Scripts/ScenarioTest/run.py --map "/Game/Maps/<맵>?Enemies=<구성>" <시나리오.py>`
  - 보스전 회귀 2회(`LV_BossStage`): 보스 처치(`AgKillBoss`), 플레이어 사망(`AgKillPlayer`) 뒤 보스 처치
  - 시뮬레이션 룸 3회: 커스터·절단자·경비 사수(적 AI 켬, 플레이어 무적, 일반 적 처치 뒤 보스 처치), 절단자+샌드백, 샌드백만(적 처치 뒤 플레이어 사망)
  - 적 선택 화면을 드롭다운으로 바꾸기 전(구성 옵션이 선택 순서이던 때)에 돌렸습니다. 바꾼 뒤 달라진 것은 구성 옵션의 형식과 자리 번호뿐이며, 배치는 아래 PIE에서 다시 확인했습니다.
- 에디터 PIE: `LV_SimulationRoom`을 주소 옵션 없이 열고, 에디터 파이썬으로 드롭다운을 고르고(`set_selected_option` 뒤 `on_selection_changed`를 마우스 선택으로 보냄) 버튼을 눌렀습니다(`InternalRootButtonBase.on_clicked`). 레벨이 열릴 때마다 첫 프레임의 배치를 기록했고, 사망은 콘솔 명령으로 일으켰으며, 화면은 `shot showui`로 찍었습니다. 타이틀의 입장 버튼은 스테이지 선택 Spec 작업이라, 다시 들어오기는 타이틀에서 주소 옵션 없는 `open /Game/Maps/LV_SimulationRoom`으로 대신했습니다.

- 화면 배치: 제목이 화면 위쪽 가운데, 그 아래 드롭다운 다섯 칸, 그 아래 Start·Return to Title. 처음에는 묶음을 세로 가운데에 두어 오른쪽 칸이 HUD 조작 안내와 겹쳤고, Spec대로 위쪽으로 옮겨 겹치지 않게 했습니다.
- 로그: 테스트 창과 PIE 모두 `LogAg` 오류·경고 없음. 위젯 에셋을 만드는 도중의 바인딩 컴파일 오류는 마지막 컴파일에서 없어짐.
- 확인하지 못한 것: 드롭다운 목록을 실제 마우스·키보드로 여는 동작과 열린 목록의 모양(파이썬으로 열 수 없음), 방향키 이동과 처음 선택(PIE 창에 포커스가 없어 CommonUI가 첫 포커스를 적용하지 않음), 선택 화면의 Esc, 보스를 먼저 처치하고 일반 적이 남은 경우의 보스 처치 연출.
- 테스트 중 고친 문제: 목록 버튼 방식일 때, 항목 상자가 풀에서 다시 쓰는 버튼에 이전 실행 연결이 남아 크래시가 났습니다. 드롭다운으로 바꾸며 그 코드는 없어졌습니다.

## 3. 회귀 확인

- 보스전(테스트 창): 보스 처치 → 슬로우모션 0.2배, 결과 연출 중 결과 화면 없음, STAGE CLEAR. 플레이어 사망 → GAME OVER, 그 뒤 보스 사망은 슬로우모션 없음(1.0배)·결과 그대로.
- 목록 버튼 때문에 바꿨던 `WBP_Button`·`WBP_PauseMenu`·`WBP_BattleResult`는 HEAD로 되돌렸습니다.
- HEAD의 `WBP_HUD`·`WBP_ExecutionPrompt`가 커밋 `d73d4363`에서 네임플레이트 작업 이전 버전으로 되돌아가 있어, HUD가 만들어질 때 모든 스테이지가 크래시했습니다(`BossStatus` 바인딩 없음). 작업 트리에서 두 파일을 `4d70fd54` 버전으로 되돌린 뒤 위 테스트를 했습니다.
