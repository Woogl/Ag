# 제자리 회전

서 있는 캐릭터가 방향을 바꿀 때 미끄러지듯 돌지 않고 회전 모션으로 발을 옮기며 돌아서게 하는 설계안입니다. [TurnInPlace](https://github.com/Vaei/TurnInPlace) 플러그인(1.8.0, MIT)의 방식을 플러그인 없이 우리 코드로 옮깁니다. 구현이 끝나면 결정을 [애니메이션과 이동](<../Program/애니메이션과 이동.md>), [캐릭터와 GAS](<../Program/캐릭터와 GAS.md>), [보스](<../Program/보스.md>), [어빌리티와 AbilityTask](<../Program/어빌리티와 AbilityTask.md>), [데이터 위치표](<../Program/데이터 위치표.md>), [구현 위치표](<../Program/구현 위치표.md>)로 옮기고 이 문서를 지웁니다.

기본 회전 경로 통일은 먼저 반영했습니다. UAgCharacterMovementComponent가 두 캐릭터의 자동 회전 제한을 공통 처리하고, 보스는 AI 포커스와 컨트롤러 목표 회전을 사용합니다. GetFacingTarget·UpdateFacing은 제거했습니다. 아래 설계 중 제자리 회전 모션과 애님 인스턴스 연동은 아직 구현하지 않았습니다.

## 목표

- 서 있는 보스와 가드 중 서 있는 플레이어는 바라볼 방향과 일정 각도 넘게 벌어지면 회전 모션으로 돌아섭니다. 그 각도 안에서는 돌지 않습니다.
- 메시가 아니라 액터를 돌립니다. 워핑, 무기 판정, 카메라가 쓰는 캐릭터 방향이 늘 액터 방향입니다.
- 판단과 진행은 C++에 두고, `ABP_Ag`에는 노드 두 개만 더합니다.

## 결정

| 항목 | 결정 | 이유 |
| - | - | - |
| 회전하는 것 | 액터를 돌립니다. 서 있는 동안 바라볼 방향(컨트롤러의 목표 회전)과 액터 방향의 차이가 최소 각도를 넘으면 회전 모션을 재생하고, 그 모션의 루트 회전만큼 액터를 돌립니다. 메시는 루트를 고정해 액터와 같은 방향을 봅니다. | 플러그인의 액터 기반 방식입니다. 메시만 돌리면(Lyra의 Rotate Root Bone) 워핑, 소켓, 판정마다 메시와 액터의 방향 차이를 따로 맞춰야 합니다. |
| 회전량 | C++가 엔진 `ExtractRootTrackTransform`으로 회전 모션의 루트 뼈 회전을 직접 읽습니다. 모션에 커브를 굽지 않습니다. 모션의 각도와 방향도 루트 회전에서 읽어 따로 적지 않습니다. 회전 모션 여섯 개는 Force Root Lock을 켜고, 고정 위치는 기본값(RefPose)입니다. | 플러그인의 커브는 루트 회전에서 만든 값이라 같은 값을 바로 읽을 수 있고, 모션과 스켈레톤에 커브가 늘지 않습니다. 이 함수는 루트 고정과 관계없이 루트 트랙을 읽습니다(엔진 소스 확인). 고정 위치를 첫 프레임으로 두면, 루트가 -90°에서 시작하는 모션(`Turn_90R`)의 몸이 옆을 봅니다. |
| 판단과 진행 | `UAgAnimInstance`가 매 프레임 게임 스레드에서 판단하고 진행합니다. 회전을 맡을 수 있고 차이가 최소 각도를 넘으면, 차이보다 크지 않은 가장 큰 각도의 같은 방향 모션(없으면 가장 작은 모션)을 처음부터 재생합니다. 모션 시간을 재생 속도대로 진행하면서 그동안의 루트 회전을 쌓아 두고, 모션이 끝나면 다시 판단합니다. 차이가 최대 각도에 닿으면 그 회전이 끝날 때까지 `PlayRateAtMaxAngle`로, 도는 쪽과 반대로 벌어지면 `PlayRateOnDirectionChange`로 재생합니다(둘 다면 큰 쪽). | 플러그인이 전용 서버에서 애님 그래프 없이 쓰는 방식(C++가 상태와 모션 시간을 진행하고 모션 데이터를 직접 읽음)을 화면에도 씁니다. 회전량이 그래프의 블렌드와 관계없어서, 플러그인이 그래프에서 섞인 커브를 1~2프레임 늦게 읽어 생기던 문제(1.8.0에서 고친 회전·회복 상태 왕복, 회전 상태에서 못 빠져나옴)가 생기지 않습니다. |
| 회전 적용 | 새 `UAgCharacterMovementComponent`가 `PhysicsRotation`을 재정의합니다. 애님 인스턴스가 회전을 맡을 수 있다고 하면, 쌓인 루트 회전만큼 액터를 돌리고 바라볼 방향과의 차이가 최대 각도를 넘지 않게 함께 돌립니다. 아니면 엔진 회전 그대로입니다. | 캐릭터 회전은 캐릭터 무브먼트가 맡는 엔진 구조를 따릅니다. 플러그인도 같은 자리에서 돌립니다. 액터를 돌리는 곳이 하나로 남습니다. |
| 회전을 맡는 조건 | 지금 자세(가드 여부)의 회전 모션 세트가 있고, 컨트롤러 목표 회전(`bUseControllerDesiredRotation`)을 쓰고, 땅에 서 있고(속도 0), 행동 중이나 비전투 상태가 아니고(`IsFacingFixed`), 살아 있을 때입니다. 애님 인스턴스의 함수 하나가 정하고, 캐릭터 무브먼트도 그 함수를 씁니다. 조건이 깨지면 회전 모션을 멈추고 쌓인 회전을 버립니다. | 몽타주 행동은 자기 회전(RootMotion, Dash)을 쓰고, 움직이기 시작하면 엔진 회전이 맡습니다. 판단이 한 곳에 있어 두 클래스가 어긋나지 않습니다. |
| 애님 그래프 | `ABP_Ag`의 가드 전환 뒤에 `BlendListByBool`(`bIsTurning`)을 하나 두고, 그 True 입력에 `Sequence Evaluator`(`TurnAnimation`, `TurnTime`, 반복 끔)를 하나 둡니다. 블렌드 시간은 엔진 기본값입니다. 상태 머신과 관성 블렌드는 두지 않습니다. | 상태와 시간을 C++가 정하므로 그래프는 고른 모션을 그 시간에 보여 주기만 합니다. 회전 모션의 처음과 끝이 대기 자세라서 모션이 끝나거나 다음 모션으로 바뀔 때 자세가 튀지 않습니다. 회전 모션을 멈출 때(움직이기 시작, 행동 시작)는 마지막 모션과 시간을 그대로 둔 채 블렌드로 빠집니다. |
| 보스가 바라보는 방향 | `AAgBossAIController`가 매 틱 현재 대상(`GetTarget`)을 AI 포커스로 둡니다(엔진 `SetFocus`, 대상이 없으면 지움). 보스는 매 틱 행동 중·비전투·사망이 아니면 `bUseControllerDesiredRotation`을 켜고, 아니면 끕니다. `AAgCharacterBase::UpdateFacing`과 `GetFacingTarget`은 지웁니다. | 지금 보스 회전은 캐릭터 틱이 액터를 직접 돌려 캐릭터 무브먼트를 거치지 않습니다. 엔진의 AI 포커스와 목표 회전으로 바꾸면 플레이어 가드와 같은 길로 제자리 회전이 걸립니다. 움직일 때는 지금처럼 회전 속도(초당 360°)로 돕니다. |
| 적용 범위 | 보스는 서 있는 동안 늘 쓰고, 플레이어는 가드 중 서 있을 때만 씁니다. 플레이어의 일반 자세에는 회전 모션 세트를 두지 않습니다(열린 문제 1). | 플레이어의 일반 대기 모션은 템플릿 `MM_Idle`이라 Samurai 회전 모션과 자세가 다릅니다(뼈 평균 거리 21.9cm). |
| 회전 모션 세트 | `FAgTurnInPlaceSet`(회전 모션 목록, 최소 각도 60°, 최대 각도 135°, `PlayRateAtMaxAngle` 1.3, `PlayRateOnDirectionChange` 1.7)을 `UAgAnimInstance`의 `TurnInPlaceSet`, `GuardTurnInPlaceSet`에 두고 자식 ABP 기본값으로 정합니다. 보스는 `TurnInPlaceSet`에 Halberd `Turn_90L`·`R`, 플레이어는 `GuardTurnInPlaceSet`에 Samurai `Guard_Turn45L`·`R`, `Guard_Turn90L`·`R`를 둡니다. 수치는 플러그인 기본값입니다. | 이동 블렌드 스페이스처럼 모션과 함께 맞추는 애니메이션 설정이라 그 모션을 쓰는 ABP에 둡니다. 회전 속도가 캐릭터 무브먼트에 있는 것과 같은 방식입니다. |

검토하고 고르지 않은 안:

- 플러그인을 그대로 설치: 코드 약 2,250줄 중 네트워크, 전용 서버, 디버그, 커스텀 중력처럼 쓰지 않는 부분이 대부분이고, 외부 모듈이 하나 늡니다.
- 플러그인의 애님 그래프를 그대로 옮김(Idle·TurnInPlace·TurnRecovery 상태 머신, 노드 함수, 관성 블렌드와 커브 제외 설정, 모션에 구운 커브): 그래프가 크게 늘어 사람이 손으로 만들어야 하고, 섞인 커브를 늦게 읽는 문제의 처리도 함께 옮겨야 합니다.
- 캐릭터 무브먼트가 회전 모션의 상태와 시간까지 맡음: 몽타주가 루트 모션을 주는 동안에는 캐릭터 무브먼트의 회전 함수가 불리지 않아, 끊긴 회전을 따로 지워야 합니다. 애님 인스턴스는 매 프레임 갱신되어 그 자리에서 멈춥니다.
- 보스의 `UpdateFacing` 안에서 제자리 회전: 플레이어 가드(캐릭터 무브먼트)와 보스(캐릭터 틱)로 액터를 돌리는 길이 둘이 됩니다.
- 제자리 회전을 몽타주 행동으로 재생: 행동 규칙(Busy, 후딜)에 걸려 이동이나 다른 행동이 바로 끊지 못합니다.

## 한 프레임의 흐름

1. AI 컨트롤러(보스)나 카메라(플레이어)가 컨트롤러 회전을 정합니다.
2. 캐릭터 무브먼트가 회전할 때, 애님 인스턴스가 회전을 맡을 수 있으면 지난 프레임에 쌓인 루트 회전만큼 액터를 돌리고 최대 각도를 넘지 않게 맞춥니다. 아니면 엔진 회전을 씁니다.
3. 애님 인스턴스가 바라볼 방향과 액터 방향의 차이로 회전 모션을 시작·진행·정지하고, 이번 프레임의 루트 회전을 쌓습니다.
4. 애님 그래프는 `bIsTurning`이면 고른 회전 모션을 그 시간의 자세로 보여 줍니다.

액터 회전은 모션보다 한 프레임 늦습니다(플러그인과 같음). 90° 모션에서 한 프레임(60fps)은 약 2°입니다.

## 열린 문제

### 1. 플레이어 일반 자세

락온 중 가드 없이 서 있으면 플레이어는 지금처럼 회전 속도로 미끄러지듯 돕니다.

| 안 | 내용 | 문제 |
| - | - | - |
| A (권함) | 가드에만 씁니다. | 락온 중 일반 자세의 회전은 지금과 같습니다. |
| B | 플레이어 대기 모션을 Samurai `Idle1`로 바꾸고 일반 자세에도 `Turn_45`·`Turn_90`을 씁니다. | 대기 모션을 바꾸는 별도 결정이 필요하고, 템플릿 걷기·달리기와 대기 자세가 서로 달라집니다. |

### 2. 보스의 90° 모션

Halberd 팩의 제자리 회전 모션은 90° 하나뿐입니다. 차이가 60°~90°일 때도 90°를 돌아서 최대 30° 지나쳐 멈춥니다.

| 안 | 내용 | 문제 |
| - | - | - |
| A (권함) | 그대로 두고 플레이해서 봅니다. | 서 있는 동안 최대 30° 지나친 방향을 봅니다. |
| B | 모션의 회전량을 필요한 각도에 맞춰 줄입니다. | 발 디딤과 몸 회전이 어긋나 발이 조금 미끄러집니다. |
| C | 보스의 최소 각도를 90°로 둡니다. | 지나치지는 않지만 서 있는 동안 최대 90° 어긋납니다. |

### 3. 원작 고지

MIT 라이선스는 가져온 부분에 원작의 저작권 고지와 허가 문구를 남기도록 합니다. 구조는 새로 짜지만, 각도에 맞는 모션 고르기와 재생 속도 규칙은 원작의 계산입니다. 우리 C++ 파일의 첫 줄은 프로젝트 저작권 문구입니다([AGENTS.md](<../../AGENTS.md>) 코딩 규칙 6).

| 안 | 내용 | 문제 |
| - | - | - |
| A (권함) | 저장소 루트에 제3자 고지 파일을 하나 두고 원작 이름, 저장소, MIT 전문, 가져온 부분을 적습니다. | 파일이 하나 늡니다. |
| B | 가져온 C++ 파일의 첫 줄 아래에 원작 고지를 적습니다. | 파일마다 고지가 반복되고, MIT 전문을 넣으면 머리말이 길어집니다. |

## 이전 결정과의 관계

- [애니메이션과 이동](<../Program/애니메이션과 이동.md>) 'ABP'의 '애님 그래프를 최소로 둔다'는 결정에 대해, 가드 전환과 같은 종류의 전환 노드 하나와 시퀀스 평가 노드 하나가 늡니다. 상태 머신과 관성 블렌드는 두지 않습니다.
- 같은 문서 '캐릭터 회전'에서 '행동하지 않을 때의 보스 회전은 `AAgCharacterBase`가 처리한다'가 'AI 포커스와 캐릭터 무브먼트의 목표 회전'으로 바뀝니다. 행동 중에 돌지 않는 것과 움직일 때의 회전 속도는 같습니다.
- 락온을 어빌리티가 맡는다는 결정은 그대로입니다. AI 포커스는 지금의 `GetFacingTarget`처럼 락온 어빌리티의 대상(`GetTarget`)을 씁니다.

## 확인

구현한 뒤 아래를 확인합니다. 테스트 실행은 실행 전에 확인을 받고, 모션의 느낌은 직접 플레이해서 봐 주세요.

- 빌드와 지난 회귀 시나리오가 통과합니다.
- 보스: 패턴 후딜레이에 서 있는 동안 플레이어가 옆으로 돌면, 60°를 넘을 때 회전 모션으로 돌아서고 발이 미끄러지지 않습니다. 걸을 때는 지금처럼 초당 360°로 돌고, 패턴과 반응 중에는 돌지 않습니다. LeapSlam, DashThrust, 넉업 중 회전은 지금과 같습니다.
- 플레이어: 가드 중 서 있을 때 카메라나 락온 대상이 60°를 넘게 벗어나면 돌아섭니다. 회전 중에 가드를 풀거나 움직이면 자세가 튀지 않고 이어집니다. 가드 없이 락온 중일 때는 지금과 같습니다.
- 대상이 계속 돌면 회전이 이어지고, 방향이 바뀌거나 최대 각도에 닿으면 빨라지며, 자세가 튀지 않습니다.
- 회전 모션 동안 몸이 액터 정면을 봅니다(루트 고정).
- 히트스톱과 시간 정지 동안 회전 모션과 액터 회전이 함께 멈춥니다.
- `BP_AgPlayer`, `BP_AgBoss`의 캐릭터 무브먼트 값(회전 속도 등)이 바뀌지 않습니다.
