# AI 워크플로우

기획자와 프로그래머가 각자 AI를 쓰며 효율적으로 일하기 위한 규칙입니다.

## 책임

- 공통
  - 사람은 디렉터이고, AI가 실무자입니다. 기획서·데이터·에셋·코드 작업은 AI가 하고, 사람은 판단하고 승인합니다.
  - AI의 작업 결과물은 지시한 사람이 확인하고 책임집니다.
- 기획자
  - 기획서를 명확하게 유지하고 최신화
  - 수치 밸런싱 방향 결정
  - 결과물이 기획 의도에 맞는지 판단
- 프로그래머
  - 기획서대로 동작하도록 구현
  - 코드 구조와 품질 관리
  - 프로젝트가 항상 빌드되고 실행되도록 유지

## 진행 순서

| # | 단계 | 담당자 | 사람이 할 일 | AI에게 맡기는 일 |
| - | - | - | - | - |
| 1 | 기획 | 기획자 | 방향을 정하고, AI가 제안한 데이터와 기획서를 검토해 확정합니다. | 기획서 초안 작성, 근거와 함께 데이터 제안, 용어·문서 간 충돌 점검 |
| 2 | 구현 | 프로그래머 | 구현 설계를 승인하고, 코드를 리뷰하고, 결과를 확인합니다. | 구현 계획서 작성, 코드와 에셋 작업, 빌드와 실행 확인, push |
| 3 | QA | 기획자 | 최신 버전을 받아 플레이하며 기획 의도에 맞는지 판단하고, 밸런싱 방향을 정합니다. | 제보 받은 버그 수정, 데이터·기획 변경 반영 |

## 협업 규칙

- 기획서
  - 기획서에 적지 않은 기능은 만들지 않습니다.
  - 기획서에 대한 질문이 생기면 프로그래머는 기획자에게 묻고, 답은 기획서에 반영합니다.
  - 변경 요청은 항목마다 기획서를 고친 뒤 구현하고, 플레이로 확인합니다.
- 데이터
  - 데이터는 기획서에 적은 수치와 설정(피격 반응, 가드·패리 가능 여부, 패턴 속성 등), 그리고 쓰는 에셋(모션, 이펙트 등)을 말합니다.
  - 데이터를 바꾸면 기획서도 함께 고칩니다.
  - 각 데이터가 어느 파일(JSON 데이터 파일, 에셋)에 들어 있는지는 [데이터 위치표](<Program/데이터 위치표.md>)에 정리합니다.
  - QA에서 기획자는 JSON 데이터 파일과 에셋만 고쳐 게임을 조정합니다. 코드를 고쳐야 하는 변경은 프로그래머에게 요청합니다.
- 구현
  - 구현은 기획서 본문을 따릅니다. 첨부 그림은 이해를 돕는 참고용이며, 좌표·크기·색을 그대로 옮기지 않습니다.
  - 코드는 데이터를 하드코딩하지 않고 데이터 파일과 에셋에서 읽어 씁니다.
  - 코드 수정은 프로그래머가 리뷰하고 승인한 뒤 push합니다.

## 문서 작성 규칙

- SSoT(Single Source of Truth)를 지킵니다. 수치, 규칙 같은 사실은 그것을 정의하는 문서의 한 곳에만 적고, 다른 곳에서는 '~를 따릅니다', '~ 참고'로 가리킵니다.
  - 용어는 [용어집](<용어집.md>)을 따릅니다.
  - 결정한 내용은 저장소의 문서에 적습니다. 개인 AI의 메모리나 대화는 출처가 될 수 없습니다.
- 기획서에는 플레이해서 확인할 수 있는 것(규칙, 수치, 화면 배치)을 적습니다. 플레이로 구분할 수 없는 것(코드 구조, 에셋 구성, 엔진 기능 선택)은 구현 계획서에서 정합니다.
- 기획서에는 현재 마일스톤의 내용만 적습니다. 다음 마일스톤에 대한 언급이나 '나중에 검토' 같은 문구는 쓰지 않습니다.
