# AI 워크플로우

기획자와 프로그래머가 각자 AI를 쓰며 효율적으로 일하기 위한 규칙입니다.

## 책임

- 공통
  - 사람은 디렉터이고, AI가 실무자입니다.
  - AI의 작업 결과물은 지시한 사람이 확인하고 책임집니다.
- 기획자
  - 기획서를 명확하게 유지하고 최신화
  - 수치 밸런싱
  - 결과물이 기획 의도에 맞는지 판단
- 프로그래머
  - 기획서대로 동작하도록 구현
  - 코드 구조와 품질 관리
  - 프로젝트가 항상 빌드되고 실행되도록 유지

## 진행 순서

| # | 단계 | 담당자 | 사람이 할 일 | AI에게 맡기는 일 |
| - | - | - | - | - |
| 1 | 기획 | 기획자 | 방향과 수치를 정하고 기획서를 확정합니다. | 기획서 초안 작성, 용어·구현 우선순위·문서 간 충돌 점검 |
| 2 | 구현 | 프로그래머 | 구현 설계를 승인하고 코드를 리뷰한 뒤, 빌드와 실행을 확인하고 푸시합니다. | 구현 계획서 작성, 코드와 에셋 작업 |
| 3 | QA | 기획자 | 최신 버전을 받아 플레이하며 기획 의도에 맞는지 판단하고, 수치를 밸런싱합니다. | 제보 받은 버그 원인 파악 및 수정 |

## 협업 규칙

- 기획서
  - 기획서에 적지 않은 기능은 만들지 않습니다.
  - 기획서는 기획자만 고칩니다. 기획서에 대한 질문이 생기면 프로그래머는 기획자에게 묻고, 기획자는 답을 기획서에 반영한 뒤 수정 이력에 적고 프로그래머에게 알립니다.
- 수치
  - 기획서의 수치는 모두 플레이 테스트 전의 초기값이며, QA 단계에서 조정합니다. QA에서 조정한 수치는 QA가 끝날 때 기획자가 기획서에 반영합니다.
  - 기획서의 수치는 코드에 직접 쓰지 않고, 기획자가 에디터에서 직접 조정할 수 있게 둡니다. 각 수치를 어디서 조정하는지는 구현 계획서의 수치 위치표에 정리합니다.
  - 기획자는 에디터에서 수치만 조정하고, 에셋을 만들거나 교체하지 않습니다.
- 코드와 에셋
  - 코드 수정은 단계와 관계없이 프로그래머가 리뷰하고 푸시합니다.
  - 코드는 에셋을 직접 가리키지 않고, 에디터에서 지정한 에셋을 씁니다.

## 문서 작성 규칙

- SSoT(Single Source of Truth)를 지킵니다. 수치, 규칙, 구현 우선순위 같은 사실은 그것을 정의하는 문서의 한 곳에만 적고, 다른 곳에서는 '~를 따릅니다', '~ 참고'로 가리킵니다.
  - 용어는 [용어집](<Design/용어집.md>)을 따릅니다.
  - 구현 우선순위 표기는 [마일스톤1 계획](<Design/마일스톤1 계획.md>)의 구현 우선순위를 따릅니다.
  - 모양과 색은 첨부 그림을 따릅니다. 기획서에 색상 값(색 이름, 16진 값, 불투명도)을 쓰지 않고, 구분이 필요하면 기능이나 상대적인 표현으로 적습니다.
  - 결정한 내용은 저장소의 문서에 적습니다. 개인 AI의 메모리나 대화는 출처가 될 수 없습니다.
- 기획서에는 플레이해서 확인할 수 있는 것(규칙, 수치, 화면 배치)을 적습니다. 플레이로 구분할 수 없는 것(코드 구조, 에셋 구성, 엔진 기능 선택)은 구현 계획서에서 정합니다.
- 기획서에는 현재 마일스톤의 내용만 적습니다. 다음 마일스톤에 대한 언급이나 '나중에 검토' 같은 문구는 쓰지 않습니다.
- 문서 수정 이력은 문서를 처음 push한 뒤부터 적습니다. 그 전에는 '최초 작성' 한 줄만 둡니다.
