# 마일스톤1 계획

현재 구현과 플레이 검증의 기준은 마일스톤1입니다.

용어는 [용어집](<../용어집.md>)을 따릅니다.

## 기간

| 단계 | 시작일 | 종료일 | 작업 내용 |
| - | - | - | - |
| 기획 | 2026.10.08 | 2026.10.10 | 마일스톤에 필요한 모든 기획서를 적확하게 작성 |
| 구현 | 2026.10.10 | 2026.10.10 | AI에게 기획서 전달하여 설계 문서화. 이후 AI에게 구현 위임 |
| 플레이 검증 | 2026.10.10 | 2026.10.26 | 의도한 대로 구현되었는지 직접 플레이하며 확인하고, 마지막 날 '목표'의 질문에 답합니다. |

## 목표

### 1. 보스전 프로토타이핑 제작

타이틀 화면에서 게임을 시작해 보스와 싸우고, 결과 UI에서 다시 도전하거나 처음으로 돌아가거나 게임을 끝내기까지 한 바퀴를 막힘없이 돌 수 있으면 됩니다.

완성도보다는 처음부터 끝까지 돌아가는 것이 먼저입니다. 기획서의 모든 항목이 들어가 있고 진행을 막는 버그나 크래시가 없다면, 이 목표는 이룬 것으로 봅니다.

### 2. 핵심 전투 재미 검증

기획자가 직접 플레이하면서 [게임 개요](<게임 개요.md>)의 핵심 재미가 정말 느껴지는지 확인합니다.

- 액션성: 원하는 대로 캐릭터를 움직이며 싸울 수 있는가?
- 타격감: 때리고 막을 때 손맛과 연출이 느껴지는가? 공격 예고와 무기 궤적 외의 VFX는 템플릿 에셋을 재사용한 것이므로 히트스톱, 카메라 셰이크, 슬로우모션의 타이밍 위주로 판단합니다.
- 성취감: 몇 번 도전하면 패턴을 읽어 낼 수 있게 되는가?

### 3. AI 워크플로우 테스트

[AI 워크플로우](<../AI 워크플로우.md>)대로 기획자와 프로그래머가 각자 AI를 써서 만들어 보고, 이 방식이 실제로 잘 돌아가는지 시험합니다. 마일스톤이 끝나면 아래 질문에 답합니다.

| 묻는 대상 | 질문 |
| - | - |
| AI | 기획서와 다르게 만들어진 부분은 어디이고, 원인은 무엇인가? |
| AI | 구현을 시작한 뒤 기획서가 고쳐진 곳은 어디이고, 왜 고쳐졌는가? |
| AI | [AI 워크플로우](<../AI 워크플로우.md>)의 규칙 중 지켜지지 않은 것은 무엇인가? |
| 기획자, 프로그래머 | AI에게 맡기기로 한 일 중 사람이 직접 한 일은 무엇이고, 왜인가? |
| 기획자 | 기획 의도와 다르게 만들어진 부분은 어디인가? |
| 기획자, 프로그래머 | [AI 워크플로우](<../AI 워크플로우.md>)의 규칙 중 수정이 필요한 것은 무엇이고, 왜인가? |

- AI에게는 기획서, 구현 문서, 데이터 위치표, 코드, 커밋 기록을 보고 답하게 합니다.

## 아트 리소스

- 마일스톤1에서는 프로젝트에 있는 템플릿 에셋, Fab 애니메이션 팩(ARPG 팩 4종, Dodge and Evade Anims), 엔진에 포함된 사운드를 활용합니다.
- 공격 예고 VFX, 무기 궤적 VFX, 궁극기·극한 회피용 화면 후처리, 카메라 셰이크와 스킬·궁극기 HUD 아이콘 2종은 직접 제작한 에셋을 씁니다. 그 밖의 모양과 소리를 위한 아트 에셋(메시, 텍스처, VFX, 글꼴, 사운드)은 기존 에셋을 씁니다.
- 동작에 필요한 에셋은 새로 만들 수 있습니다.

캐릭터 외형, 사용하는 리소스와 세부 표현은 [아트 표현 사양](<../Art/아트 표현 사양.md>)을 따릅니다.
