## 목표

### 1. 보스전 프로토타이핑 제작

타이틀 화면에서 게임을 시작해 보스와 싸우고, 결과 UI에서 다시 도전하거나 처음으로 돌아가거나 게임을 끝내기까지 한 바퀴를 막힘없이 돌 수 있으면 됩니다.

완성도보다는 처음부터 끝까지 돌아가는 것이 먼저입니다. 🔴 S 항목이 모두 들어가 있고 진행을 막는 버그나 크래시가 없다면, 이 목표는 이룬 것으로 봅니다.

### 2. 핵심 전투 재미 검증

QA 때 직접 플레이하면서 [게임 개요](<게임 개요.md>)의 핵심 재미가 정말 느껴지는지 확인합니다.

- 액션성: 원하는 대로 캐릭터를 움직이며 싸울 수 있는가?
- 타격감: 때리고 막을 때 손맛과 연출이 느껴지는가? 이펙트는 템플릿 에셋을 재사용한 것이므로 히트스톱, 카메라 셰이크, 슬로우모션의 타이밍 위주로 판단합니다.
- 성취감: 몇 번 도전하면 패턴을 읽어 낼 수 있게 되는가?

질문은 🔴 S 기능을 기준으로 답하고, 그 밖의 기능은 구현된 만큼 함께 확인합니다.

### 3. AI 워크플로우 테스트

[AI 워크플로우](<../AI 워크플로우.md>)대로 기획자와 프로그래머가 각자 AI를 써서 만들어 보고, 이 방식이 실제로 잘 돌아가는지 시험합니다. 마일스톤이 끝나면 아래 질문에 답합니다.

| 묻는 대상 | 질문 |
| - | - |
| AI | 기획서와 다르게 만들어진 부분은 어디이고, 원인은 무엇인가? |
| AI | 구현을 시작한 뒤 기획서가 고쳐진 곳은 어디이고, 왜 고쳐졌는가? |
| AI | [AI 워크플로우](<../AI 워크플로우.md>)의 규칙 중 지켜지지 않은 것은 무엇인가? |
| 기획자, 프로그래머 | AI에게 맡기기로 한 일 중 사람이 직접 한 일은 무엇이고, 왜인가? |
| 기획자 | 기획 의도와 다르게 만들어진 부분은 어디인가? |
| 기획자, 프로그래머 | [AI 워크플로우](<../AI 워크플로우.md>)의 규칙 중 수정이 필요한 것은 무엇이고, 왜인가? |

- AI에게는 기획서, 구현 계획서, 데이터 위치표, 코드, 커밋 기록을 보고 답하게 합니다.

- 동작에 필요한 에셋은 새로 만들 수 있습니다.

| 용도 | 쓰는 에셋 | 표현 |
| - | - | - |
| 붉은 섬광 | 템플릿의 NS_JumpPad | 색(사용자 파라미터 Color)만 바꿔 재생합니다. 위치와 시점은 [보스 사양](<보스 사양.md>)의 붉은 섬광을 따릅니다. |

## 구현 우선순위

기획서에서는 기능별 구현 우선순위를 아래 신호등으로 표시합니다.

| 표시 | 구현 우선순위 | 기준 |
| - | - | - |
| 🔴 | S | 마일스톤1에 반드시 구현 |
| 🟡 | A | 일정 내 구현 목표 |
| 🟢 | B | 여유가 있을 때 구현 |

- 구현 우선순위는 항목을 정의한 곳 한 곳에만 표시합니다. 같은 항목을 다른 문서나 다른 항목에서 다시 다룰 때는 표시하지 않습니다.
- 구현 우선순위 표시가 없는 항목은 자신이 속한 상위 항목의 구현 우선순위를 따릅니다.
- 상위 항목에도 표시가 없으면 🔴 S로 봅니다. (예: [전투 시스템](<전투 시스템.md>), [게임 플로우](<게임 플로우.md>)의 규칙)
- 다른 곳에 정의된 항목을 가리키는 문장('~를 따릅니다', '~ 참고')은 구현 우선순위를 새로 정하지 않습니다. 가리킨 항목은 정의한 곳의 구현 우선순위를 따릅니다.
- 다른 기능이 있어야만 쓰이는 항목은 그 기능보다 구현 우선순위가 높을 수 없습니다. 상위 항목을 따라 더 높게 읽히면 그 기능의 구현 우선순위로 봅니다. (예: 회피 반격 적중 시 MP 충전)
- 범위와 목표가 맞지 않으면 기능을 🔴 S로 올리기보다 덜 중요한 쪽을 낮추거나 줄입니다.
