# 개발 도구와 검증

에디터와 게임을 확인하고 다루는 개발 도구, 동작 테스트 방식을 정합니다.

## 기술 결정

| 항목 | 결정 | 이유 |
| - | - | - |
| 적 시야 미리 보기 | 레벨 편집 뷰포트에서 선택한 적의 캡슐 중심에 청록색 부채꼴 윤곽을 표시합니다. `Characters.json`의 `SightDistance`(cm)와 `SightAngle`(전체 각도)을 읽고 현재 위치·회전을 따릅니다. 액터 스케일로 거리를 늘리지 않으며, 지형 가림을 제외한 설정 범위를 보여 줍니다. 선택을 해제하면 숨기고 게임 월드에는 그리지 않습니다. JSON 재로드 후 편집 뷰포트도 다시 그립니다. | 배치 중 시야를 확인하며, 기획 값을 컴포넌트나 BP에 중복 저장하지 않습니다. |
| 테스트용 콘솔 명령 | 개발 빌드에만 둡니다. 직접 플레이와 동작 테스트가 같은 명령으로 상황을 만듭니다. 사망(플레이어 `AgKillPlayer`, 보스 `AgKillBoss`, 보스를 뺀 적 `AgKillEnemies`), 플레이어 무적 켜기·끄기(`AgGod`), 플레이어 MP·UP 채우기(`AgFillMPUP`), 대상 적의 그로기(`AgGroggy`)·패턴 발동(`AgPattern <패턴 ID>`)·HP 비율 설정(`AgSetHP <퍼센트>`), 모든 적 AI 멈춤·다시 시작(`AgStopAI`, `AgStartAI`)이 있습니다. 대상 적은 플레이어의 락온 대상이고, 없으면 가장 가까운 적입니다. 자원은 플레이어가 건 효과로 바꿔 HUD·사망·그로기·페이즈 전환이 실제 피격과 같이 반응합니다. 무적은 `State.Invincible`을 붙여 적의 공격을 무시하므로, 극한 회피는 일어나지만 패리·가드는 일어나지 않습니다. 패턴 발동은 대상의 쿨다운을 비우고 발동하며, 발동을 막는 상태(행동 중, 피격 반응 등)는 지킵니다. 키 입력과 프레임마다의 관찰·판정은 테스트 창에서 파이썬으로 합니다('에디터 파이썬 원격 실행'). | 직접 플레이에서 던전 진행과 전투 결과를 빠르게 확인하고, AI가 확인한 상황을 사람이 같은 명령으로 재현합니다. 파이썬으로 어트리뷰트를 직접 쓰면 변경 이벤트가 없어 HUD·사망·그로기 판정이 일어나지 않고, 테스트마다 준비 코드를 새로 짜게 됩니다. 엔진 `God` 명령은 대미지가 엔진 대미지 처리(`bCanBeDamaged`)를 거치지 않는 효과로 들어오므로 듣지 않습니다. 플레이어에게 보이는 기능이 아닌 개발 도구입니다. |
| 확인용 입력 | 플레이어 캐릭터에 에디터 전용 속성(`DevPressInput`, `DevMashInput`, `DevHoldInput`, `DevMoveInput`)을 둡니다. 테스트 창이나 PIE에서 파이썬으로 값을 넣으면 키를 누른 것과 같이 처리합니다. `DevPressInput`은 누른 다음 프레임에 떼어, 엔진 점프가 시작될 틈을 줍니다. | AI가 키보드 없이 조작(이동 및 액션)을 확인합니다. 에디터 빌드에만 있어 게임에는 들어가지 않습니다. |
| 프로젝트 MCP 도구 | 엔진 MCP 도구와 에디터 파이썬으로 바꿀 수 없는 설정(몽타주 섹션, 몽타주 구간과 구간별 재생 속도, 슬롯 그룹, 위젯 애니메이션, 블루프린트 컴포넌트의 Parent Socket, StateTree 에셋의 생성과 상태·태스크·전환 편집과 컴파일)을 바꾸는 도구를 에디터 전용 모듈 `AgEditor`에 두고, 영역(애니메이션, 블루프린트, StateTree)마다 툴셋 클래스를 하나씩 둡니다. 엔진 MCP에 툴셋으로 등록해, AI가 열린 에디터에서 다른 MCP 도구처럼 부릅니다. 엔진 도구로 할 수 있는 일은 이 툴셋들에 두지 않습니다. | 몽타주처럼 반복되는 에셋 작업을 AI가 처리합니다. 영역끼리 공유하는 코드가 없어, 엔진 툴셋처럼 영역별로 나눕니다. 엔진에 들어 있는 MCP 도구에는 이 기능이 없습니다. 엔진의 StateTree MCP 도구는 조회만 하고, StateTree 편집 함수는 C++ 에디터 API에만 있습니다. 나이아가라 시스템 편집(사용자 파라미터, 모듈 입력, 모듈 삭제, 이미터 이름)은 엔진의 실험 플러그인 NiagaraToolsets가 MCP 도구로 제공하므로 켜서 쓰고, 나이아가라 툴셋은 두지 않습니다. 게임 모듈에는 게임 코드만 둡니다. |
| 에디터 파이썬 원격 실행 | Python 플러그인(에디터 전용)과 원격 실행(`DefaultEngine.ini`)을 켭니다. AI가 열린 에디터에서 파이썬으로 에셋을 고치고, 테스트 창('동작 테스트 실행')과 PIE를 파이썬으로 조종합니다. 원격 실행은 엔진 기본 설정대로 이 PC 안에서만 열립니다. | 에셋 작업마다 에디터를 닫고 헤드리스로 처리하지 않아도 되고, 에디터 도구(MCP)로 읽거나 바꿀 수 없는 값(몽타주 노티파이, 배열 등)도 다룰 수 있습니다. |
| 동작 테스트 실행 | 테스트는 공유 에디터의 PIE 대신 테스트마다 게임 창(별도 프로세스)을 하나씩 띄워 확인합니다. 실행은 `Scripts/ScenarioTest`를 씁니다(쓰는 법은 폴더의 README). 창은 낮은 그래픽 품질과 60fps 제한으로 띄우고, 창 제목과 화면 안내 글자로 무엇을 확인하는지 보여 줍니다. 창은 사람의 입력을 받지 않습니다. 창마다 원격 실행 포트를 따로 쓰고, 값은 그 창의 메모리에서만 바꿉니다. 테스트 창으로 확인할 수 없는 것(타이틀 화면, 메뉴 조작, 소리)은 PIE에서 확인합니다. 실행 전 물음과 끝난 뒤 정리는 [AI 워크플로우](<../AI 워크플로우.md>)의 '테스트 작업 수칙'을 따릅니다. | 에디터 하나에는 PIE가 하나뿐이라 여러 AI가 동시에 확인할 수 없습니다. 창으로 띄우면 사람이 진행을 지켜볼 수 있고, 지켜보다 창을 눌러도 테스트에 섞이지 않습니다. 프레임을 고정해야 공격 판정 같은 타이밍 확인을 믿을 수 있습니다. `DesignData` JSON은 모든 창과 에디터가 함께 읽습니다. |
| PIE 마우스 포커스 | 에디터 플레이 설정 'Game Gets Mouse Control'을 켭니다(`DefaultEditorPerProjectUserSettings.ini`). PIE가 시작하면 게임 뷰포트가 포커스를 가져가고, 보스 스테이지에서는 마우스를 바로 잡습니다(Shift+F1로 풀림). | 꺼져 있으면 PIE가 뷰포트 포커스 없이 시작하는데, CommonUI는 에디터에서만 이때 화면의 입력 설정(커서, 마우스 캡처)과 첫 포커스를 건너뛰고 다시 적용하지 않습니다. 그러면 타이틀에서 빈 곳을 클릭할 때 뷰포트가 마우스를 잡아 커서가 사라집니다. 에디터 설정이라 패키지 게임에는 영향이 없습니다. |

## 클래스 구조

### 에디터 도구

| 클래스 | 부모 | 역할 |
| - | - | - |
| `UAgAnimationToolset` | `UToolsetDefinition` | 몽타주와 스켈레톤 슬롯 그룹을 고치는 프로젝트 MCP 도구 (에디터 전용 모듈 `AgEditor`) |
| `UAgBlueprintToolset` | `UToolsetDefinition` | 블루프린트 컴포넌트의 Parent Socket과 위젯 애니메이션을 고치는 프로젝트 MCP 도구 (에디터 전용 모듈 `AgEditor`) |
| `UAgStateTreeToolset` | `UToolsetDefinition` | StateTree 에셋을 만들고 고치는 프로젝트 MCP 도구 (에디터 전용 모듈 `AgEditor`) |
| `UAgDataReloadSubsystem` | `UEditorSubsystem` | `DesignData` 폴더를 지켜보다가 저장된 JSON을 에셋 매니저에 다시 읽게 합니다 (에디터 전용 모듈 `AgEditor`) |
| `UAgEnemySightPreviewComponent` | `UActorComponent` | 적 캐릭터의 에디터 전용 기본 서브오브젝트. 캐릭터 데이터 ID로 시야 값을 조회하고 캡슐 중심·액터 회전을 전달합니다. 게임 패키지에는 인스턴스를 포함하지 않습니다. |
| `FAgEnemySightVisualizer` | `FComponentVisualizer` | `AgEditor` 모듈에서 등록·해제하며, 선택한 적의 시야 부채꼴을 편집 뷰포트에 그립니다. |
