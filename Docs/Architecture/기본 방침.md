# 기본 방침

구현 전체에 적용하는 방침을 정합니다.

| 항목 | 결정 | 이유 |
| - | - | - |
| 새 에셋 위치 | 새로 만드는 에셋은 `/Game` 바로 아래 종류별 폴더에 둡니다. 템플릿 에셋은 원래 폴더(`Characters/Mannequins`, `LevelPrototyping`, `Variant_*`)에, Fab 에셋은 `Fab`에 둡니다. | 경로에 프로젝트 이름(`/Game/Ag`)이나 같은 단어(`/Game/Game`)가 겹치면 헷갈립니다. 템플릿·Fab 에셋은 각자의 폴더에 있어 구분됩니다. |
| Fab 모션 | 쓰는 시퀀스의 루트 모션 설정은 원본에서 정합니다. 켜는 것이 기본이고, 루트 모션 소스로 움직이는 동안만 재생하는 시퀀스와 궁극기 컷신 뒤에 재생하는 시퀀스는 끄고 루트 뼈를 고정합니다. | 같은 모션을 두 벌 두지 않습니다. 엔진은 루트 모션을 주는 몽타주를 하나만 기억하는데, 컷신의 시퀀서 몽타주가 그 자리를 가져갔다가 끝날 때 비웁니다. 다시 정하려면 몽타주를 새로 재생해야 하고 그러면 시간 정지·Busy 구간이 끊기므로, 컷신 뒤의 시퀀스는 루트 모션을 끕니다. |
| ABP | 공통 `ABP_Character` 하나에 최소 노드만 두고(자식 `ABP_Player`·`ABP_Boss`는 기본값만), 값 계산은 C++ `UAgAnimInstance`가, 행동은 모두 몽타주가 맡습니다. 상태 머신은 두지 않습니다. | AI가 BP 그래프를 다루기 어렵습니다. |
| 캐릭터 설정 | 기획서에 없는 캐릭터 설정(캡슐, 가속)은 템플릿 값이 아니라 엔진 기본값을 씁니다. | 플레이 전에 임의의 수치를 늘리지 않습니다. |
| 연출 | 모양·페이드·채우기 같은 시각 표현은 머티리얼, 위젯 애니메이션, 나이아가라, 큐 에셋이 맡고 코드는 파라미터와 재생만 다룹니다. 큐 블루프린트에는 데이터만 두고, 엔진 큐 데이터로 안 되는 기능만 엔진 큐 클래스를 상속한 C++ 클래스에 칸으로 더합니다. 연출마다 C++ 클래스를 만들지 않습니다. | 연출과 게임 로직이 나뉩니다. 클래스는 연출 수가 아니라 엔진에 없는 기능 수만큼만 늘어납니다. |
| 템플릿 콘텐츠 | 템플릿의 메시, 머티리얼, 텍스처, 애니메이션, 몽타주, 나이아가라, 컨트롤 릭 같은 리소스는 대역 에셋(NS_Damage, LevelPrototyping 폴더) 말고도 나중에 쓸 수 있어 남겨 둡니다. 패키징은 게임 맵 2개(`LV_FrontEnd`, `LV_BossStage`)만 쿡합니다. | 쿡할 맵을 정하지 않으면 프로젝트의 모든 맵을 쿡합니다. |
| 구조 선택 | 코드 구조는 AI가 작업하기 편한 쪽보다 엔진이 권장하는 쪽을 따릅니다. 엔진·프레임워크 기능이 기대대로 동작하지 않으면, 관계없는 클래스(PlayerController 등)에 우회 코드를 넣지 않고 그 기능의 설정과 확장 지점(에디터 설정, 위젯, CommonUI 하위 클래스 등)을 먼저 찾습니다. 예외로, 몽타주 안에서 게임 규칙이 쓰는 시각은 엔진 노티파이 대신 프로젝트 코드가 몽타주 타임라인으로 판정합니다([몽타주 타임라인과 구간 판정](<몽타주 타임라인과 구간 판정.md>)). Epic 샘플(Lyra)은 참고만 하고 구조를 옮기지 않습니다(화면 분할용 `GameUIManagerSubsystem`·`GameUIPolicy`, Game Feature용 `UI.Layer.*` 태그 등). | 엔진 기능을 설계된 대로 써야 코드가 엔진의 동작과 어긋나지 않습니다. Lyra의 구조는 로컬 플레이어 여럿과 Game Feature를 위한 것이라 이 게임에 필요 없습니다. |
| 객체 수명 | `TStrongObjectPtr`와 `AddToRoot`를 쓰지 않습니다. 객체는 그것을 쓰는 액터나 컴포넌트가, 게임 전체가 쓰는 객체는 에셋 매니저가 UPROPERTY로 들고, 네이티브 클래스의 기본 객체(프로젝트 설정 포함)에는 값(수치, 열거형, 소프트 경로)만 둡니다. | 객체 수명을 GC가 관리합니다. 패키징 빌드에서는 네이티브 기본 객체를 GC가 따라가지 않으므로, 나중에 만들거나 읽은 객체를 가리키게 두면 안 됩니다. |
