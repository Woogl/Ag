# 카메라와 화면 효과

플레이어 카메라(자유 시점, 락온 카메라), 카메라 셰이크, 화면 후처리를 어떻게 구현할지 정합니다.

## 기술 결정

| 항목 | 결정 | 이유 |
| - | - | - |
| 자유 시점 | 스프링 암과 카메라로 만듭니다. 거리, 회전 중심 높이, 위치 추적 지연, FOV는 `BP_Player`의 스프링 암과 카메라에 적고, 회전 지연은 두지 않습니다. 스프링 암은 캐릭터의 회전을 물려받지 않습니다(절대 회전). 락온 카메라도 스프링 암의 위치를 회전 중심으로 씁니다. | 회피 방향처럼 행동이 캐릭터를 한 번에 돌리는 일이 스프링 암이 그 프레임의 카메라 자리를 정한 뒤에도 일어납니다(선입력은 타이머로 실행). 회전을 물려받으면 그 한 프레임 동안 카메라가 캐릭터와 함께 돌아 화면이 튑니다. |
| 락온 카메라 | 락온 행동이 실행 중이면 플레이어 캐릭터가 매 프레임 카메라를 락온 대상 쪽으로 돌립니다. 각도 제한·내려다보는 각도·회전 속도·보간 시간은 `BP_Player`의 `Camera > Lock-On` 기본값에 둡니다. 락온 지점은 `AAgBossCharacter::GetLockOnLocation`으로 얻고, 그 본은 [UI 시스템과 게임 플로우](<UI 시스템과 게임 플로우.md>) '월드 위치 HUD'를 따릅니다. 락온 행동과 대상은 [대상 찾기와 락온](<대상 찾기와 락온.md>)을 따릅니다. | |
| 카메라 셰이크 | 상황별 단계 선택은 `BP_Player`의 `Camera > Combat Shake` 기본값, 시간표의 재생 시점·단계는 `MontageTimelines.json`에 둡니다. `AgCameraShake::Play`가 로컬 플레이어 Pawn의 ASC에 단계별 GameplayCue를 실행합니다. 엔진 Burst 큐가 단계별 CameraShake 에셋을 재생하며, 진폭·진동수·지속 시간·페이드는 그 에셋에서 조정합니다. 같은 단계도 겹쳐 재생하도록 `Single Instance`를 끕니다. | 기획이 정하는 발생 조건과 아트가 조정하는 흔들림을 나눕니다. 엔진 Cue와 기본 카메라 매니저를 사용하므로 전용 PlayerCameraManager 클래스가 필요하지 않습니다. |
| 화면 후처리 | 화면 효과용 GameplayCue 액터가 `UAgPostProcessComponent`를 소유합니다. 머티리얼과 페이드는 큐 에셋의 컴포넌트 기본값에 둡니다. 지속 효과는 Looping 큐, 한 번 재생하는 효과는 BurstLatent 큐를 사용합니다. 적용·해제와 아트 제작 규약은 아래 '화면 후처리'를 따릅니다. | 연출의 수명과 자원을 큐가 함께 관리하고, 같은 컴포넌트를 새 화면 효과에도 재사용합니다. |

## 화면 후처리

`GC_UltimateScreen`은 궁극기 전용 화면 연출입니다. `AM_Player_Ultimate`의 `ScreenEffect` 트랙에 둔 엔진 `AnimNotify_GameplayCueState`가 `GameplayCue.UltimateScreen`을 켜고 끕니다. 구간은 몽타주 시작부터 Judgment 끝(Draw 시작)까지이며, 궁극기 중단 때도 노티파이 종료로 해제됩니다.

극한 회피 화면 효과는 `AM_Player_PerfectDodge`의 `ScreenEffect` 트랙에 둔 엔진 `AnimNotify_GameplayCue`가 각 섹션(`Left`, `Right`, `Forward`, `Backward`) 시작 0.0001초 뒤에 `GameplayCue.PerfectDodgeScreen`을 한 번 실행합니다. 큐는 시간 서브시스템의 지금 슬로우모션 지속 시간(실제 시간)을 전체 재생 시간으로 씁니다. 극한 회피 슬로우모션은 같은 행동의 발동 ApplyEffect가 몽타주가 움직이기 전에 걸므로, 노티파이가 울릴 때는 늘 그 슬로우모션이 돌고 있습니다. 이 값에는 페이드 인과 아웃이 포함됩니다. 같은 큐가 재실행되면 자기 머티리얼 인스턴스를 정리하고 처음부터 재생합니다.

### 아트 설정

1. `/Game/GameplayCues/GC_UltimateScreen` 또는 `GC_PerfectDodgeScreen`을 열고 `PostProcess` 컴포넌트를 선택합니다.
2. `Screen Effect`의 `Material`에 아트가 만든 머티리얼 또는 머티리얼 인스턴스를 지정합니다. `Blend In`·`Blend Out`도 여기서 조정합니다. 페이드 시간의 합은 단발 효과의 전체 재생 시간 이하여야 합니다.
3. 머티리얼은 `Material Domain = Post Process`로 만들고 `Is Blendable`을 끕니다. 톤매핑 뒤의 `PostProcessInput0`을 사용합니다. 필수 스칼라 `AgEffectWeight`가 0일 때 원래 화면, 1일 때 완전한 효과가 되도록 구성합니다. 선택 스칼라 `AgEffectTime`은 효과가 시작한 뒤 지난 초입니다. 시간에 따른 표현이 필요하면 이 값을 사용합니다.

궁극기와 극한 회피는 부모 머티리얼까지 따로 둡니다. 한쪽의 그래프나 파라미터를 바꿔도 다른 쪽에 영향을 주지 않습니다. 아트는 각 인스턴스의 `01 Art` 그룹을 조정합니다. `00 Runtime` 그룹은 Cue가 갱신하므로 연출 강도 조절에는 사용하지 않습니다. 아트가 만든 다른 머티리얼을 Cue의 `Material`에 지정해도 됩니다. 공간 절단선·파편·캐릭터 잔상은 이 후처리 머티리얼이 생성하지 않습니다.

### 수명과 중첩

- 로컬 플레이어가 실제로 소유한 Pawn에만 적용합니다. 현재 싱글 플레이 범위에서 Unbound 후처리를 사용하므로 같은 월드의 뷰에 적용됩니다.
- 큐마다 MID와 엔진 `UPostProcessComponent`를 따로 만듭니다. 활성 효과는 함께 적용하며 우선순위로 하나를 고르지 않습니다. 같은 부모 머티리얼도 합쳐지지 않도록 `Is Blendable`을 끄고, 같은 렌더 단계 안의 합성 순서는 보장하지 않습니다.
- 페이드와 `AgEffectTime`은 `UWorld::GetAudioTimeSeconds`로 계산합니다. 시간 정지·슬로우모션·캐릭터 히트스톱과 무관하게 흐르고 게임 일시정지에는 멈춥니다. 단발 효과는 이 시계로 끝내며 엔진 BurstLatent의 게임 시간 종료 타이머를 사용하지 않습니다.
- Looping 큐를 해제하면 현재 강도에서 페이드 아웃하고 끝난 뒤 엔진 풀로 돌아갑니다. 페이드 중 다시 켜면 기존 큐는 마무리하고 새 큐가 시작합니다. 재활용·EndPlay·Pawn 소유권 상실 때도 MID와 후처리 컴포넌트를 정리합니다.
- 에셋 검증과 재생 시 머티리얼 도메인, 필수 파라미터, `Is Blendable`, 페이드와 전체 시간을 확인합니다. 잘못된 설정은 오류를 남기고 재생하지 않습니다.

## 클래스 구조

### 플레이어 카메라

`AAgPlayerCharacter`는 카메라와 스프링 암을 소유하고, 락온 카메라를 갱신하며 `GetCombatCameraShake`로 전투 결과에 맞는 셰이크 단계를 선택합니다. 대미지 처리 코드는 로컬 플레이어 Pawn에서 단계를 조회합니다.

### 카메라 셰이크

| 클래스 | 부모 | 역할 |
| - | - | - |
| `GC_CameraShake_Small/Medium/Large` | `UGameplayCueNotify_Burst` | 엔진 `BurstEffects.BurstCameraShake`로 해당 단계의 셰이크 에셋 재생 |
| `CS_Small/Medium/Large` | `UCameraShakeBase` | `UWaveOscillatorCameraShakePattern`에 흔들림의 축별 진폭·진동수, 지속 시간·페이드 저장 |

`AgCameraShake::Play`는 단계 열거형을 네이티브 큐 태그로 바꾸는 C++ 함수입니다. 피격 결과와 CameraShake Task가 이 함수를 사용합니다. 단계 선택은 호출부에서 끝내고, 큐는 해당 로컬 플레이어의 카메라에 재생합니다.

### 화면 후처리

| 클래스 | 부모 | 역할 |
| - | - | - |
| `UAgPostProcessComponent` | `UActorComponent` | 머티리얼·페이드 설정, MID와 엔진 후처리 컴포넌트 생성·정리, 실제 시간 재생 |
| `AAgGameplayCueNotify_Looping` | `AGameplayCueNotify_Looping` | 엔진 지속 연출 기능에 더해 화면 후처리를 시작·해제. `GC_UltimateScreen`의 부모 |
| `AAgGameplayCueNotify_BurstLatent` | `AGameplayCueNotify_BurstLatent` | 실행될 때 시간 서브시스템의 지금 슬로우모션 지속 시간 동안 화면 후처리 재생. `GC_PerfectDodgeScreen`의 부모 |

UE 5.8의 `UPostProcessComponent`는 프로젝트 DLL에서 상속하는 데 필요한 함수가 공개되어 있지 않습니다. 따라서 프로젝트 컴포넌트가 엔진 후처리 컴포넌트를 런타임에 생성해 소유합니다.
