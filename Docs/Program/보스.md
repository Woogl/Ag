# 보스

보스를 어떻게 구현할지 정합니다.

| 항목 | 결정 | 이유 |
| - | - | - |
| 패턴 | 2연격, 휩쓸기, 3연격, 뛰어 내려찍기는 공용 패턴 어빌리티(`UAgBossPattern_Common`) 하나로, 돌진 찌르기, 도약 내려찍기, 검기 발사, 백스텝은 각자의 어빌리티로 처리합니다. 패턴 ID는 `Boss.json`의 `Id`에 적는 문자열(`FName`)입니다. 몽타주와 패턴을 실행하는 어빌리티는 `DA_Boss`에서, 타별 공격 데이터와 쿨다운 시간은 `Boss.json`에서 패턴 ID로 찾습니다. 보스는 어빌리티를 부여할 때 스펙 핸들마다 패턴 ID를 기억합니다. 패턴별 쿨다운은 `UAgGameplayAbility`가 그 패턴 스펙의 어빌리티 인스턴스를 소스 오브젝트로 삼아 쿨다운 GameplayEffect(`UAgEffect_PatternCooldown`)를 적용하고, 그 소스로 GameplayEffect를 조회해 쿨다운 중인지 확인합니다. 쿨다운이 있는지는 쿨다운 시간(0이면 없음)이 정합니다. 공용 패턴은 공격 태스크([전투 규칙](<전투 규칙.md>) '공격 진행')로, 검기 발사는 공격 중 이동 태스크로 정지 간격과 접근을 지킵니다. 판정 구간 노티파이 앞의 회전 정지는 보스 캐릭터가 모든 패턴에 대해 맡고, 그런 노티파이가 없는 도약 내려찍기와 검기 발사는 그 어빌리티가 회전 정지 태그를 붙입니다('검기 발사 회전 정지', [애니메이션과 이동](<애니메이션과 이동.md>) '도약 내려찍기'). | 2연격, 휩쓸기, 3연격, 뛰어 내려찍기는 몽타주와 데이터만 다릅니다. 특수 패턴은 같은 태스크와 함수를 쓰고 돌진, 도약, 투사체, 백스텝만 더합니다([캐릭터와 GAS](<캐릭터와 GAS.md>) '어빌리티 구조'). 쿨다운 유무를 시간 하나로 정해, 쿨다운 GameplayEffect가 있는지와 시간이 어긋나지 않습니다. 패턴별 태그가 없어 패턴을 더할 때 C++를 고치지 않고 JSON과 DA만 고칩니다. |
| 2페이즈 | 보스 사양 '2페이즈 변화'의 배율을 몽타주 재생 속도와 패턴 중 이동 속도(돌진 찌르기의 돌진 속도, 도약 내려찍기의 체공 시간)에 곱합니다. MOV 배율은 걷기 속도에 곱합니다. 쿨다운은 그대로 둡니다. | |
| AI | 보스 AI의 흐름은 StateTree 에셋 `ST_Boss`의 상태와 전환으로 짜고, 보스 AI 컨트롤러의 StateTree AI 컴포넌트가 실행합니다. 상태는 패턴 후딜레이(레벨 시작·넉백·그로기·페이즈 전환 뒤의 고정 대기, 패턴 뒤의 대기), 패턴 실행, 다가가기, 백스텝, 페이즈 전환, 피격 반응, 비전투, 사망입니다. 태스크와 조건은 C++로 짜고 블루프린트 태스크는 쓰지 않으며, 대기 시간 같은 값은 에셋에 적지 않고 `Boss.json`에서 읽습니다. 보스 사양 '전투 시작과 행동 전환' 표의 전환은 상위 상태에 우선순위가 높은 전환으로 두어, 같은 프레임에 행동이 끝나도 표의 전환이 먼저 적용됩니다. 넉백, 그로기, 처형 피격, 페이즈 전환, 사망은 상태 어빌리티가 처리합니다. 넉백이나 그로기가 시작되면 피격 반응 상태에서 기다리고, 둘 다 끝나면 패턴 후딜레이로 넘어갑니다. 보스가 사망하면 사망 상태로 넘어가 엔진 Delay 태스크(계속 실행)로 머물며 더 전환하지 않습니다. 사망 전환은 루트가 아니라 전투, 피격 반응, 비전투에 둡니다. 루트에 두면 사망 상태에서도 매 틱 같은 상태로 다시 전환합니다. | 엔진이 권장하는 AI 구조라 상태와 전환을 에디터에서 한눈에 보고, 실행 중에는 StateTree 디버거로 따라갈 수 있습니다. 바뀐 내용은 에디터의 StateTree 비교 화면으로 리뷰합니다. 에셋에는 구조만 두고 계산은 C++에, 값은 JSON에 둡니다. |
| AI 대상 | 보스 AI 컨트롤러가 현재 대상을 정합니다. 지금은 플레이어입니다. AI 태스크와 조건, 보스 회전, 패턴(정지 간격, 접근, 돌진 찌르기의 돌진 방향, 도약 내려찍기의 착지 목표와 착지 판정)은 이 대상을 씁니다. 락온 마커·처형 안내의 표시와 도약 내려찍기의 착지 셰이크처럼 플레이어 화면에 관한 것은 로컬 플레이어를 기준으로 합니다. | 대상을 정하는 곳이 한 곳이라, 대상을 정하는 방식이 바뀌어도 AI와 패턴은 고치지 않습니다. |
| 패턴 선택 | 패턴 실행 상태의 C++ 태스크 하나가 후보를 모으고 가중치로 고른 뒤 그 패턴을 실행합니다. 후보가 없거나 시작하지 못하면 다가가기로 넘어가 재시도 간격 뒤 다시 고릅니다. | 패턴마다 상태를 만들지 않아 패턴 목록이 `Boss.json` 한 곳에만 있습니다. StateTree의 가중치 선택 기능은 패턴마다 상태가 필요합니다. |
| 백스텝 | 플레이어의 평타 각 타와 점프 공격의 시작 이벤트(`Event.BasicAttackStarted`)에 그 공격의 대상(타를 시작할 때 가장 가까운 적, 정지 간격의 대상)을 담습니다. 컨트롤러는 대상이 자기 보스인 이벤트만 StateTree 이벤트로 넘기고, 패턴 후딜레이 상태의 전환이 발동 조건과 확률을 검사합니다. 발동 조건과 백스텝 상태의 패턴 실행은 다른 패턴처럼 패턴 ID(`Backstep`)로 스펙을 찾으며, ID는 `ST_Boss`에서 파라미터로 넣습니다. 공격 패턴이 아니므로 모션 재생 속도는 받지 않지만 2페이즈 배율은 받습니다. 물러나는 거리는 모션의 루트 모션 전체 이동에 배율을 걸어 보스 사양 '백스텝'의 거리에 맞춥니다. 배율은 엔진 몽타주 태스크(`PlayMontageAndWait`)의 루트 모션 배율 인자로 넘기고, 태스크가 몽타주가 끝날 때 1로 되돌립니다. 끝나면 바로 다음 패턴을 고르되, 페이즈 전환 HP 구간이면 페이즈 전환이 먼저입니다. | 다른 적을 공격할 때는 검사하지 않습니다. 백스텝의 플레이어와의 거리(보스 사양 '백스텝')가 평타 타겟팅 범위보다 길어, 타겟팅 범위로 대상을 제한하면 범위 밖에서 백스텝하지 않게 됩니다. 보스 사양 '모션 재생 속도'는 공격 패턴에만 적용되고, '2페이즈 변화'의 패턴 진행 속도는 백스텝에도 적용됩니다. |
| 패턴 전조 동작 (2연격, 휩쓸기, 3연격 1타, 뛰어 내려찍기) | 몽타주에서 패턴 전조 동작 부분(2연격은 찌르기 전 자세를 잡는 부분과 내려찍기 전 창을 들어 올리는 부분, 휩쓸기는 창을 세워 드는 부분, 3연격 1타는 2연격 1타와 같은 부분, 뛰어 내려찍기는 뛰어올라 창을 머리 위로 치켜든 부분)을 느린 재생 속도의 별도 구간으로 나누고, 그 뒤의 노티파이를 늘어난 만큼 미룹니다. | 몽타주 시간 자체가 늘어나므로 판정 구간, 회전 정지, 접근(Motion Warping)이 모두 같은 기준으로 맞습니다. |
| 검기 발사 회전 정지 | 검기 발사 노티파이를 길이 없는 판정 구간으로 봅니다. 검기 발사 어빌리티가 발사 노티파이보다 회전 정지 시간만큼 앞선 몽타주 위치를 기다렸다가 회전 정지 태그를 붙이고, 발사하면 뗍니다. 검기는 발사하는 순간 보스 정면으로 날아갑니다. | 보스 사양 '검기 발사'는 발사 순간을 판정 구간으로 봅니다. 검기 발사만의 규칙이라 보스 캐릭터가 아니라 검기 발사 어빌리티가 맡습니다. |
| 넉백 | 보스도 플레이어와 같은 넉백 어빌리티를 받고, 넉백 몽타주만 각자의 캐릭터 데이터에서 읽습니다. 피격 반응 어빌리티는 진행 중인 보스 패턴도 취소하고, 패턴은 피격 반응 중에 시작하지 못하며, 플레이어와 보스 모두 피격 반응 중에는 회전하지 않습니다. 플레이어는 그동안 캐릭터 무브먼트의 이동 방향·카메라 방향 회전을 끕니다. 넉백 몽타주(`AM_Player_KnockBack`, `AM_Boss_KnockBack`)는 각 팩의 Hit_knockdown 하나로 쓰러짐과 기상을 재생하고, 시퀀스의 루트 모션을 켜 모션대로 물러납니다. 무적 시작 노티파이는 등이 바닥에 닿는 순간에 둡니다. | 넉백 규칙이 캐릭터마다 같아 어빌리티 하나로 처리합니다. 넉백 시퀀스(할버드 Hit3)는 다른 보스 모션처럼 루트 모션을 켭니다. |
| 비전투 | AI의 대상(플레이어)이 사망하면 AI가 비전투 상태로 넘어가 보스에게 비전투 태그를 붙이고 진행 중인 패턴을 취소합니다. 이 태그는 패턴, 그로기, 페이즈 전환을 막고 보스 회전을 멈춥니다. | 비전투 뒤에는 사망만 적용합니다. |
| 이동 | 다가가기와 좌우 걷기는 AI 태스크가 매 프레임 이동 입력을 직접 줍니다. NavMesh는 쓰지 않습니다. | 아레나가 장애물 없는 평지라 길찾기가 필요 없습니다. |
| 좌우 걷기 방향 | 패턴 후딜레이를 시작할 때마다 왼쪽과 오른쪽 중 무작위로 고릅니다. 패턴 후딜레이 대기 시간을 쓰는 모든 대기(레벨 시작, 넉백·페이즈 전환·그로기 뒤 포함)에서 걷습니다. | 기획서에 정해져 있지 않아 가장 단순한 방식을 씁니다. |
