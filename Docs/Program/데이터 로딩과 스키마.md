# 데이터 로딩과 스키마

기획서의 데이터(수치, 설정, 쓰는 에셋)는 주인이 분명한 곳에 둡니다. 각 데이터의 위치는 [데이터 위치표](<데이터 위치표.md>)에 정리합니다.

행동 정의의 형식은 아래 '행동'에 둡니다. 행동이 실행되는 구조와 Task 목록은 [어빌리티와 AbilityTask](<어빌리티와 AbilityTask.md>)를, 몽타주 안의 구간과 지점은 [몽타주 시간표](<몽타주 시간표.md>)를 따릅니다.

## 기술 결정

| 항목 | 결정 | 이유 |
| - | - | - |
| 형식 | 기획 데이터와 구현용 참조의 구분은 [AGENTS.md](<../../AGENTS.md>) 코딩 규칙을 따릅니다. 코드 전용 효과의 내부 구성은 [캐릭터 기반 구조와 GAS](<캐릭터 기반 구조와 GAS.md>) '코드가 효과를 쓰는 방법'에 따라 C++에서만 관리합니다. 전투 데이터를 담는 UE 에셋(DataAsset, DataTable, GE 블루프린트, TargetingPreset)과 GE C++ 클래스는 두지 않습니다. | 에셋 선택을 포함한 데이터 변경을 텍스트로 검토하고 병합합니다. |
| 파일 구성 | 종류마다 파일 하나를 둡니다(아래 '파일 구성'). JSON 밖의 제작 설정은 [데이터 위치표](<데이터 위치표.md>)에서 찾습니다. | 같은 종류의 정의를 한 파일에서 보고, 여러 캐릭터가 같은 어빌리티·효과 정의를 함께 씁니다. |
| 어빌리티 정의 | `Abilities.json`의 항목 하나가 행동 하나의 정의입니다(아래 '행동'). 모든 행동이 어빌리티 클래스 하나(`UAgGameplayAbility`)로 실행되므로 정의에 클래스 경로가 없습니다. Task 항목은 Task 이름(`Task`)과 그 Params의 필드로 적고, 선택 블록·선택 필드는 적었는지로 쓰는지를 구분합니다. | 있는 Task를 조합한 새 행동은 C++ 없이 JSON과 몽타주로 더하고, 클래스·구조체 타입 문자열을 데이터에 중복하지 않습니다. |
| 읽는 방법 | `UAgAssetManager`가 엔진 초기화(`StartInitialLoading`) 때 아래 '파일 구성'의 파일들을 같은 타입의 새 객체에 한 묶음으로 읽고, 모두 통과하면 기존 데이터 객체에 값을 복사합니다. ID로 가리켜지는 정의 파일을 먼저 읽습니다. JSON 효과와 대상 프리셋은 읽은 정의로 매번 새 객체(GE, TargetingPreset)를 만듭니다. 데이터가 가리키는 에셋(몽타주, 투사체 블루프린트)도 이때 읽혀, 패키지 게임은 타이틀 화면부터 두 캐릭터의 에셋을 메모리에 둡니다. | 기존 데이터 객체를 참조하는 코드가 새 값을 볼 수 있습니다. |
| 로더의 객체 이름 | `UAgAssetManager`가 만드는 로딩 후보 데이터, 효과(JSON·코드 전용), 대상 프리셋과 그 안의 Task는 이름을 지정하지 않고 엔진의 고유 이름을 사용합니다. 조회는 ID와 객체 참조로 하며, 자동 이름에 의존하지 않습니다. 생성자의 기본 서브오브젝트는 `CombatRules`, `Effects`처럼 고정된 역할 이름을 사용합니다. 이 규칙은 이 로더의 객체 생성에 적용합니다. | 종류가 다른 객체의 이름 충돌을 막고, 재로딩할 때 기존 GE를 같은 이름으로 다시 만들어 적용 중인 효과를 훼손하지 않습니다. |
| 검증 시점 | 검증은 읽기와 함께 합니다. 쿡에서도 `LoadJsonData`에 등록된 파일 전체의 최신 내용을 읽어, 하나라도 읽기 오류가 있으면 쿡과 패키징을 실패시킵니다. 검증한 JSON과 배포하는 JSON은 같아야 합니다. 정의 ID 검사는 에디터 전용 메타데이터를 쓰므로 패키징된 게임에서는 하지 않습니다. | 배포 전에 데이터 오류를 차단합니다. |
| 오류 검사 | 읽기 검사와 오류 출력은 JSON을 리플렉션으로 읽는 함수 하나(`UAgAssetManager::ReadJson`)가 맡고, 데이터 클래스와 Task에는 두지 않습니다. 검사 대상은 문법, 모르는 키, 엔진 변환(`FJsonObjectConverter`)이 받지 못한 값(형식, enum 이름), 없는 에셋·클래스·어트리뷰트, 등록되지 않은 태그, 없는 정의 ID, 적중 충전량(`HitReward`, 아래 '효과에 두는 값')의 범위입니다. 정의 ID 검사는 `DataId` 메타데이터가 있는 필드에 명시한 값만 해당 파일의 최상위 키와 대조합니다. 누락·null 처리는 아래 '기본값 작성'을 따릅니다. 오류는 파일명과 필드 경로로 로그·화면에 표시하고, 이전 정상 데이터 전체를 유지합니다. 최초 묶음 읽기에 실패한 상태에서는 캐릭터가 전투를 시작하지 않습니다. | 적중 충전량 밖의 값 범위나 필드 조합, 캐릭터별 몽타주 ID·섹션명과 실제 에셋의 대조까지 검사하지 않습니다. 읽기 성공이 모든 작성 규칙의 충족을 뜻하지는 않으며, 이런 항목은 데이터 검토와 플레이로 확인합니다. |
| 다시 읽기 | 에디터의 `UAgDataReloadSubsystem`이 `DesignData` 폴더 바로 아래 JSON의 변경을 감지해 등록된 파일 전체를 다시 읽습니다. 성공한 뒤 게임에서 사용하는 시점은 아래 '재로딩 반영 시점'을 따릅니다. 배열·맵 원소의 포인터·참조는 함수 안에서만 사용하고, 이후에는 ID로 다시 조회하거나 실행에 필요한 값을 복사합니다. 패키징 빌드와 커맨드렛은 파일을 감시하지 않습니다. | 에디터 재시작이나 C++ 빌드 없이 JSON을 고쳐 다시 플레이할 수 있습니다. |
| 패키징 | `Ag.Build.cs`의 `RuntimeDependencies`가 `DesignData/*.json`을 UFS에 넣습니다. 검증과 실패 처리는 '검증 시점'을 따릅니다. `ModifyCook`은 전투 규칙·투사체·몽타주 시간표·어빌리티·캐릭터 데이터의 객체 참조(Transient 포함)가 속한 패키지를 쿡 목록에 추가합니다. `/Script/`와 `/Engine/Transient` 패키지는 제외합니다. | JSON 문자열과 Transient 참조는 저장된 에셋 의존성이 아니므로 쿡 단계에 직접 전달해야 합니다. |
| 데이터를 찾는 방법 | 파일 이름과 그 파일을 읽는 클래스는 에셋 매니저에 정해 둡니다. 캐릭터 블루프린트는 `CharacterDataId`를 목록에서 고르며, 목록에는 그 캐릭터 클래스의 데이터 클래스에 맞는 ID만 나옵니다. 캐릭터는 컴포넌트를 초기화하기 전(`PreInitializeComponents`)에 한 번 확인하고(없거나 맞지 않으면 멈춤), 그 밖의 코드는 있다고 보고 씁니다. | 코드에 에셋 경로를 쓰지 않습니다. 확인을 한 곳에서 해, 쓰는 곳마다 데이터가 있는지 묻지 않습니다. 파일마다 그 파일을 읽는 클래스가 정해져 있어 이름을 바꿀 일이 없습니다. |
| 어빌리티의 데이터 | 부여는 [캐릭터 기반 구조와 GAS](<캐릭터 기반 구조와 GAS.md>) '어빌리티 목록'을 따릅니다. 각 스펙 인스턴스는 자기 ID의 정의와 재생하는 몽타주의 시간표를 복사하고, 발동 Task와 시간표 Task는 그 사본으로 만듭니다. 복사 시점과 ID로 참조하는 효과·투사체·프리셋의 조회 시점은 아래 '재로딩 반영 시점'을 따릅니다. | 행동 정의와 각 재생의 시간표가 사용 도중 바뀌지 않고, 클래스 CDO를 행동별 설정으로 덮지 않습니다. |

## 파일 구성

| 파일 | 내용 | 최상위 키 |
| - | - | - |
| `Characters.json` | 캐릭터마다 스탯, 쓰는 어빌리티 ID 목록(부여 순서), 시작할 때 거는 효과 ID 목록, 몽타주 ID별 에셋, 캐릭터 종류별 값(플레이어가 코드에서 거는 효과 ID 목록, 보스의 AI·페이즈 값) | 캐릭터 ID(`Player`, `Boss`) |
| `Abilities.json` | 행동 정의(아래 '행동'). 두 캐릭터가 함께 쓰는 정의(`KnockDown`, `KnockUp`, `Juggle`)는 하나입니다. | 어빌리티 ID |
| `Effects.json` | 기획자가 조정하는 GameplayEffect 정의 | 효과 ID |
| `Projectiles.json` | 투사체 클래스, 비행 값, 공격 값 | 투사체 ID |
| `MontageTimelines.json` | 몽타주 시간표([몽타주 시간표](<몽타주 시간표.md>)) | 몽타주 경로 |
| `TargetingPresets.json` | 대상 프리셋 정의([대상 찾기와 락온](<대상 찾기와 락온.md>) '대상 프리셋') | 프리셋 ID |
| `CombatRules.json` | 모든 캐릭터에 공통인 전투 규칙(히트스톱 시간, 가드의 SP 소모 포함) | 속성 이름 |

- 파일을 추가할 때는 `LoadJsonData`의 읽기 목록에도 등록합니다. `DesignData` 폴더에 JSON을 두는 것만으로 로딩·검증 대상이 되지는 않습니다.
- 현재 효과 데이터에는 외부 에셋 참조가 없고, 대상 프리셋은 네이티브 Task만 사용합니다. 이 데이터들에 에셋 참조를 추가하면 `ModifyCook`의 참조 수집 대상도 함께 확장해야 합니다.
- 에셋은 전체 객체 경로(`/Game/폴더/에셋.에셋`)로, 클래스는 네이티브 클래스 경로(`/Script/Ag.클래스`)나 생성 클래스 경로(`/Game/폴더/BP_Name.BP_Name_C`)로 적습니다.
- 빠진 키는 그 속성의 기본값입니다. 기본값의 명시·생략은 아래 '기본값 작성'을 따릅니다. 쓰지 않는 필드 몇 개 때문에 구조체를 나누지 않습니다.
- UPROPERTY는 맵 값으로 배열을 담지 못해, 배열이나 맵 하나만 가진 구조체로 감쌉니다. 이런 구조체는 감싸는 키 없이 그 배열이나 맵을 바로 적습니다(시간표의 섹션 맵, 대상 프리셋의 Task 배열).
- 캐릭터 ID와 데이터 클래스의 짝(`Player`는 `UAgPlayerData`, `Boss`는 `UAgBossData`)은 에셋 매니저 생성자에 적습니다. 항목의 형식을 데이터 클래스가 정하기 때문입니다. 캐릭터를 더할 때는 이 짝을 하나 더합니다. 등록된 항목에는 객체 또는 기본값을 뜻하는 null만 적을 수 있고, 문자열 참조로 데이터 객체를 바꿀 수 없습니다.
- 단일 게임플레이 태그 필드는 문자열로 적습니다. 빈 문자열은 빈 태그이고, null은 기본값입니다. 숫자·배열·객체·불리언은 형식 오류입니다.
- 태그 목록(`Tags`, `GrantedTags` 등)은 등록된 태그 문자열의 배열입니다. 빈 목록은 `[]`로 적으며, 배열 원소에 빈 문자열이나 null을 넣으면 오류입니다.
- 효과와 대상 프리셋의 ID는 파일별로 독립적이며, 조회에는 각 맵의 ID를 씁니다.
- PlayMontage의 몽타주 ID(`Montage`)는 그 행동을 쓰는 캐릭터의 `Montages`에서 찾습니다. 두 캐릭터가 같은 정의를 쓰면서 각자의 몽타주를 재생합니다.

```mermaid
flowchart LR
    BP["캐릭터 블루프린트<br>CharacterDataId"] --> C["Characters.json"]
    C -->|"Abilities"| A["Abilities.json"]
    C -->|"시작 효과, 패리·극한 회피 효과"| E["Effects.json"]
    A -->|"몽타주 ID"| C
    A -->|"ApplyEffect"| E
    A -->|"대상 프리셋 ID"| G["TargetingPresets.json"]
    C -->|"몽타주 경로"| T["MontageTimelines.json"]
    T -->|"ApplyEffect"| E
    T -->|"SpawnProjectile"| P["Projectiles.json"]
    K["C++ 호출부"] -->|"Damage, Resource, Cooldown,<br>Kill, Hitstop, PPRefill"| N["C++ 코드 전용 효과"]
```

## 기본값 작성

일반 필드는 기본값과 같은 값을 적거나 생략할 수 있습니다. 기획 의도를 드러내거나 항목을 비교하는 데 도움이 되면 기본값도 명시합니다.

- 읽을 때마다 새 객체·구조체의 기본값에서 시작합니다. 필드를 생략하거나 null로 적으면 그 기본값을 유지하며, 재로딩 전 값을 이어받는다는 뜻은 아닙니다. 모르는 키·미등록 캐릭터 ID는 값이 null이어도 오류입니다.
- `TOptional` 필드는 생략하거나 null로 적으면 설정하지 않은 상태입니다. 반면 `0`, `false`, `{}`처럼 값을 적으면 설정한 상태가 됩니다. 예를 들어 `"Targeting": {}`는 기본값으로 채운 대상 설정을 사용하고, `"Targeting": null`은 대상 설정을 사용하지 않습니다.

다음 항목은 값이 기본값과 같아도 명시합니다.

| 항목 | 명시할 필드 | 이유 |
| - | - | - |
| 플레이어 시작 자원 | `Characters.json`의 `Player.Attributes.MP`, `UP` | 시작 자원량을 데이터에서 바로 확인합니다. |
| 보스 일반 공격 패턴의 거리별 선택 가중치 | `Abilities.json`의 `PatternSelection.WeightNear`, `WeightMid`, `WeightFar` | 선택하지 않는 거리의 0도 표시해 세 거리의 가중치를 비교합니다. 반응형 행동인 Backstep에는 이 가중치를 추가하지 않습니다. |
| 공격의 가드 가능 여부 | `MontageTimelines.json`과 `Projectiles.json`의 모든 `Damage.bGuardable` | 매 타의 가드 가능·불가를 확인합니다. |
| RootMotion 추적 구간의 위치 보정 여부 | `MontageTimelines.json`에서 `Direction`이 Target인 RootMotion 구간의 `bWarpTranslation` | 위치 보정을 하는 구간과 회전만 하는 구간을 구분합니다. Direction의 기본값도 Target입니다. |

`StopDistance`, `ReleaseRange`, `TargetingRange`처럼 생략하면 상위 설정을 따르는 필드는 그 설정을 따를 때 계속 생략하고, 따로 정할 때만 명시합니다. `MaxDistance`처럼 생략이 제한 없음을 뜻하는 필드도 그 의미를 유지합니다. 위 명시 관례는 로딩 시 누락을 오류로 판정하는 조건이 아닙니다.

## 재로딩 반영 시점

묶음 읽기가 성공하면 보관 중인 데이터는 함께 바뀌지만, 이미 실행 중인 객체가 새 값을 사용하는 시점은 다음과 같습니다.

| 데이터 | 반영 시점 |
| - | - |
| 행동의 수치·대상 요청 조건·발동 Task | 다음 행동 발동 때 정의를 복사합니다. 실행 중인 행동은 기존 사본을 씁니다. |
| 캐릭터의 몽타주 ID별 에셋 | 새 PlayMontage Task가 시작하거나 캐릭터 코드가 몽타주 ID를 다시 조회할 때 적용합니다. 이미 재생 중인 몽타주를 강제로 교체하지 않습니다. |
| 몽타주 시간표 | PlayMontage가 재생을 시작할 때마다 복사합니다. 같은 행동 안에서도 BlendTime 전환으로 다시 재생하면 새 시간표를 씁니다. 같은 재생 안의 섹션 이동은 기존 시간표를 씁니다. |
| 대상 프리셋 | 다음 타겟팅 요청 때 ID로 다시 조회합니다. 실행 중인 행동도 대상을 다시 찾을 때 새 프리셋을 쓸 수 있습니다. |
| 투사체 정의 | SpawnProjectile이 쏠 때 조회해 클래스·비행 값·공격 값을 투사체에 넘깁니다. 이미 쏜 투사체는 쏠 때의 값을 씁니다. |
| JSON 효과 | 다음에 효과를 걸 때 새 GE를 씁니다. 이미 걸린 효과는 제거될 때까지 이전 GE를 유지합니다. |
| 행동 태그와 `Activation` | 캐릭터를 다시 만들 때 적용합니다. 현재 정의가 부여 당시 설정과 다르면 해당 행동의 새 발동을 거부합니다. |
| 캐릭터의 어빌리티 목록 | 스펙을 새로 부여하려면 캐릭터를 다시 만들어야 합니다. 다만 목록에서 뺀 행동은 정의 조회가 실패하므로 기존 캐릭터에서도 새로 발동할 수 없습니다. |
| 스탯·시작 효과·Yaw 회전 속도 등 스폰 설정 | 캐릭터를 다시 만들 때 적용합니다. 다음 플레이 시작도 이에 해당합니다. |
| 코드 전용 효과 | JSON 재로딩으로 다시 만들거나 교체하지 않습니다. |

## 행동

`Abilities.json`의 항목은 `FAgAbilityData`입니다. 각 필드가 실행에서 하는 일은 [어빌리티와 AbilityTask](<어빌리티와 AbilityTask.md>)를 따릅니다.

| 필드 | 뜻 | 엔진 |
| - | - | - |
| `Tags` | 행동 태그. 입력 계층·HUD·취소가 이 태그로 행동을 찾습니다. | 스펙의 `DynamicSpecSourceTags` |
| `Cooldown` | 쿨다운(초). 0이면 쿨다운 효과를 걸지 않습니다. | 쿨다운 효과(`Cooldown`)의 지속 시간 |
| `Activation` | 발동 조건: `RequiredTags`, `BlockedTags`, `OwnedTags`, `BlockTags`, `CancelTags`, `Triggers`, `bAllowRetrigger` | `ActivationRequiredTags`, `ActivationBlockedTags`, `ActivationOwnedTags`, `BlockAbilitiesWithTag`, `CancelAbilitiesWithTag`, 스펙의 `DynamicAbilityTriggers` |
| `Activation.Triggers` | `{"Tag", "Source"}`의 배열. `Source`는 `GameplayEvent`(기본, 그 이벤트를 받으면 발동)나 `OwnedTagPresent`(태그가 붙으면 발동하고, 떨어지면 엔진이 취소)입니다. | `FAbilityTriggerData` |
| `Cost` | 자원별 소모량: `SP`, `MP`, `UP`(예: `{"SP": 20}`). 적지 않은 자원은 소모하지 않습니다. | 자원 효과(`Resource`) |
| `Targeting` | 선택. 대상을 정하는 프리셋의 ID(`Preset`, `TargetingPresets.json`의 ID)와 요청 조건(`Range`, `TargetRequiredTags`, `TargetBlockedTags`, `bRequired`, `StopDistance`). `Range`를 뺀 조건은 선택입니다. | GameplayTargetingSystem |
| `End` | 행동이 끝나는 때. `Tasks`(기본, 행동의 Task가 모두 끝날 때)나 `TriggerTag`(`OwnedTagPresent` 트리거의 태그가 사라질 때) | |
| `Tasks` | 발동 동안 실행하는 Task의 배열. 항목은 `{"Task": 이름, Params의 필드}`입니다. 몽타주도 이 배열의 PlayMontage로 재생합니다. | `UAbilityTask` |
| `PatternSelection` | 선택. 보스 AI가 패턴을 고르는 값: `Phases`(1·2), `WeightNear`, `WeightMid`, `WeightFar`, `ResponseRange`, `ResponseChance`([보스 AI와 패턴](<보스 AI와 패턴.md>) '패턴 선택') | |

- 선택 블록은 그 행동이 쓸 때만 적습니다. `Targeting`의 `Range`는 기본 0이고, 0 이하이면 검색하지 않습니다. 후보 수집 범위도 이 값 하나로 정합니다. `StopDistance`를 적지 않으면 캐릭터의 `StopDistance`입니다.
- Task 이름과 Params의 필드, 선택 필드, 둘 수 있는 곳은 [어빌리티와 AbilityTask](<어빌리티와 AbilityTask.md>)의 '스키마와 등록'과 'Task 목록'을 따릅니다. 같은 Task를 시간표에 두는 형식은 [몽타주 시간표](<몽타주 시간표.md>)를 따릅니다.

## 효과

기획 값은 JSON에서 조정하고, 호출 코드와 맞아야 하는 효과의 내부 연결은 코드가 보장합니다.

### 형식

| 필드 | 뜻 | 엔진 |
| - | - | - |
| `DurationPolicy` | `Instant`, `HasDuration`, `Infinite`. 기본 `Instant` | `DurationPolicy` |
| `Duration` | `HasDuration`의 시간(초). | `DurationMagnitude` |
| `Modifiers` | 모디파이어 객체의 배열입니다. 각 항목에 `Attribute`를 적고, 크기는 `Value`(더할 고정 값), `PerSecond`(더할 초당 값), `Multiplier`(곱할 배율), `FromAttribute`(더할 대상의 다른 어트리뷰트) 중 하나로 지정합니다. `FromAttribute`에는 선택 `Coefficient`를 곱합니다(기본 1). 선택 `RequiredTags`, `IgnoredTags`는 그 모디파이어가 적용되는 대상 태그 조건입니다. 어트리뷰트는 `UAgAttributeSet`의 속성 이름(`SP`)으로 적습니다. | `Modifiers`, 크기의 `Coefficient`, 모디파이어의 `TargetTags` |
| `GrantedTags` | 걸려 있는 동안 대상에 붙는 태그 | 대상 태그 컴포넌트 |
| `OngoingIgnoredTags` | 걸려 있는 동안 대상에 있으면 효과가 꺼지는 태그 | 대상 태그 조건 컴포넌트 |
| `RegenDelay` | 선택. 회복 효과의 리젠 대기: `Effect`(대기 효과 ID), 선택 `EffectAtZero`(값이 0이 되었을 때의 대기 효과 ID) | 리젠 대기 컴포넌트([캐릭터 기반 구조와 GAS](<캐릭터 기반 구조와 GAS.md>) 'GameplayEffect') |
| `SlowMotionSpeed`, `SlowMotionDuration` | 선택. 실행될 때 거는 게임 전체 슬로우모션의 속도 배율(기본 1)과 실제 시간(초). Duration이 있을 때만 겁니다. 즉시 효과에 씁니다. | 슬로우모션 컴포넌트([전투 연출과 시간 제어](<전투 연출과 시간 제어.md>) '슬로우모션') |

- `PerSecond`가 있는 효과는 C++에서 주기 효과로 구성합니다. `AgEffectData.cpp`의 `PeriodicEffectInterval` 간격으로 실행하며, 적용 직후에는 실행하지 않고 중단됐다 재개되면 주기를 처음부터 셉니다(`ResetPeriod`). 이 실행 정책은 JSON에 노출하지 않습니다. 로더는 초당 값에 공통 간격을 곱해 한 번에 더할 값으로 넣습니다. 회복·소모량과 리젠 대기 시간은 JSON에서 관리합니다.
- 모디파이어의 태그 조건은 엔진이 즉시·주기 효과를 실행할 때마다 대상의 지금 태그로 판정합니다. 상태에 따라 양만 다른 회복(가드 중 SP 회복)은 효과를 나누지 않고 모디파이어 조건으로 나눕니다.
- 회복 효과는 대기 태그를 `OngoingIgnoredTags`에 두어 멈춥니다. `RegenDelay`가 대기를 다시 거는 동작은 [캐릭터 기반 구조와 GAS](<캐릭터 기반 구조와 GAS.md>)의 '리젠'을 따릅니다.
- `Multiplier`는 `PerSecond`와 한 효과에 두지 않습니다. 주기 효과의 모디파이어는 주기마다 기본값에 적용되므로 배율이 계속 곱해집니다.
- `Instant`에는 `PerSecond`, `GrantedTags`, 지속 조건을 쓰지 않습니다. `Duration`은 `HasDuration`에만 씁니다. 이 조합과 모디파이어 크기의 중복·누락은 작성할 때 확인하며, 로더가 검사하지 않습니다.
- 필드는 지금 효과들이 쓰는 것만 둡니다. 새 효과가 다른 GE 설정을 필요로 하면 그때 필드를 더합니다.
- GE 컴포넌트는 생성 코드가 `AddComponent<T>`로 붙입니다. JSON 효과의 리젠 대기·슬로우모션 컴포넌트는 클래스 경로 대신 `RegenDelay`·`SlowMotionDuration` 필드로 선택합니다. 대미지 계산기와 결과 처리 컴포넌트는 코드 전용 효과 생성부에서 직접 붙입니다.

### 효과에 두는 값

효과 정의에는 그 효과에서 하나로 정해진 값을 둡니다. 쓰는 곳마다 다른 값(공격 배율, 행동의 비용·쿨다운)은 시간표와 행동 정의에 두고, 적용할 때 SetByCaller와 지속 시간으로 넘깁니다. 적중 충전량은 피해를 주는 Task의 `HitReward`(`MP`·`UP`. 생략한 자원은 0이며, 적어도 하나는 양수이고 모두 유한한 0 이상 값)에 둡니다. 지급은 [대미지와 피격 처리](<대미지와 피격 처리.md>) '적중 충전'을 따릅니다. 한 행동만 쓰는 시간·보상·소모(패리 구간, 패리 보상과 공격자의 PP 감소 비율, 극한 회피, 회피 반격 기회, 그로기 시간, 달리기 소모)는 그 효과의 값이라 효과 정의에 둡니다.

## 몽타주 관리

몽타주 경로의 원본은 `Characters.json` 캐릭터 항목의 `Montages`입니다. PlayMontage의 `Montage`, 행동의 `DeathMontage`, 코드가 직접 재생하는 모션(`Jump`, `GuardFlinch`)은 이 ID를 가리키고 에셋 경로를 다시 적지 않습니다. 한 행동의 여러 모션은 ID를 나누지 않고 한 몽타주의 섹션으로 둡니다. ID는 에셋 파일 이름이 아니라 모션을 고르는 키라, 같은 ID에 캐릭터마다 다른 에셋을 둘 수 있습니다. 에셋을 옮기거나 이름을 바꾸면 JSON 경로와 그 몽타주 시간표의 키(몽타주 경로)도 함께 바꿉니다. 실제 ID와 에셋은 [데이터 위치표](<데이터 위치표.md>)를 따릅니다.

## 투사체 정의

`Projectiles.json`의 항목은 `FAgProjectileDefinition`이고, `ProjectileClass`, `Params`(`FAgProjectileParams`: Speed·Range), `Damage`(`FAgDamage`: HPMultiplier·PPMultiplier·HitReaction·bGuardable·bFinisher)으로 구성합니다. 속도·사거리는 양수입니다. 같은 클래스라도 비행 설정이나 공격 값이 다르면 별도 ID를 사용합니다.

몽타주 시간표의 SpawnProjectile 항목에는 발사 시각·투사체 ID·발사 소켓만 둡니다. 실제 데이터 위치는 [데이터 위치표](<데이터 위치표.md>), 생성 순서와 수명은 [전투 연출과 시간 제어](<전투 연출과 시간 제어.md>)를 따릅니다.
