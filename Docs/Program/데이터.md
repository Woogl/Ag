# 데이터

기획서의 데이터(수치, 설정, 쓰는 에셋)는 주인이 분명한 곳에 둡니다. 각 데이터의 위치는 [데이터 위치표](<데이터 위치표.md>)에 정리합니다.

| 항목 | 결정 | 이유 |
| - | - | - |
| 형식 | 기획서에 적힌 수치와 설정 가운데 기획자가 밸런싱하고 조절하는 값은 JSON 파일에 둡니다. 기획서에 없는 구현 값과 코드 연결(시작할 때 주는 어빌리티와 거는 리젠 GameplayEffect, 패턴을 실행하는 어빌리티, 코드가 읽는 본 이름)은 캐릭터 DataAsset에, 모든 캐릭터에 공통인 구현 값은 그 값을 쓰는 클래스(리젠 GameplayEffect의 주기, 사망 어빌리티의 래그돌 밀림 속도)에 둡니다. 몽타주처럼 Content의 에셋을 가리키는 참조는 DataAsset에 둡니다. 엔진 컴포넌트와 애님 노드의 설정(스프링 암과 카메라, 블렌드 노드의 블렌드 시간, 충돌 상자의 크기, 무기 컴포넌트의 메시와 붙이는 소켓)은 JSON에 두지 않고 그 블루프린트에 직접 적습니다. 데이터 하나는 이 가운데 한 곳에만 있습니다. | 작업은 AI가 하고 사람은 판단하고 리뷰합니다. JSON은 에디터 없이 읽고 고칠 수 있고, 바뀐 수치가 커밋 diff에 보이며, 두 사람이 같은 파일을 고쳐도 병합됩니다. 에셋 참조는 DataAsset에 있어야 에셋 이름을 바꾸거나 옮길 때 엔진이 따라 고치고, 패키징할 때 쿡에서 빠지지 않습니다. 엔진 설정을 JSON에 두면 코드가 그 값을 엔진에 다시 넣어야 하고, 블루프린트에 보이는 값과 실제 값이 달라집니다. JSON은 기획자가 AI를 시켜 값만 고쳐 바로 플레이해 보는 곳이라, 기획서에 있는 값만 둡니다. |
| 묶는 단위 | 캐릭터마다 JSON 하나와 DataAsset 하나(`Player.json`과 `DA_Player`, `Boss.json`과 `DA_Boss`)를 두고, 모든 캐릭터에 공통인 규칙은 `CombatRules.json`에, 락온 카메라와 셰이크의 상황별 단계는 `Camera.json`에 둡니다. 셰이크 단계별 값은 카메라 셰이크 에셋 3개에, 이펙트와 효과음은 GameplayCue 에셋에, 공격 예고가 켜지는 구간은 보스 패턴 몽타주의 노티파이에, 화면의 크기·배치·표시 시간은 위젯에, 글자 크기 단계는 CommonUI 글자 스타일에 둡니다. | 한 캐릭터의 수치를 파일 하나에서 모두 볼 수 있습니다. |
| JSON 파일 | 프로젝트 폴더의 `Data`에 둡니다. 키는 C++ 필드 이름 그대로 쓰고, 모든 필드를 빠짐없이 적습니다. 게임플레이 태그는 태그 이름으로, 열거형은 값 이름으로 적습니다. MP·UP 충전은 플레이어 공격에만 있고, 그 밖의 공격 데이터는 플레이어와 보스가 같은 필드를 씁니다. 그 캐릭터가 쓰지 않는 필드(보스 공격의 PP 배율, 플레이어 공격의 가드·패리 가능, 플레이어의 PP)도 기본값으로 적습니다. | `Content`에 두면 에디터가 JSON을 에셋으로 가져오려 합니다. 기획서, 데이터 위치표, 코드, JSON의 이름이 같아 대조하기 쉽습니다. 쓰지 않는 필드 몇 개 때문에 구조체를 나누지 않습니다. |
| 읽는 방법 | JSON은 프로젝트의 에셋 매니저(`UAgAssetManager`)가 읽습니다. 캐릭터 DataAsset은 로드될 때 에셋 매니저에 자기 JSON(`ValuesFile`)을 넘겨 같은 객체의 Transient 필드를 채웁니다. 공통 JSON은 에셋 매니저가 엔진 초기화 때(`StartInitialLoading`) 자기가 가진 공통 데이터 객체(`UAgCombatRules`, `UAgCameraData` 하나씩)에 읽고, 코드는 이 객체를 에셋 매니저에서 받아 씁니다. 대상 찾기 프리셋(`TP_Enemy`)은 `DA_Player`가 가리킵니다. | 에셋 매니저는 게임 전체가 쓰는 데이터를 엔진 초기화 때 읽도록 엔진이 열어 둔 확장 지점이고(Lyra 샘플도 게임 데이터를 여기서 읽습니다), 에디터·쿡·패키징 빌드에 모두 있습니다. 엔진이 GC 제외 객체 풀을 닫은 뒤에 만들어 엔진 객체의 UPROPERTY로 들고 있으므로, 에셋 매니저가 UPROPERTY로 든 공통 데이터 객체도 GC가 따라갑니다([기본 방침](<기본 방침.md>) '객체 수명'). 값을 쓰는 코드는 값이 어느 파일에서 왔는지 몰라도 됩니다. 게임 중에는 파일을 읽지 않습니다. |
| 오류 검사 | 읽을 때 문법, 모르는 키, 빠진 키, 값의 형식, 없는 태그·열거형 값, 정수 필드의 소수를 검사하고, 에디터에서는 필드의 허용 범위(배열 원소는 배열 필드의 범위)도 검사합니다. 키는 대소문자를 구분하지 않습니다. 오류가 있으면 그 파일의 값을 하나도 바꾸지 않고 로그와 화면에 띄웁니다. | 엔진의 JSON 변환기는 모르는 키를 무시하고 빠진 키도 다 잡지 못해, 오타가 조용히 기본값이 됩니다. 엔진의 이름(FName)과 JSON 객체도 키의 대소문자를 구분하지 않고, 패키징 빌드의 필드 이름은 대소문자를 보존하지 않습니다(예: `UP`이 `Up`으로 나옴). |
| 다시 읽기 | 에디터는 `Data` 폴더를 지켜보다가 JSON이 저장되면 그 파일을 다시 읽습니다. 쓸 때마다 읽는 값(리젠 회복량, HUD의 보스 이름 포함)은 다음 동작부터 바뀌고, 스폰할 때 넣는 값인 스탯은 PIE를 다시 시작해야 바뀝니다. DataAsset의 값은 에디터에서 고치면, 쓸 때마다 읽는 값은 바로 바뀌고 스폰할 때 넣는 값은 다음 PIE부터 바뀝니다. DataAsset 편집을 실행 취소하거나 다시 실행하면 그 DataAsset의 JSON을 다시 읽습니다. 패키징 빌드는 시작할 때 한 번만 읽습니다. 데이터 배열의 원소(패턴, 타격 데이터)를 가리키는 포인터나 참조는 그 함수 안에서만 쓰고, 나중에 쓸 값은 복사해 두거나 키(패턴 ID, 타 번호)로 다시 찾습니다. | 컴파일 없이 PIE 중에 수치를 바꿔 볼 수 있습니다. 스탯을 다시 넣으면 HP가 처음 값으로 돌아가 싸움이 초기화됩니다. 다시 읽으면 배열의 원소를 새로 만들고 원소 수가 바뀌면 배열이 다른 메모리로 옮겨지므로, 원소를 가리킨 채 다음 프레임까지 들고 있으면 해제된 메모리를 읽어 에디터가 크래시합니다. |
| 패키징 | `Data`의 JSON은 빌드 규칙(`RuntimeDependencies`)으로 pak에 넣습니다. | `Content` 밖의 파일은 쿡이 모릅니다. |
| 데이터를 찾는 방법 | 공통 JSON은 에셋 매니저가 정한 파일 이름(`CombatRules.json`, `Camera.json`)으로 읽고, 캐릭터 DataAsset은 캐릭터 블루프린트에서 가리킵니다. 캐릭터 블루프린트에는 데이터만 넣고 이벤트 그래프는 쓰지 않습니다. 캐릭터 DataAsset은 필수라, 캐릭터가 시작할 때 한 번 확인하고(없으면 멈춤) 그 밖의 코드는 있다고 보고 씁니다. | 코드에 에셋 경로를 쓰지 않습니다. 공통 JSON 파일은 그 파일을 읽는 클래스와 짝이라 이름을 바꿀 일이 없습니다. |
| 어빌리티의 데이터 | 어빌리티는 C++ 클래스만 두고, 몽타주와 수치는 캐릭터 데이터의 해당 항목(예: 평타 1타)에서 읽습니다. | 캐릭터의 데이터가 JSON 하나와 DataAsset 하나에 모입니다. |
