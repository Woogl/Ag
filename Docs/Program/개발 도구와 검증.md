# 개발 도구와 검증

개발 도구와 검증 방법을 정합니다.

## 기술 결정

| 항목 | 결정 | 이유 |
| - | - | - |
| 테스트용 콘솔 명령 | 개발 빌드에만 둡니다. 보스·플레이어를 사망시키는 명령(`AgKillBoss`, `AgKillPlayer`)입니다. 그 밖의 상황(그로기, 자원, 무적)은 테스트 창이나 PIE에서 파이썬으로 만듭니다('에디터 파이썬 원격 실행'). | 단계별 동작 테스트와 직접 플레이에서 결과 UI를 빠르게 확인합니다. 플레이어에게 보이는 기능이 아닌 개발 도구입니다. |
| 확인용 입력 | 플레이어 캐릭터에 에디터 전용 속성(`DevPressInput`, `DevMashInput`, `DevHoldInput`, `DevMoveInput`)을 둡니다. 테스트 창이나 PIE에서 파이썬으로 값을 넣으면 키를 누른 것과 같이 처리합니다. | AI가 키보드 없이 행동을 확인합니다. 에디터 빌드에만 있어 게임에는 들어가지 않습니다. |
| 프로젝트 MCP 도구 | 엔진 MCP 도구와 에디터 파이썬으로 바꿀 수 없는 설정(몽타주 섹션, 몽타주 구간과 구간별 재생 속도, 슬롯 그룹, 위젯 애니메이션, 블루프린트 컴포넌트의 Parent Socket, StateTree 에셋의 생성과 상태·태스크·전환 편집과 컴파일)을 바꾸는 도구를 에디터 전용 모듈 `AgEditor`의 `UAgAssetToolset`에 둡니다. 엔진 MCP에 툴셋으로 등록해, AI가 열린 에디터에서 다른 MCP 도구처럼 부릅니다. 엔진 도구로 할 수 있는 일은 이 툴셋에 두지 않습니다. StateTree 에셋을 읽을 때는 엔진의 StateTree 조회 도구를 쓰고, 스키마의 속성은 엔진의 `set_properties`로 스키마 객체에 씁니다. | 몽타주처럼 반복되는 에셋 작업을 AI가 처리합니다. ([마일스톤1 구현 계획](<마일스톤1 구현 계획.md>) '위험 요소'의 에디터 작업량) 엔진에 들어 있는 MCP 도구에는 이 기능이 없습니다. 엔진의 StateTree MCP 도구는 조회만 하고, StateTree 편집 함수는 C++ 에디터 API에만 있습니다. 게임 모듈에는 게임 코드만 둡니다. |
| 에디터 파이썬 원격 실행 | Python 플러그인(에디터 전용)과 원격 실행(`DefaultEngine.ini`)을 켭니다. AI가 열린 에디터에서 파이썬으로 에셋을 고치고, 테스트 창('동작 테스트 실행')과 PIE를 파이썬으로 조종합니다. 원격 실행은 엔진 기본 설정대로 이 PC 안에서만 열립니다. | 에셋 작업마다 에디터를 닫고 헤드리스로 처리하지 않아도 되고, 에디터 도구(MCP)로 읽거나 바꿀 수 없는 값(몽타주 노티파이, 배열 등)도 다룰 수 있습니다. |
| 동작 테스트 실행 | AI는 테스트 창이나 PIE, 패키지 게임을 띄우기 직전에 무엇을, 창 몇 개로, 얼마나 확인할지 사람에게 묻고 답을 받은 뒤 시작합니다. 작업 계획을 승인받은 것은 이 물음을 대신하지 않습니다. 테스트는 공유 에디터의 PIE 대신 테스트마다 게임 창(별도 프로세스)을 하나씩 띄워 확인합니다. 실행은 `Scripts/ScenarioTest`를 씁니다(쓰는 법은 폴더의 README). 창은 낮은 그래픽 품질과 60fps 제한으로 띄우고, 창 제목과 화면 안내 글자로 무엇을 확인하는지 보여 줍니다. 창은 사람의 입력을 받지 않습니다. 창마다 원격 실행 포트를 따로 쓰고, 값은 그 창의 메모리에서만 바꿉니다. 테스트 때문에 `Data` JSON을 고쳐야 하면(예: 로더의 오류 검사) 먼저 묻습니다. 테스트가 끝나면 결과와 로그를 확인하고 창을 닫은 뒤, 결과 보고 전에 이번 테스트에서 추가한 임시 코드·시나리오 파일을 정리하고 임시로 바꾼 설정을 복원합니다. 실행을 취소하거나 테스트가 실패한 경우에도 같은 정리를 수행합니다. 공용 테스트 도구와 정식 자동화 테스트는 유지합니다. 결과 보고는 [AI 워크플로우](<../AI 워크플로우.md>)의 '테스트 작업'을 따릅니다. 테스트 창으로 확인할 수 없는 것(타이틀 화면, 메뉴 조작, 소리)은 PIE에서 확인합니다. | 사람이 직접 플레이해 확인하는 편이 나을 때가 있습니다. 에디터 하나에는 PIE가 하나뿐이라 여러 AI가 동시에 확인할 수 없습니다. 창으로 띄우면 사람이 진행을 지켜볼 수 있고, 지켜보다 창을 눌러도 테스트에 섞이지 않습니다. 프레임을 고정해야 공격 판정 같은 타이밍 확인을 믿을 수 있습니다. `Data` JSON은 모든 창과 에디터가 함께 읽습니다. 떠 있는 창은 프로젝트 DLL을 잡아 빌드를 막습니다. |
| PIE 마우스 포커스 | 에디터 플레이 설정 'Game Gets Mouse Control'을 켭니다(`DefaultEditorPerProjectUserSettings.ini`). PIE가 시작하면 게임 뷰포트가 포커스를 가져가고, 보스 스테이지에서는 마우스를 바로 잡습니다(Shift+F1로 풀림). | 꺼져 있으면 PIE가 뷰포트 포커스 없이 시작하는데, CommonUI는 에디터에서만 이때 화면의 입력 설정(커서, 마우스 캡처)과 첫 포커스를 건너뛰고 다시 적용하지 않습니다. 그러면 타이틀에서 빈 곳을 클릭할 때 뷰포트가 마우스를 잡아 커서가 사라집니다. 에디터 설정이라 패키지 게임에는 영향이 없습니다. |
| [데이터 위치표](<데이터 위치표.md>) | 데이터 필드(JSON, DataAsset)를 코드로 만들 때마다 행을 추가하고, 코드 리뷰 때 표와 대조합니다. | 실제 필드 이름과 항상 맞습니다. |
| 클래스 구조 | 클래스를 더하거나 빼거나, 클래스의 역할이나 클래스 사이의 관계를 바꾸면 그 클래스가 속한 주제 문서의 '클래스 구조'도 함께 고칩니다. | |

## 클래스 구조

### 에디터 도구

| 클래스 | 부모 | 역할 |
| - | - | - |
| `UAgAssetToolset` | `UToolsetDefinition` | 프로젝트 MCP 도구 (에디터 전용 모듈 `AgEditor`) |
| `UAgDataReloadSubsystem` | `UEditorSubsystem` | `Data` 폴더를 지켜보다가 저장된 JSON을 에셋 매니저에 다시 읽게 합니다 (에디터 전용 모듈 `AgEditor`) |

고정 기능 Params·공용 몽타주 Task·투사체 연결의 에디터 데이터 검사는 `UAgMontageTaskValidator`가 맡습니다. `Ag.Tasks.DataAndAssets`는 JSON 오류와 실제 에셋 연결을, `Ag.Tasks.Ownership`은 게임 플레이를 시작하지 않는 임시 월드에서 태그·충돌·시간 정지 Task의 소유권과 재진입 정리를 검사합니다. `Ag.Tasks.Dash`는 게임 플레이 없이 임시 월드에서 돌진 태스크의 유도 회전 제한·일정 속도·직선 모드·대상 소멸·누적 거리·벽 막힘·취소와 보스 JSON 연결을 검사합니다. `Ag.Tasks.FixedSchema`는 고정 스키마와 설계안 JSON 블록을, `Ag.Tasks.AbilityExecution`은 BeginPlay 없는 임시 월드에서 실제 스펙 부여·비용·실행 사본·재진입·공격 구간·달리기 소모·회피 첫 프레임 보호를 검사합니다. 충돌 검사는 순차 실행·중복 종료·다른 채널의 독립 복원·대상 소멸·적용 및 복원 콜백 중 재진입을 포함하며, 동일 채널 구간 중복은 에셋 검증에서 검사합니다. Ability 실행 검사는 워핑 종료·블렌드 아웃 중 이동 제약 유지, 취소·늦은 해제, 최소 간격과 물리 속도 적용도 확인합니다. 공격 검사는 Task별 적중 기록·무적 대상 중복 억제·진입 즉시 판정·단발 중복 대상·늦은 틱·피해 콜백 중 Task 및 Ability 취소와 틱 해제를 포함합니다. 비용 검사는 세 자원의 독립 차감·비용 없음·실행 사본을, 알림 검사는 첫 프레임·동기 취소·재생 교체·늦은 알림과 구독 해제를 포함합니다. 실제 전투 동작 확인은 위 동작 테스트 실행 절차를 따릅니다.

GameplayCue 검사는 `Ag.Cues.Registration`이 8개 태그가 `/Game/GameplayCues`의 큐 블루프린트로 등록되고 각 블루프린트의 부모가 맞는지 확인합니다. `Ag.Cues.SlashLifetime`은 BeginPlay·Tick 없이 임시 월드에서 베기 선 견본의 복제·위치·방향·Remove·재사용 정리를 확인합니다. 화면·소리와 실제 전투 수명 검증은 동작 테스트 실행 절차를 따릅니다.

`Ag.Tasks.AbilityExecution`은 태그·시간 정지 Task의 Activate 콜백에서 실제 소유 Ability가 취소되는 경우의 복원도 검사합니다. `Ag.Combat.ProjectileEffect`는 발사 Ability가 제거된 뒤의 투사체 피해, 스펙 태그·출처 보존, 적중 시점의 ATK 재캡처, 대상별 결과·적중 위치의 분리를 검사합니다.
