# 개발 도구와 검증

개발 도구와 검증 방법을 정합니다.

## 기술 결정

| 항목 | 결정 | 이유 |
| - | - | - |
| 테스트용 콘솔 명령 | 개발 빌드에만 둡니다. 보스·플레이어를 사망시키는 명령(`AgKillBoss`, `AgKillPlayer`)입니다. 그 밖의 상황(그로기, 자원, 무적)은 테스트 창이나 PIE에서 파이썬으로 만듭니다('에디터 파이썬 원격 실행'). | 단계별 동작 테스트와 직접 플레이에서 결과 UI를 빠르게 확인합니다. 플레이어에게 보이는 기능이 아닌 개발 도구입니다. |
| 확인용 입력 | 플레이어 캐릭터에 에디터 전용 속성(`DevPressInput`, `DevMashInput`, `DevHoldInput`, `DevMoveInput`)을 둡니다. 테스트 창이나 PIE에서 파이썬으로 값을 넣으면 키를 누른 것과 같이 처리합니다. `DevPressInput`은 누른 다음 프레임에 떼어, 엔진 점프가 시작될 틈을 줍니다. | AI가 키보드 없이 행동을 확인합니다. 에디터 빌드에만 있어 게임에는 들어가지 않습니다. |
| 프로젝트 MCP 도구 | 엔진 MCP 도구와 에디터 파이썬으로 바꿀 수 없는 설정(몽타주 섹션, 몽타주 구간과 구간별 재생 속도, 슬롯 그룹, 위젯 애니메이션, 블루프린트 컴포넌트의 Parent Socket, 나이아가라 시스템의 사용자 파라미터, StateTree 에셋의 생성과 상태·태스크·전환 편집과 컴파일)을 바꾸는 도구를 에디터 전용 모듈 `AgEditor`의 `UAgAssetToolset`에 둡니다. 엔진 MCP에 툴셋으로 등록해, AI가 열린 에디터에서 다른 MCP 도구처럼 부릅니다. 엔진 도구로 할 수 있는 일은 이 툴셋에 두지 않습니다. StateTree 에셋을 읽을 때는 엔진의 StateTree 조회 도구를 쓰고, 스키마의 속성은 엔진의 `set_properties`로 스키마 객체에 씁니다. | 몽타주처럼 반복되는 에셋 작업을 AI가 처리합니다. 엔진에 들어 있는 MCP 도구에는 이 기능이 없습니다. 엔진의 StateTree MCP 도구는 조회만 하고, StateTree 편집 함수는 C++ 에디터 API에만 있습니다. 나이아가라 시스템의 사용자 파라미터도 파이썬과 MCP로 읽거나 더할 수 없습니다. 게임 모듈에는 게임 코드만 둡니다. |
| 에디터 파이썬 원격 실행 | Python 플러그인(에디터 전용)과 원격 실행(`DefaultEngine.ini`)을 켭니다. AI가 열린 에디터에서 파이썬으로 에셋을 고치고, 테스트 창('동작 테스트 실행')과 PIE를 파이썬으로 조종합니다. 원격 실행은 엔진 기본 설정대로 이 PC 안에서만 열립니다. | 에셋 작업마다 에디터를 닫고 헤드리스로 처리하지 않아도 되고, 에디터 도구(MCP)로 읽거나 바꿀 수 없는 값(몽타주 노티파이, 배열 등)도 다룰 수 있습니다. |
| 동작 테스트 실행 | AI는 테스트 창이나 PIE, 패키지 게임을 띄우기 직전에 무엇을, 창 몇 개로, 얼마나 확인할지 사람에게 묻고 답을 받은 뒤 시작합니다. 작업 계획을 승인받은 것은 이 물음을 대신하지 않습니다. 테스트는 공유 에디터의 PIE 대신 테스트마다 게임 창(별도 프로세스)을 하나씩 띄워 확인합니다. 실행은 `Scripts/ScenarioTest`를 씁니다(쓰는 법은 폴더의 README). 창은 낮은 그래픽 품질과 60fps 제한으로 띄우고, 창 제목과 화면 안내 글자로 무엇을 확인하는지 보여 줍니다. 창은 사람의 입력을 받지 않습니다. 창마다 원격 실행 포트를 따로 쓰고, 값은 그 창의 메모리에서만 바꿉니다. 테스트 때문에 `Data` JSON을 고쳐야 하면(예: 로더의 오류 검사) 먼저 묻습니다. 테스트가 끝나면 결과와 로그를 확인하고 창을 닫은 뒤, 결과 보고 전에 이번 테스트에서 추가한 임시 코드·시나리오 파일을 정리하고 임시로 바꾼 설정을 복원합니다. 실행을 취소하거나 테스트가 실패한 경우에도 같은 정리를 수행합니다. 공용 테스트 도구(`Scripts/ScenarioTest`)는 유지합니다. 결과 보고는 [AI 워크플로우](<../AI 워크플로우.md>)의 '테스트 작업'을 따릅니다. 테스트 창으로 확인할 수 없는 것(타이틀 화면, 메뉴 조작, 소리)은 PIE에서 확인합니다. | 사람이 직접 플레이해 확인하는 편이 나을 때가 있습니다. 에디터 하나에는 PIE가 하나뿐이라 여러 AI가 동시에 확인할 수 없습니다. 창으로 띄우면 사람이 진행을 지켜볼 수 있고, 지켜보다 창을 눌러도 테스트에 섞이지 않습니다. 프레임을 고정해야 공격 판정 같은 타이밍 확인을 믿을 수 있습니다. `Data` JSON은 모든 창과 에디터가 함께 읽습니다. 떠 있는 창은 프로젝트 DLL을 잡아 빌드를 막습니다. |
| PIE 마우스 포커스 | 에디터 플레이 설정 'Game Gets Mouse Control'을 켭니다(`DefaultEditorPerProjectUserSettings.ini`). PIE가 시작하면 게임 뷰포트가 포커스를 가져가고, 보스 스테이지에서는 마우스를 바로 잡습니다(Shift+F1로 풀림). | 꺼져 있으면 PIE가 뷰포트 포커스 없이 시작하는데, CommonUI는 에디터에서만 이때 화면의 입력 설정(커서, 마우스 캡처)과 첫 포커스를 건너뛰고 다시 적용하지 않습니다. 그러면 타이틀에서 빈 곳을 클릭할 때 뷰포트가 마우스를 잡아 커서가 사라집니다. 에디터 설정이라 패키지 게임에는 영향이 없습니다. |
| 클래스 구조 | 클래스를 더하거나 빼거나, 클래스의 역할이나 클래스 사이의 관계를 바꾸면 그 클래스가 속한 주제 문서의 '클래스 구조'도 함께 고칩니다. | |

## C++ 포매터

자동 포맷의 정본은 루트 [`.clang-format`](<../../.clang-format>)입니다. [Epic C++ 코딩 표준](https://dev.epicgames.com/documentation/en-us/unreal-engine/epic-cplusplus-coding-standard-for-unreal-engine)의 코드 배치(탭 들여쓰기, 새 줄 중괄호, 한 문장 블록의 중괄호)와 엔진에 들어 있는 Epic 설정(`Engine/Source/Runtime/AutoRTFM/.clang-format`)을 기준으로 하며, 문서에서 정하지 않은 선택은 설정 파일에 둡니다. 옵션 의미는 [LLVM 문서](https://clang.llvm.org/docs/ClangFormatStyleOptions.html)를 참고합니다.

줄 길이 제한은 두지 않습니다(`ColumnLimit: 0`). 함수 선언을 한 줄로 두기 위해서입니다. 포매터는 작성한 줄바꿈을 유지하고 들여쓰기만 맞추므로, 한 줄 선언과 `.cpp` 정의 순서([AGENTS.md](<../../AGENTS.md>) 코딩 규칙 7)는 포매터가 아니라 작성할 때 지킵니다.

실행 진입점은 [`Scripts/FormatCpp.ps1`](<../../Scripts/FormatCpp.ps1>)이며, 기준 도구 버전은 스크립트의 `RequiredVersion` 한 곳에서 관리합니다. PATH의 clang-format, 없으면 Visual Studio의 x64 LLVM 도구를 찾습니다. 버전이 다르거나 설치되지 않았으면 중단합니다. 필요한 버전의 실행 파일을 `-ClangFormat '절대 경로/clang-format.exe'`로 지정할 수 있습니다.

프로젝트 루트에서 실행합니다. 기본값은 파일을 바꾸지 않는 검사이고, `-Write`로 적용합니다. `-Files`를 생략하면 `Source/Ag`, `Source/AgEditor`의 모든 `.h`·`.cpp`를 대상으로 합니다. 상대 파일 경로는 프로젝트 루트 기준입니다.

```powershell
# 전체 검사
powershell -NoProfile -ExecutionPolicy Bypass -File Scripts/FormatCpp.ps1

# 수정한 파일만 적용하고 검사 (PowerShell에서 실행)
& ./Scripts/FormatCpp.ps1 -Write -Files 'Source/Ag/Ag.cpp', 'Source/Ag/Ag.h'
& ./Scripts/FormatCpp.ps1 -Files 'Source/Ag/Ag.cpp', 'Source/Ag/Ag.h'
```

종료 코드는 성공 0, 포맷 불일치·포매터 실패 1, 경로·버전·실행 준비 오류 2입니다. IDE도 같은 실행 파일과 루트 설정을 사용하며, 최종 판정은 이 스크립트의 검사로 합니다. IDE 별도 스타일 설정을 정본으로 두지 않습니다.

include 순서는 보존하여 `.generated.h`와 기존 의존 관계를 유지합니다. UE 리플렉션 매크로와 `GENERATED_BODY`는 독립된 문장으로 취급합니다. 단일 제어문에도 중괄호를 추가하므로 적용 후 diff를 검토합니다. 전처리기·매크로 문맥에서는 자동 중괄호 삽입에 한계가 있어 직접 확인합니다.

이 도구는 코드 배치만 다룹니다. 타입 이름, 저작권 문구, `auto` 사용 범위, JSON 단일 정본, 한 줄 선언과 `.cpp` 정의 순서 등 의미를 판단하는 규칙은 [AGENTS.md](<../../AGENTS.md>)와 코드 리뷰로 확인합니다. 기존 코드 전체를 일괄 적용할 때는 기능 변경과 분리해 diff를 검토합니다.

## 클래스 구조

### 에디터 도구

| 클래스 | 부모 | 역할 |
| - | - | - |
| `UAgAssetToolset` | `UToolsetDefinition` | 프로젝트 MCP 도구 (에디터 전용 모듈 `AgEditor`) |
| `UAgDataReloadSubsystem` | `UEditorSubsystem` | `Data` 폴더를 지켜보다가 저장된 JSON을 에셋 매니저에 다시 읽게 합니다 (에디터 전용 모듈 `AgEditor`) |

데이터 검사는 `UAgAssetManager`가 JSON을 읽을 때 합니다([JSON 데이터](<JSON 데이터.md>) '오류 검사'). 실제 전투 동작은 위 '동작 테스트 실행' 절차로 확인합니다.
