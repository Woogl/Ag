# 마일스톤1 구현 계획

마일스톤1 기획서를 어떻게 구현할지 정합니다. 기술 결정, 클래스 구조, 에셋 목록, 데이터 위치표, 작업 순서를 이 문서 한 곳에 적습니다.

무엇을 만들지는 `Docs/Design`의 기획서를, 작업 방식은 [AI 워크플로우](<../AI 워크플로우.md>)를 따릅니다. 기간과 목표는 [마일스톤1 계획](<../Design/마일스톤1 계획.md>)을, 용어는 [용어집](<../용어집.md>)을 따릅니다.

## 범위와 완료 기준

- 기획서의 모든 항목을 구현 우선순위 순서(🔴 S → 🟡 A → 🟢 B)로 구현합니다. 구현 우선순위의 기준과 표시 규칙은 [마일스톤1 계획](<../Design/마일스톤1 계획.md>)을 따릅니다.
- 일정보다 완성도를 우선합니다. 일정 때문에 항목을 빼거나 완성도를 낮추지 않고, 필요하면 일정을 늘립니다.
- 각 단계는 아래를 모두 만족하면 끝납니다.
  1. 에디터 빌드가 오류 없이 성공합니다.
  2. 그 단계의 확인 항목을 PIE에서 기획서와 대조해 확인합니다.
  3. 자동 테스트가 있으면 모두 통과합니다.
  4. 새로 만든 데이터 필드를 '데이터 위치표'에 추가합니다.
  5. 프로그래머가 코드를 리뷰하고 승인한 뒤 push합니다.
- 모든 항목을 구현하고 단계별 확인을 마치면 QA에 넘깁니다.

## 기술 결정

### 기본 방침

| 항목 | 결정 | 이유 |
| - | - | - |
| 진행 방식 | 타이틀 화면 → 최소한의 전투가 되는 보스전 → 결과 UI를 먼저 잇고, 그 위에 기능을 채웁니다. | 마일스톤 목표 1을 일찍 확보하고, 늘 처음부터 끝까지 실행되는 상태를 유지합니다. |
| 새 에셋 위치 | 새로 만드는 에셋은 모두 `/Game/Ag` 아래에 둡니다. | 템플릿·Fab 에셋과 구분하고, 정식 에셋으로 바꿀 때 찾기 쉽게 합니다. |
| Fab 모션 | 쓰는 시퀀스의 루트 모션 설정은 원본에서 켭니다. | 같은 모션을 두 벌 두지 않습니다. |
| 템플릿 코드·콘텐츠 | 새 코드는 Ag 접두사로 따로 만듭니다. LV_BossStage를 Lvl_Combat에서 복사한 뒤, 템플릿 코드(`Variant_*`, `AgCharacter`)를 지웁니다. 템플릿 콘텐츠는 대역 에셋(NS_Damage, LevelPrototyping 폴더, MI_ThirdPersonColWay) 말고도 필요할 수 있어 아직 남겨 둡니다. 템플릿 코드를 부모로 쓰던 템플릿 블루프린트와 레벨은 부모 클래스가 없어 쓸 수 없으므로, 패키징은 게임 맵 2개(`LV_FrontEnd`, `LV_BossStage`)만 쿡합니다. | LV_BossStage를 만들기 전에는 Lvl_Combat이 템플릿 에셋을 쓰므로 지울 수 없고, 그 뒤에는 비슷한 이름의 템플릿 클래스가 혼동을 줍니다. 쿡할 맵을 정하지 않으면 프로젝트의 모든 맵을 쿡합니다. |
| 시간 처리 | 기획서의 시간 규칙이 애매하면(타이머와 모션 시간, 게임 시간과 실제 시간 등) 구현하기 쉬운 쪽으로 정하고 이 문서에 적습니다. | 기획 단계에서 정한 방침입니다. |

### 캐릭터와 GAS

| 항목 | 결정 | 이유 |
| - | - | - |
| ASC 위치 | 캐릭터에 둡니다. | 싱글플레이라 PlayerState에 둘 이유가 없습니다. |
| 어트리뷰트 | 세트 하나에 기획서 스탯을 기획서 이름 그대로 둡니다. HP, MaxHP, SP, MaxSP, MP, MaxMP, UP, MaxUP, PP, MaxPP, ATK, DEF, MOV. 보스가 쓰지 않는 SP·MP·UP는 0입니다. 기본값이 바뀌기 전에 범위(0 ~ 최대값)로 고정합니다. | 기획서, 데이터 위치표, 코드의 이름이 같아 대조하기 쉽습니다. 최대값에서 리젠이 더해져도 기본값이 넘치지 않아야 다음 감소가 바로 보입니다. |
| 행동 | 플레이어 행동(평타, 회피, 회피 반격, 가드·패리, 스킬, 궁극기, 처형, 달리기, 점프)과 보스 패턴은 어빌리티로 만듭니다. | 전투는 GAS로 구현합니다. (AGENTS.md) |
| 상태 | 피격 반응, 그로기, 처형 피격, 페이즈 전환, 사망은 이벤트로 발동하는 어빌리티로 만들고, 상태 우선순위는 태그로 나타냅니다. 높은 상태는 낮은 상태를 취소하고, 낮은 상태는 높은 상태 중에 시작하지 못합니다. | 행동과 같은 방식이라 규칙이 한곳에 모입니다. |
| 피격 처리 | 피격 처리 순서는 C++ 함수 하나에서 판정하고, HP·PP·SP 변화는 GameplayEffect로 적용합니다. | 패리처럼 공격자의 PP가 주는 분기가 있어, GameplayEffect 계산 클래스보다 함수 하나가 명확합니다. |
| 쿨다운 | 쿨다운용 GameplayEffect로 처리합니다. 쿨다운, 리젠 대기, 패리 구간은 시간과 태그를 적용할 때 정하는 GameplayEffect 하나를 같이 씁니다. 비용(SP·MP·UP)은 어빌리티의 비용 확인·적용 단계에서 자원 GameplayEffect로 처리합니다. | GAS 기본 방식입니다. 값이 데이터 에셋에 있어 GameplayEffect 에셋에 따로 둘 데이터가 없습니다. |
| 모션 캔슬 | 행동 어빌리티는 후딜 전까지 '행동 중' 태그를, 모션이 끝날 때까지 '행동 모션' 태그를 갖습니다. 후딜 시작은 '애니메이션과 이동'의 '모션을 따르는 구간'과 '기획서에 초로 적힌 구간'을 따릅니다. 새 행동은 '행동 중' 태그가 없을 때만 시작하고, 시작하면 진행 중인 행동을 취소합니다. 회피 후딜에 회피를 누르면 회피를 처음부터 다시 시작합니다. 이동 입력은 '행동 모션' 태그가 있는 동안 무시합니다. 선입력은 두지 않습니다. 플레이어 행동은 블렌드 아웃이 시작될 때가 아니라 모션이 끝날 때 끝납니다. | 상태별 허용 입력 표를 그대로 옮길 수 있습니다. 이동만 후딜에도 막히므로 태그를 따로 둡니다. 블렌드 아웃은 모션 끝보다 먼저 시작해, 그때 끝내면 후딜이 짧아집니다. |
| 리젠 | SP·PP 리젠은 GameplayEffect로 처리합니다. 리젠 대기는 태그를 주는 지속 GameplayEffect로, 자원이 줄 때마다 다시 적용해 처음부터 다시 셉니다. SP가 0이 될 때는 더 긴 대기용 GameplayEffect를 적용합니다. 회복은 주기 GameplayEffect로 하고, 대기 태그가 있는 동안에는 멈춥니다. SP는 평소용과 가드 중용 주기 GameplayEffect를 가드 태그 조건으로 바꿔 씁니다. 회복량과 대기 시간은 데이터 에셋에서 읽어 적용합니다. | 자원 변화를 모두 GameplayEffect로 처리하는 GAS 표준 방식입니다. GameplayEffect 타이머는 게임 시간으로 흘러, 히트스톱 중에도 리젠이 계속되는 기획서 규칙과 맞습니다. |

### 데이터

기획서의 데이터(수치, 설정, 쓰는 에셋)는 주인이 분명한 곳에 둡니다. 각 데이터의 위치는 아래 '데이터 위치표'에 정리합니다.

| 항목 | 결정 | 이유 |
| - | - | - |
| 형식 | DataAsset | '공격 → 타' 구조와 몽타주 같은 에셋 참조를 그대로 담고, MCP로 필드를 바로 고칠 수 있습니다. |
| 묶는 단위 | `DA_Player`, `DA_Boss`, `DA_CombatRules`(모든 캐릭터에 공통인 규칙), `DA_Camera`. 셰이크 단계별 값은 카메라 셰이크 에셋 3개에, 이펙트는 GameplayCue 에셋에, 화면의 크기·배치·표시 시간은 위젯에, 글자 크기 단계는 CommonUI 글자 스타일에 둡니다. | 한 캐릭터의 데이터를 한 에셋에서 모두 볼 수 있습니다. |
| 에셋 안 구성 | 숫자 필드와 에셋 참조(몽타주 등)는 구역을 나눕니다. | 수치를 고칠 때 에셋 참조를 건드리지 않게 합니다. |
| 에셋을 찾는 방법 | 공통 에셋은 C++ 개발자 설정 클래스에서 가리키고, 캐릭터 에셋은 캐릭터 블루프린트에서 가리킵니다. 캐릭터 블루프린트에는 데이터만 넣고 이벤트 그래프는 쓰지 않습니다. | 코드에 에셋 경로를 쓰지 않습니다. |
| 어빌리티의 데이터 | 어빌리티는 C++ 클래스만 두고, 몽타주와 수치는 캐릭터 데이터 에셋의 해당 항목(예: 평타 1타)에서 읽습니다. | 데이터가 캐릭터 에셋 하나에 모입니다. |

### 애니메이션과 이동

| 항목 | 결정 | 이유 |
| - | - | - |
| ABP | `ABP_Ag` 하나를 플레이어와 보스가 같이 씁니다. 값은 C++ `UAgAnimInstance`에서 계산하고, 애님 그래프에는 이동 블렌드 스페이스 → 가드 블렌드 스페이스 전환 → 공중 여부 전환 → 몽타주 슬롯 → 덧입힘 슬롯만 둡니다. 루트 모션은 몽타주에서만 씁니다. | AI가 BP 그래프를 다루기 어려우므로 그래프를 최소로 둡니다. |
| 블렌드 스페이스 | 플레이어 이동(템플릿 `BS_Idle_Walk_Run`: MM_Idle, Walk·Jog 8방향), 플레이어 가드(Guard, Guard_Walk 8방향. 가드 중에는 이동하지 않으므로 정지 샘플인 Guard만 보입니다), 보스 이동(Idle1, Walk 8방향) 3개를 캐릭터 데이터에 넣어 바꿔 끼웁니다. 가로축은 캐릭터 정면 기준 이동 방향, 세로축은 이동 속도이고, 샘플은 각 모션의 실제 이동 속도에 둡니다. 팩의 이동 모션은 제자리(`_IPC`) 버전을, 템플릿 이동 모션은 루트 모션을 켠 원본(재생할 때 제자리)을 씁니다. | 세 블렌드 스페이스의 축이 같아 ABP 하나로 처리됩니다. 템플릿 블렌드 스페이스는 샘플이 모션의 실제 속도(걷기 3m/s, 뛰기 6m/s)에 있어 그대로 씁니다. |
| 메시 갱신 | 캐릭터 메시는 화면에 보이지 않을 때도 포즈와 본을 갱신합니다. | 공격 판정이 메시의 피직스 바디를 쓰고 무기가 손을 따라가므로, 보이지 않을 때도 위치가 맞아야 합니다. |
| 덧입힘 모션 | 움찔은 플레이어와 보스 모두 사무라이 `Hit14`를, 가드 움찔은 `Guard_Hit1`을 덧입힘 모션으로 만들어 씁니다. 덧입힘 모션은 루트 모션을 끕니다. | 루트 모션이 있는 몽타주는 재생하는 동안 이동 입력과 다른 몽타주의 루트 모션을 대신합니다. |
| 점프 | 점프 시작과 착지는 몽타주로 재생하고, 공중에서는 Airborne을 반복 재생합니다. 이동 입력이 있으면 시작·착지 몽타주를 생략하고 Airborne만 보입니다. 착지 몽타주가 끝나기 전에 이동하면 착지 몽타주를 멈춥니다. 점프 높이와 공중 제어는 캐릭터 무브먼트의 엔진 기본값이 기획서 값과 같아 그대로 씁니다. | 시작과 착지를 C++에서 몽타주로 재생하므로 애님 그래프에는 공중 여부 전환 하나만 늘어납니다. 두 모션은 제자리 모션이라 움직이면서 재생하면 미끄러져 보이고, 루트 모션이 켜져 있어 재생하는 동안에는 이동 입력이 먹히지 않습니다. |
| 달리기 | 회피 모션이 끊기지 않고 끝날 때 Shift와 이동 입력이 남아 있고 가드 키를 누르지 않았으면 달리기 어빌리티를 시작합니다. '달리는 중' 태그가 속도와 방향(락온 중에도 이동 방향)을 바꾸고, SP 소모는 이 태그가 있을 때만 도는 주기 GameplayEffect가 맡습니다. Shift를 떼거나 이동 입력이 없거나 SP가 0이 되면 플레이어 캐릭터가 달리기를 취소합니다. 다른 행동은 달리기를 취소하지만 점프는 취소하지 않습니다. | 리젠과 같은 방식(태그 조건의 주기 GameplayEffect)이라 자원 변화가 모두 GameplayEffect로 모입니다. |
| 몽타주 | 행동마다 하나를 둡니다. 이어지는 모션은 조사 문서의 연결 시점에서 잘라 한 몽타주에 붙입니다. 평타는 타마다 따로 둡니다. 자세가 어긋나는 연결(궁극기 B 연결)과 대기 자세에서 바로 시작하지 않는 모션(A2, A6, 회피 반격)은 블렌드로 잇습니다. 다운은 쓰러짐과 기상을 두 몽타주로 나눠 블렌드로 잇습니다. 블렌드로 잇는 몽타주는 끝까지 재생한 뒤 다음 몽타주로 넘어가도록 블렌드 아웃을 모션 끝에서 시작합니다. 가드 시작 모션(Guard_Start)은 따로 재생하지 않고 ABP의 가드 전환 블렌드로 대신합니다. | 평타는 타마다 별도 행동입니다. 다운의 두 모션은 누운 자세가 조금 어긋납니다. 가드 시작 모션은 아주 짧아(0.12초) 자세가 갑자기 바뀌어 보이므로, 그보다 긴 블렌드로 부드럽게 바꿉니다. |
| 모션을 따르는 구간 | 판정 구간(몇 번째 타인지 포함), 처형 마지막 일격, 다운 무적 시작, A3 돌진 시작·자세 유지, A6 검기 발사는 몽타주 노티파이로 표시합니다. 판정 구간 외의 시점은 게임플레이 이벤트를 보내는 노티파이 하나로 표시하고, 이벤트 태그로 구분합니다. 연속 공격의 후딜 시작은 마지막 판정 구간의 끝으로 정합니다. | 시점마다 노티파이 클래스를 만들지 않고, 어빌리티가 이벤트를 기다립니다. |

| 카메라 충돌 | 스프링 암의 충돌 검사를 씁니다. 플레이어, 보스, 투사체, 보이지 않는 벽은 카메라 채널을 무시합니다. | |
| 락온 | 플레이어의 락온 컴포넌트가 대상 선택, 해제 조건, 락온 카메라의 회전을 맡습니다. 락온 지점이 되는 보스의 본 이름은 `DA_Boss`에 둡니다. 카메라 회전은 위아래·좌우 각도마다 임계 감쇠 스프링(`FMath::CriticallyDampedSmoothing`)으로 목표를 따라가고, 회전 속도를 최대 속도로 자릅니다. 락온할 때마다 회전 속도 0에서 시작합니다. | 일정한 속도로 돌면 출발과 멈춤이 갑작스러워 기계적으로 보입니다. 스프링은 출발과 멈춤이 부드럽고, 움직이는 대상을 따라잡는 시간이 스프링의 시간 값과 같습니다. |

| HUD | `WBP_HUD`의 배치는 디자이너에서, 동작은 C++ 부모 클래스(BindWidget)에서 처리합니다. 바는 텍스처 없는 단색으로 그립니다. 스킬·궁극기 아이콘은 이미지 위젯의 브러시에 넣은 텍스처나 머티리얼로 표시하고, 브러시가 비어 있으면 숨깁니다. HP 감소 잔상은 HP 바 뒤의 잔상 바이고, 대기·줄어드는 시간은 위젯에 둡니다. 잔상은 게임 시간으로 흘러 슬로우모션에 맞춰 느려집니다. 사망 연출에는 상태 요소(플레이어 상태, 슬롯, 보스 상태)를 담은 패널을 숨깁니다. | 모양은 에셋이 정하고 코드는 값만 맡습니다. 엔진 기본 진행 바 텍스처는 끝이 흐려, 가득 찬 바도 끝이 비어 보입니다. 빈 브러시는 단색 사각형으로 그려집니다. 위젯 애니메이션(대미지 숫자)은 에디터 도구(MCP)로 만들 수 없어 에셋 스크립트 도우미로 만듭니다. |
| 슬롯 흐림 | 스킬·궁극기 어빌리티의 비용 확인과 쿨다운 확인을 그대로 불러 정합니다. | 사용 조건을 어빌리티 한 곳에만 둡니다. |
| 그로기 중 PP 바 | 보스가 그로기 시간을 세기 시작한 시각(공중에서 그로기가 되면 착지한 때)을 기록하고, HUD는 지난 시간을 그로기 지속 시간으로 나눈 만큼 채웁니다. | 그로기 시간과 같은 기준으로 채웁니다. |
| 월드 위치 HUD | 락온 마커, 처형 안내, 대미지 숫자는 화면 공간 위젯 컴포넌트로 표시합니다. 락온 마커와 처형 안내는 보스의 락온 지점과 머리 본에 붙이고, 보스가 매 프레임 표시 여부를 정합니다. 대미지 숫자는 맞은 위치에 생성한 액터가 떠오르고, 투명해지는 것은 위젯 애니메이션이 맡습니다. 표시 시간(애니메이션 길이)과 떠오르는 높이는 위젯에 둡니다. 상황별 표시 규칙은 HUD와 이 위젯들이 각각 따릅니다. | 대미지 숫자는 HUD가 숨은 뒤에도 끝까지 재생해야 해 HUD와 따로 둡니다. |
| UP 게이지 | 텍스처 없는 기능용 UI 머티리얼로 슬롯 테두리를 채웁니다. 채우는 모양은 머티리얼이 정하고, 코드는 UP 비율만 머티리얼 파라미터로 넘깁니다. 채우는 수식은 머티리얼의 Custom 노드(HLSL) 하나에 넣어 그래프를 작게 둡니다. | 코드가 아트를 직접 그리지 않고 모양은 에셋이 맡습니다. 수식이 텍스트라 AI도 고칠 수 있습니다. |
| 화면 UI | 타이틀과 결과 UI는 CommonUI 화면으로 만듭니다. 화면마다 입력 모드(화면 UI는 UI 전용 입력과 커서 표시, HUD는 게임 입력과 커서 숨김)와 첫 선택 버튼을 정합니다. 버튼은 포커스를 받으면 선택되고, 마우스를 올리면 포커스를 가져옵니다. W·S 이동은 Slate 내비게이션 설정에 키를 더해 처리합니다. 실행 키(좌클릭, Enter, Space)는 Slate 버튼의 기본 처리로 동작하므로 CommonUI 입력 데이터(확인·뒤로 액션)는 만들지 않고, CommonUI 설정 `CommonButtonAcceptKeyHandling`을 `TriggerClick`으로 둡니다. | CommonUI 입력 데이터는 입력 아이콘 표시와 뒤로 가기 처리에만 쓰이는데, 기획서에는 둘 다 없습니다. 이 설정의 기본값(`Ignore`)은 Enter와 Space를 버튼에 넘기지 않습니다. |
| 게임 모드 | 레벨마다 하나씩, 타이틀용과 보스전용을 `AAgGameMode`를 상속해 둡니다. | |
| 결과 처리 | 보스전 게임 모드가 먼저 처리된 사망으로 결과를 정하고, 사망 연출 시간이 지나면 결과 UI를 띄웁니다. Try Again은 레벨을 다시 로드합니다. | |

### 개발 도구와 검증

| 항목 | 결정 | 이유 |
| - | - | - |
| 테스트용 콘솔 명령 | 개발 빌드에만 둡니다. 보스·플레이어 HP를 0으로, 무적, 즉시 그로기, UP 채우기처럼 특정 상황을 바로 만드는 명령입니다. | 단계별 확인과 QA에서 처형, 페이즈 전환, 결과 UI를 빠르게 확인합니다. 플레이어에게 보이는 기능이 아닌 개발 도구입니다. |
| 자동 테스트 | 대미지·PP 계산식, 패턴 선택 확률처럼 입력과 결과가 분명한 계산 로직만 언리얼 자동화 테스트로 확인합니다. 동작과 느낌은 PIE에서 확인합니다. | AI가 코드를 고칠 때 계산이 깨지는 것을 바로 잡습니다. |
| PIE 확인용 입력 | 플레이어 캐릭터에 에디터 전용 속성(`DevPressInput`, `DevMashInput`, `DevHoldInput`, `DevMoveInput`)을 둡니다. PIE 중 에디터 도구로 값을 넣으면 키를 누른 것과 같이 처리합니다. | AI가 키보드 없이 PIE에서 행동을 확인합니다. 에디터 빌드에만 있어 게임에는 들어가지 않습니다. |
| 에셋 스크립트 도우미 | `UAgEditorUtilities`에 에디터 화면에서만 바꿀 수 있는 설정(몽타주 구간과 구간별 재생 속도, 슬롯 그룹, 위젯 애니메이션)을 파이썬 스크립트에서 바꾸는 함수를 둡니다. 에디터 빌드에만 있습니다. | 몽타주처럼 반복되는 에셋 작업을 스크립트로 처리합니다. ('위험 요소'의 에디터 작업량) |
| 데이터 위치표 | 데이터 에셋의 필드를 코드로 만들 때마다 행을 추가하고, 코드 리뷰 때 표와 대조합니다. | 실제 필드 이름과 항상 맞습니다. |

| - | - | - |
| 3 | 평타 1타가 정지 간격에서 맞는지 | 대기 중인 보스에게는 맞습니다. 멀리서 다가가 정지 간격에서 멈춘 경우와 정지 간격 안쪽에서 바로 친 경우 모두 맞았습니다. 보스가 A1을 하는 중에는 보스 자세에 따라 빗나가기도 했습니다(평타를 14초 동안 연타했을 때 1타 6번 중 2번). |
