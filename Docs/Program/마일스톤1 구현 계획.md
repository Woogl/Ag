# 마일스톤1 구현 계획

마일스톤1을 구현하는 범위와 완료 기준, 작업 순서, 확인 기록, 위험 요소를 적습니다. 어떻게 구현할지는 같은 폴더의 주제별 구현 계획서에 적습니다.

무엇을 만들지는 `Docs/Design`의 기획서를, 작업 방식은 [AI 워크플로우](<../AI 워크플로우.md>)를 따릅니다. 기간과 목표는 [마일스톤1 계획](<../Design/마일스톤1 계획.md>)을, 용어는 [용어집](<../용어집.md>)을 따릅니다.

## 범위와 완료 기준

- 기획서의 모든 항목을 구현합니다.
- 일정보다 완성도를 우선합니다. 일정 때문에 항목을 빼거나 완성도를 낮추지 않고, 필요하면 일정을 늘립니다.
- 각 단계는 아래를 모두 만족하면 끝납니다.
  1. 에디터 빌드가 오류 없이 성공합니다.
  2. 그 단계의 확인 항목을 기획서와 대조해 확인합니다. 확인 방법은 [개발 도구와 검증](<개발 도구와 검증.md>) '동작 테스트 실행'을 따릅니다.
  3. 새로 만든 데이터 필드를 [데이터 위치표](<데이터 위치표.md>)에 추가합니다.
  4. 코드를 push합니다.
- 모든 항목을 구현하고 단계별 확인을 마치면 기획자에게 플레이 검증용 빌드를 전달합니다.

## 작업 순서

| 단계 | 작업 | 완료 확인 |
| - | - | - |
| 0. 준비 | 빌드, 에디터·MCP 연결, `/Game` 아래 에셋 폴더, `AgGameplayTags`, 프로젝트 설정(시작 맵, 공격 판정 채널, GameplayCue 경로, CommonInput), 테스트용 콘솔 명령의 틀 | 빌드되고 에디터가 MCP로 연결됨 |
| 1. 한 바퀴 골격 | CommonUI 타이틀 화면, 게임 모드 2개, `LV_FrontEnd`, 결과 UI, 레벨 전환. `LV_BossStage`는 Lvl_Combat을 복사해 보스 스테이지 기획서대로 고치고, 다 되면 템플릿 코드를 정리합니다. | 타이틀 → 보스 스테이지 → (콘솔 명령으로 사망) → 결과 UI → 버튼 3개가 모두 동작 |
| 2. 캐릭터 기반 | 캐릭터 클래스, ASC·어트리뷰트, 캐릭터 데이터, `ABP_Ag`·블렌드 스페이스, 입력, 자유 시점·카메라 충돌, 무기 소켓, Fab 시퀀스의 루트 모션 켜기 | 플레이어가 움직이고 보스가 서 있음 |
| 3. 전투 핵심 | 공격 판정, 피격 처리, 대미지 계산식, 히트스톱, 평타와 공격 중 위치·회전 보정, 피격 반응, 사망, 보스 AI의 골격과 DoubleStrike, 최소한의 HP 바 | 평타로 보스를 쓰러뜨리거나 DoubleStrike에 쓰러져 결과 UI까지 이어짐. 평타 1타가 대상과의 최소 간격에서 맞는지 확인해 기록 |
| 4. 플레이어 행동 | 회피·극한 회피, 가드·패리·가드 브레이크, 입력과 모션 캔슬, 자원(SP·MP·UP)과 리젠(SP·PP), 스킬, 궁극기, 그로기, 처형과 처형 피격, 락온과 락온 카메라 | 작업 항목 전부. 스킬의 타가 대상과의 최소 간격에서 맞는지 확인해 기록 |
| 5. 보스 | 패턴 선택 흐름, Sweep·DashThrust·LeapSlam, 가드 불가 예고, 페이즈 전환 | 작업 항목 전부 |
| 6. HUD | 나머지 HUD 요소, 상황별 표시 규칙 | 작업 항목 전부 |
| 7. 나머지 기능 | 달리기, 점프, 회피 반격, 슬로우모션, 카메라 셰이크, 피격·패리 VFX, QuintupleStrike·SwordWave·Backstep, 패턴 후딜레이의 좌우 걷기, 비전투, HP·MP 수치, 감소 잔상 | 구현한 항목마다 기획서와 대조 |
| 8. 마무리 | 데이터 위치표 점검, 기획서 대조 검증 | 기획자에게 전달할 플레이 검증용 빌드 |

- 모든 단계는 '범위와 완료 기준'의 단계 완료 조건을 만족하면 끝납니다.

## 확인 기록

단계 완료 확인에서 기록하기로 한 결과입니다. 수치를 고칠지는 기획자가 플레이 결과를 보고 판단합니다.

| 단계 | 확인 항목 | 결과 |
| - | - | - |
| 3 | 평타 1타가 대상과의 최소 간격에서 맞는지 | 대기 중인 보스에게는 1 ~ 5타가 모두 맞습니다. 멀리서 다가가 대상과의 최소 간격에서 멈춘 경우와 대상과의 최소 간격 안쪽에서 바로 친 경우 모두 맞았습니다. 보스가 패턴(Backstep, DoubleStrike)을 쓰는 중에는 보스 자세와 움직임에 따라 빗나가기도 했습니다(평타를 14초 동안 연타했을 때 1타와 5타는 모두 맞고, 2 ~ 4타는 19번 중 5번 빗나감). |
| 4 | 스킬의 타가 대상과의 최소 간격에서 맞는지 | 대기 중인 보스에게 스킬이 대상과의 최소 간격에서 맞았습니다. |
| 4 | 처형 두 모션의 정렬 | Warrior 처형으로 바꾼 뒤(Samurai 애니메이션 조사 'Warrior 팩의 처형') 재생 속도 1배에서 잰 결과, 두 몽타주의 재생 위치가 매 프레임 같았습니다. 보스 정면 2.5m, 측면 60° 2.9m, 정면 0.75m 거리에서 평타 직후 시작해도 찌르기 순간 두 캡슐 중심 사이가 92 ~ 95cm이고 서로 마주 봅니다. 칼은 찌르기부터 발차기까지 보스 몸통을 꿰뚫고 있고(척추선에서 보스 오른쪽으로 6 ~ 15cm), 발차기는 0.81초에 몸에 닿으며, 대미지는 찌르기와 마지막 일격에 1 : 3으로 들어갑니다. 처형으로 사망하면 찌르기든 마지막 일격이든 처형 사망 몽타주가 같은 재생 위치에서 이어집니다. |

## 위험 요소

| 위험 | 영향 | 대응 |
| - | - | - |
| 에디터 작업량 | 몽타주·노티파이 40여 개, 블렌드 스페이스, 위젯을 에디터에서 만들어야 하고, MCP 연결이 끊기면 작업이 멈춥니다. | 반복 작업은 파이썬 스크립트로 한꺼번에 처리하고, 단계 0에서 MCP 연결부터 확인합니다. |
| 처형 두 모션의 정렬 | 두 모션이 맞물리는 시간 차이와 간격이 조사되지 않아, 칼이 빗나가거나 보스가 맞기 전에 반응해 보일 수 있습니다. | 두 모션의 시간 차이와 원래 배치를 모션 데이터에서 재어 몽타주와 데이터에 두었습니다. ('확인 기록') |
| 공격 중 위치·회전 보정의 순간이동감 | 선딜이 짧은 공격(회피 반격)은 Motion Warping으로 거의 순간이동처럼 다가갑니다. | 기획서의 '순식간에 다가가' 의도와 맞는지 기획자가 직접 플레이하며 판단합니다. |
| 공격 중 회전 속도 | 공통 회전 속도 제한을 쓰는 공격은 짧은 추적 구간에 큰 각도를 다 돌지 못할 수 있습니다. 회피 반격의 예외와 구현은 [애니메이션과 이동](<애니메이션과 이동.md>) '플레이어 공격 워핑 저작'을 따릅니다. | 기획자가 직접 플레이하며 헛치기가 잦은지 봅니다. |
| 메시 바디 판정 | 메시 바디는 캡슐보다 가늘어서, 대상과의 최소 간격에서 평타 1타와 스킬이 닿지 않을 수 있습니다. | 단계 3·4에서 맞는지 확인해 '확인 기록'에 적고, 기획자가 조정이 필요하다고 판단하면 데이터 작업으로 대상과의 최소 간격을 고칩니다. |
| CommonUI 입력 설정 | 마우스·키보드 전환과 포커스가 기획서대로 동작하지 않을 수 있습니다. | 단계 1에서 타이틀 화면으로 먼저 확인합니다. |
