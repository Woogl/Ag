# 입력 처리

행동의 실행 구조는 [어빌리티와 AbilityTask](<어빌리티와 AbilityTask.md>)를 따릅니다.

플레이어 입력(키 배치, 상태별 허용 입력, 선입력, 모션 캔슬)을 어떻게 구현할지 정합니다.

## 기술 결정

| 항목 | 결정 | 이유 |
| - | - | - |
| 입력 | Enhanced Input 입력 에셋 10개(이동, 시야, 평타, 가드, 회피·달리기, 점프, 스킬, 궁극기, 처형, 락온)를 둡니다. 행동 키는 입력 바인딩이 입력 태그를 함께 넘겨 함수 하나가 처리합니다. 키에 맞는 행동은 행동 태그로 찾습니다(아래 '입력 계층의 행동 찾기'). 평타 키 처리 순서(공중이면 점프 공격, 회피 반격 기회가 있으면 회피 반격, 평타가 실행 중이면 `Input.Attack` 이벤트, 그 밖에는 평타), 트리거 태그(`Input.Guard`, `Input.Sprint`, `Input.LockOn`)와 이동 입력 태그(`Input.Move`), 자동 가드, 이동 입력 제한은 플레이어 캐릭터의 C++ 입력 처리에서 합니다. | 키와 행동 태그의 대응이 입력 규칙이라 C++ 한 곳에 있고, 그 태그를 가진 행동은 데이터가 정합니다. |
| 자동 가드 | 가드 키를 누른 채 후딜이 시작되거나(`State.Busy`가 풀림) 행동·피격 반응이 끝나면 다음 프레임에 가드로 돌아옵니다. 가드가 실행 중이면(패리 모션은 가드를 끝내지 않음) 후딜에 든 패리 모션(`Ability.Action.Parry`)을 취소하고, 아니면 가드의 트리거 태그를 붙입니다. 가드 밀림은 가드를 끝내지 않으므로 가드가 그대로 이어집니다. 가드를 새로 시작할 때마다 패리 구간이 열립니다(플레이어 사양 '패리 구간'). 패리 모션의 후딜 전에 가드 키를 떼었다가 다시 누르면, 그 입력은 선입력으로 기억했다가 후딜이 시작될 때 가드를 새로 시작합니다(패리 구간이 열림). 후딜 전에는 가드 입력이 허용되지 않기 때문입니다(플레이어 입력 '상태별 허용 입력'). | 가드 밀림 뒤에는 가드가 끝나지 않아 패리 구간이 다시 열리지 않고, 가드 어빌리티에 시작 방법을 전하는 이벤트가 필요 없습니다. |
| 모션 캔슬 | 행동은 후딜 전까지 `State.Busy`(시간표의 ApplyEffect 구간)를 갖고, 모션이 있는 플레이어 행동은 행동 내내 `State.Acting`(OwnedTags)을 갖습니다. 새 행동은 Busy가 없을 때 발동해 진행 중인 행동을 취소합니다. 회피 후딜의 재입력은 회피를 다시 시작합니다. 이동 입력은 `State.Acting`, 패리 구간(`State.ParryWindow`), 피격 반응, 그로기, 처형, 사망 태그가 있으면 적용하지 않습니다. 이동 입력 방향과 `Input.Move`는 이동을 막는 동안에도 갱신합니다(회피의 Roll 선택). | Busy와 행동의 수명이 다르므로 태그 두 개로 나눕니다. 이동 제한이 행동 정의에 드러나고, 일반 점프·가드 유지·달리기에는 `State.Acting`이 없어 새 제한이 걸리지 않습니다. |
| 선입력 | 처형 입력은 선입력 저장 대상에서 제외하고 즉시 실행만 시도합니다. 처형 키를 누르면 기존에 기억한 입력도 지웁니다. 플레이어 캐릭터가 나머지 입력을 받을 때 '행동 중'이나 피격 반응 태그가 있으면, 그 입력 하나와 누른 시각(월드 시간)을 기억합니다. 점프 중의 평타 키는 점프 공격으로 허용되므로 기억하지 않습니다([애니메이션과 이동](<애니메이션과 이동.md>) '점프 공격'). 입력은 그때도 그대로 처리하므로 허용되지 않은 행동은 시작하지 않고, 실행 중인 평타는 다음 타 입력(`Input.Attack`)을 그대로 받습니다. 두 태그가 풀리면 다음 프레임에 기억한 입력을 다시 처리하고, 기억하는 시간이 지났거나 가드 키를 뗐으면 버립니다. 자동 가드를 시작할 때도 기억한 입력을 먼저 처리합니다. | 입력이 한 함수로 모이고 허용되는 순간이 태그 두 개로 드러나, 행동 정의를 고치지 않아도 됩니다. 다음 프레임에 처리해야 같은 프레임에 이어지는 상태(평타의 후딜 표시, 행동을 끊은 피격 반응)가 반영됩니다. 월드 시간은 히트스톱 중에도 흐릅니다. |

## 트리거 태그

OwnedTagPresent 트리거([어빌리티와 AbilityTask](<어빌리티와 AbilityTask.md>) '트리거')는 태그가 붙는 순간에만 발동을 시도하고, 막혀서 실패하면 태그가 붙어 있는 동안 다시 시도하지 않습니다. 그래서 입력 계층은 자기가 붙이는 요청 태그(`Input.Guard`, `Input.Sprint`, `Input.LockOn`)에 다음을 지킵니다. 세 규칙은 요청 태그를 관리하는 함수 하나(`SetTriggerTag`)로 구현하고 가드·달리기·락온이 함께 씁니다.

1. 행동을 시작할 수 있을 때만(그 스펙의 CanActivateAbility) 태그를 붙입니다. 막혀 있으면 붙이지 않고 기다립니다.
2. 붙였는데 행동이 실행되지 않았으면 바로 뗍니다.
3. 태그가 남아 있는데 행동이 다른 이유(CancelTags 등)로 끝나면 태그를 뗍니다. 다시 시작할 때 다시 붙입니다.

| 행동 | 트리거 태그 | 주인과 규칙 |
| - | - | - |
| 가드 | `Input.Guard` | 입력 계층. 가드 키를 누르고 있고 가드를 시작할 수 있을 때 붙이고, 키를 떼면 뗍니다. 막혀 있으면 선입력, 후딜 시작, 행동 종료에서 다시 붙입니다. |
| 달리기 | `Input.Sprint` | 입력 계층. 회피 후딜에 Shift와 이동 입력이 있고 가드 키를 누르지 않았고 SP가 0보다 크면 붙이고, Shift를 떼거나 SP가 0이면 뗍니다. 이동 입력이 없어도 유지합니다. |
| 락온 | `Input.LockOn` | 입력 계층. 락온 키로 붙이고 뗍니다(토글). 락온 대상이 없으면 시작할 수 없어 붙이지 않고(규칙 1), 대상을 잃어 행동이 끝나면 뗍니다(규칙 3, [대상 찾기와 락온](<대상 찾기와 락온.md>) '락온'). |
| 점프 | `State.Jumping` | 캐릭터. 점프가 실제로 시작될 때(`OnJumped`) 붙이고 착지할 때(`Landed`) 뗍니다. 요청이 아니라 공중 상태라 위 규칙 대신, 입력 계층이 점프 행동을 시작할 수 있을 때만 엔진 `Jump`를 불러 막힌 발동을 피하고, 키를 떼면 `StopJumping`을 부릅니다. 행동이 다른 이유로 끝나도 떼지 않습니다(점프 공격의 시작 조건). |

## 입력 계층의 행동 찾기

입력 계층은 행동 ID 대신 행동 태그로 스펙을 찾습니다. 키와 행동 태그의 대응은 입력 규칙이라 입력 계층(C++의 `AAgPlayerCharacter::GetInputAbilityTags`)에 두고, 그 태그를 가진 정의가 무엇인지는 캐릭터의 행동 목록이 정합니다. 그래서 같은 키를 쓰는 새 캐릭터의 행동은 다른 ID로 정의하고 Tags만 맞추면 데이터만으로 붙습니다.

| 키·처리 | 찾는 행동 태그 |
| - | - |
| 평타 키 | 공중이면 `Ability.Action.JumpAttack`, 회피 반격 기회가 있으면 `Ability.Action.DodgeCounter`, 그 밖에는 `Ability.Action.BasicAttack`(실행 중이면 `Input.Attack` 이벤트) |
| 가드 키 | `Ability.Action.Guard`(트리거 태그를 붙여도 되는지 확인) |
| 회피·달리기 키 | `Ability.Action.Dodge`, 회피 후딜의 달리기는 `Ability.Sprint` |
| 점프 키 | `Ability.Action.Jump`(엔진 Jump를 불러도 되는지 확인) |
| 스킬, 궁극기, 처형 키 | `Ability.Action.Skill`, `Ability.Action.Ultimate`, `Ability.Action.Execution` |
| 락온 키 | `Ability.LockOn` |
| 패리 후딜 복귀(취소) | `Ability.Action.Parry` |
| 처형 안내 HUD(Targeting 평가) | `Ability.Action.Execution` |

- 스펙 태그(`GetDynamicSpecSourceTags`)가 그 태그와 정확히 같은 스펙을 `UAgAbilitySystemComponent::FindSpecByTag`로 찾습니다. 엔진 `TryActivateAbilitiesByTag`는 클래스 태그를 보므로 쓰지 않습니다. HUD도 같은 함수를 씁니다.
- 한 캐릭터에서 위 태그를 정확히 가진 행동은 태그마다 하나 이하입니다. 없으면 그 키는 아무것도 하지 않습니다.
- 새 키를 더할 때(입력 태그, Enhanced Input 에셋)만 이 표와 C++가 바뀝니다.
- 보스 AI는 캐릭터의 행동 목록과 StateTree 에셋에 적힌 ID를 씁니다. ID가 데이터에서 오므로 코드에는 행동 ID가 없습니다. 락온 행동과 락온 대상은 플레이어와 같이 `Ability.LockOn`으로 찾습니다.

## 클래스 구조

### 입력에서 행동까지

이동은 캐릭터 무브먼트로 갑니다. 락온 키는 선입력과 행동 제한을 거치지 않고 바로 락온의 트리거 태그를 붙이거나 뗍니다. 나머지 행동 키는 아래처럼 행동으로 갑니다.

```mermaid
sequenceDiagram
    participant In as Enhanced Input
    participant P as AAgPlayerCharacter
    participant ASC as 플레이어 ASC
    participant GA as 행동 어빌리티
    In->>P: 행동 키
    P->>P: HandleInputPressed<br>처형 외의 입력이 막혀 있으면 선입력으로 기억
    P->>P: RunInput
    alt 평타 키이고 평타가 실행 중
        P->>ASC: Input.Attack 게임플레이 이벤트
        ASC->>GA: 평타의 Transition이 다음 타로 전환
    else 가드 키
        P->>ASC: 시작할 수 있으면 Input.Guard를 붙임
        ASC->>GA: 트리거 태그로 가드 시작
    else 그 밖
        P->>ASC: 행동 태그로 찾은 스펙에 TryActivateAbility
        ASC->>GA: 막는 태그가 없으면 시작
    end
    Note over P: 행동이 다시 허용되면<br>기억한 입력을 RunInput으로 다시 처리
```
