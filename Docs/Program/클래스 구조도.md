# 클래스 구조도

게임 코드(`Source/Ag`)의 클래스가 서로 어떻게 이어지는지 그림으로 보여 줍니다. 클래스마다의 역할은 [마일스톤1 구현 계획](<마일스톤1 구현 계획.md>)의 '클래스 구조'를, 그렇게 만든 이유는 같은 문서의 '기술 결정'을 따릅니다.

클래스를 더하거나 빼거나 클래스 사이의 관계를 바꾸면 이 문서도 함께 고칩니다.

## 그림 읽는 법

- 클래스 그림의 선은 아래 뜻입니다. 선 위의 글은 필드 이름이나 함수 이름입니다.
  - 속이 빈 삼각형: 상속. 삼각형 쪽이 부모입니다. 점선이면 인터페이스 구현입니다.
  - 검은 마름모: 소유. 마름모 쪽이 컴포넌트나 구조체를 가지고 있습니다.
  - 실선 화살표: 참조. 화살표 쪽 클래스나 에셋을 필드로 가리킵니다.
  - 점선 화살표: 사용. 필드 없이 함수를 부르거나, 게임플레이 이벤트를 보내거나, 액터를 생성합니다.
- 클래스 상자 안의 줄은 엔진 클래스를 가리키는 주요 필드(타입, 이름)입니다.
- 클래스 이름 위 « » 안의 글은 그 클래스로 만든 에셋이나, 그 클래스가 맡는 기획서 항목입니다. «interface», «struct», «enum», «namespace»는 C++ 종류입니다.
- `BP_`, `WBP_`, `ABP_`, `GC_`로 시작하는 이름은 블루프린트이고, `DA_`로 시작하는 이름은 데이터 에셋입니다. `.json`으로 끝나는 이름은 프로젝트 `Data` 폴더의 데이터 파일입니다.
- 이름에 `Ag`가 없는 클래스는 엔진과 플러그인 클래스입니다.
- 게임플레이 태그(`AgGameplayTags`)는 거의 모든 클래스가 쓰므로 그리지 않습니다. 에디터에서만 쓰는 코드와 자동 테스트는 게임에 들어가지 않아 그리지 않습니다.

## 어빌리티

모든 어빌리티는 `UGameplayAbility`를 상속한 `UAgGameplayAbility`를 바로 상속하고, 여러 어빌리티가 함께 쓰는 동작은 어빌리티 태스크로 씁니다([마일스톤1 구현 계획](<마일스톤1 구현 계획.md>) '어빌리티 구조'). 플레이어 행동, 상태, 보스 패턴으로 나눠 그립니다.

### GameplayEffect

GameplayEffect는 모두 C++ 클래스입니다. 대미지 GameplayEffect는 공격하는 쪽(무기 스윕, 검기, A4 착지, 처형)이 적용하고, 피격 처리는 그 안에서 끝납니다. 계산 클래스가 피격 결과를 정해 스펙 태그로 남기고, 어트리뷰트 세트가 사망·그로기를 판정하며, 결과 처리 컴포넌트가 반응과 적중 후 처리를 합니다. 행동 비용은 어빌리티의 비용 GameplayEffect로 엔진이 치르고, 자원 얻기, PP 회복, 패리로 잃는 PP는 그 일을 하는 어빌리티나 결과 처리 컴포넌트가 적용합니다. 시간 태그 GameplayEffect는 그 클래스의 함수(`Apply`)로 적용하고, 리젠 GameplayEffect는 캐릭터가 시작할 때 캐릭터 데이터의 목록(`RegenEffects`)대로 겁니다. 리젠의 회복량은 크기 계산 클래스가 주기마다 캐릭터 데이터에서 읽습니다.

## 주요 흐름

클래스 그림만으로는 보이지 않는 실행 순서입니다.

### 입력에서 행동까지

이동은 캐릭터 무브먼트로 갑니다. 락온 키는 선입력과 행동 제한을 거치지 않고 바로 `RunInput`으로 가서 락온 어빌리티를 시작하거나 끝냅니다. 나머지 행동 키는 아래처럼 어빌리티로 갑니다.

```mermaid
sequenceDiagram
    participant In as Enhanced Input
    participant P as AAgPlayerCharacter
    participant ASC as 플레이어 ASC
    participant GA as 행동 어빌리티
    In->>P: 행동 키
    P->>P: HandleInputPressed<br>막혀 있으면 선입력으로 기억
    P->>P: RunInput
    alt 이 키를 받는 어빌리티가 실행 중
        P->>ASC: 입력 태그의 게임플레이 이벤트
        ASC->>GA: 이벤트 전달<br>(평타 다음 타, 패리 모션 중 가드)
    else 그 밖
        P->>ASC: TryActivateAbilitiesByTag
        ASC->>GA: 막는 태그가 없으면 시작
    end
    Note over P: 행동이 다시 허용되면<br>기억한 입력을 RunInput으로 다시 처리
```

### 공격 판정과 피격 처리

```mermaid
sequenceDiagram
    participant GA as 공격 어빌리티<br>(플레이어는 공격 태스크)
    participant A as 공격자
    participant N as 판정 구간 노티파이
    participant G as 대미지 GameplayEffect
    participant T as 맞은 캐릭터
    GA->>A: SetActiveAttack
    GA->>A: 몽타주 재생
    N->>A: BeginAttackWindow
    loop 판정 구간 동안 매 프레임
        A->>A: 무기 날 스윕
        opt 상대 메시에 처음 닿음
            A->>G: ApplyAttack
            G->>T: 피격 결과, HP·PP·SP 변화(계산 클래스)
            Note over T: HP·PP가 0 이하면 사망·그로기 이벤트<br>(어트리뷰트 세트)
            G->>T: 상태 어빌리티 이벤트<br>또는 PlayFlinch(결과 처리 컴포넌트)
            G->>T: GameplayCue(이펙트, 셰이크, 대미지 숫자)
            G->>A: 히트스톱 태그 GameplayEffect
            G->>T: 히트스톱 태그 GameplayEffect
        end
    end
    N->>A: EndAttackWindow
    N-->>GA: Event.AttackWindowEnded
```

A6 검기는 `AAgSwordWave`가, A4 착지는 `UAgBossPattern_Leap`이 같은 함수(`ApplyAttack`)로 대미지 GameplayEffect를 적용합니다. 처형의 타격은 `UAgAbility_Execution`이 스펙을 만들어 공격을 담고(`SetAttack`) 적용하며, 엔진이 스펙에 넣는 처형 어빌리티 태그로 처형의 셰이크와 히트스톱 없음이 정해집니다.

### 보스 패턴 실행

```mermaid
sequenceDiagram
    participant T as 패턴 실행 태스크<br>FAgBossAITask_RunPattern
    participant B as AAgBossCharacter
    participant ASC as 보스 ASC
    participant GA as 패턴 어빌리티
    T->>T: GatherCandidates, PickWeighted
    T->>B: FindPatternSpec (패턴 ID)
    T->>ASC: TryActivateAbility
    ASC->>GA: 시작
    GA->>B: FindPattern (스펙의 패턴 ID)<br>SetActiveAttack
    GA->>GA: 공격 중 이동 태스크,<br>몽타주 재생
    GA-->>ASC: 끝남
    T->>ASC: 매 프레임 스펙이 실행 중인지 확인
    Note over T: 끝났으면 성공 →<br>ST_Boss가 패턴 뒤 대기로 넘어감
```

B1은 컨트롤러가 대상(플레이어) ASC의 `Event.BasicAttackStarted` 가운데 그 타의 대상이 자기 보스인 것을 StateTree 이벤트로 넘기면 패턴 후딜레이 상태의 전환이 백스텝 상태로 보내 시작하고, 페이즈 전환은 페이즈 전환 태스크가 보스에게 `Event.PhaseTransition`을 보내 시작합니다.

### 사망에서 결과 UI까지

```mermaid
sequenceDiagram
    participant C as 죽는 캐릭터
    participant D as UAgAbility_Death
    participant GM as AAgBossStageGameMode
    participant PC as AAgPlayerController
    participant R as UAgResultScreen
    Note over C: Event.Death를 받음
    C->>D: 이벤트로 시작
    D->>C: Die
    C-->>GM: OnDied
    GM->>PC: HideHUD
    Note over GM: 사망 연출 시간 뒤
    GM->>PC: ShowResult
    PC->>R: PushScreen, SetResult
    R->>GM: 버튼에 따라<br>OpenBossStage 등
```

`Event.Death`는 GameplayEffect가 HP를 0 이하로 만들 때 어트리뷰트 세트(`PostGameplayEffectExecute`)가 보냅니다. 대미지 GameplayEffect와, `Kill`(Kill Z 낙하, 테스트용 콘솔 명령)이 적용하는 HP를 0으로 만드는 GameplayEffect가 모두 이 판정을 거칩니다. 보스와 플레이어의 사망은 StateTree의 전환 조건이 매 프레임 확인해, 보스 AI가 각각 사망 상태와 비전투 상태로 넘어갑니다.
